# 标准 Bar 复权数据适配方案

## 1. 背景与结论

当前标准 Bar 回测直接读取 `qmt_kline` 或临时聚合 Bar，回测引擎不会进行复权处理；表中也未保存复权类型、复权因子或公司行为版本。因此，用户无法明确选择用于趋势指标与标准 Bar 模拟成交的价格口径。

本方案新增 `adjustmentMode（复权方式）`：

- `none（不复权）`
- `qfq（前复权）`
- `hfq（后复权）`

复权计算放在 Bar 数据适配器层。原始数据表不改写，策略与 Bar 回测引擎只读取适配后的 Bar。L2 十档盘口回放固定使用不复权真实价格，不支持复权选择。

## 2. 目标与边界

### 2.1 目标

1. 用户可在标准 Bar 回测中选择三类价格口径。
2. `on_bar`、MA、ATR、突破与标准 Bar 开盘成交都使用同一所选 Bar 口径。
3. 每次任务保存 `adjustmentMode（复权方式）`、原始数据版本与 `factorVersion（因子版本）`，结果可追溯。
4. 同一口径与版本的 Bar 可缓存复用，缓存不得改变结果语义。

### 2.2 非目标

1. 不修改 `raw_historical_data.qmt_kline` 原始 OHLC。
2. 不为 L2 盘口、L2 成交或实时行情生成复权价格。
3. 首期不实现除权除息日的真实持仓数量、现金分红与成本重算账本；标准 Bar 的复权模式是用户选择的价格序列模拟口径，不能宣称等同于真实清算。
4. 不将历史任务未记录的复权方式猜测为任一新值。

## 3. 数据与适配架构

```text
前端 adjustmentMode
  → 回测请求与任务快照
  → RawBarProvider（正式映射表 / QMT / 临时快照聚合）
  → BarAdjustmentAdapter（none / qfq / hfq）
  → 标准 Bar 回测引擎
  → on_bar / on_order_event

L2 Provider（不复权十档盘口）
  → L2 回测引擎
```

`RawBarProvider（原始 Bar 提供器）`统一输出元价格的原始 Bar。`BarAdjustmentAdapter（复权 Bar 适配器）`按标的和交易日查询因子后返回同一时间戳、同一周期、不同价格口径的 Bar。

## 4. 复权因子数据契约

新增版本化的复权因子数据集，推荐以 ClickHouse 表维护，每个标的、每个交易日保存：

| 字段 | 含义 |
| --- | --- |
| `symbol` | 标的代码 |
| `trade_date` | 因子生效交易日 |
| `qfq_price_factor` | 前复权价格因子 |
| `hfq_price_factor` | 后复权价格因子 |
| `qfq_volume_factor` | 前复权成交量因子 |
| `hfq_volume_factor` | 后复权成交量因子 |
| `source` / `source_version` | 因子来源与上游版本 |
| `factor_version` | 本系统因子批次版本 |
| `quality_status` | 完整、缺失、异常等质量状态 |

`open（开盘价）`、`high（最高价）`、`low（最低价）`、`close（收盘价）`、`preClose（前收盘价）`按对应价格因子转换；`volume（成交量）`按对应成交量因子转换；`amount（成交额）`保留原币值口径，除非因子来源明确提供对应定义。

因子必须由可追溯上游数据生成或导入，不能通过单日价格跳空猜测。实施前需核验 QMT 数据导出参数与至少三类公司行为样本：现金分红、送转/拆并股、配股。

## 5. 请求、界面与历史兼容

### 5.1 前端和 API

标准 Bar 回测的成交模式下新增下拉框：`不复权`、`前复权`、`后复权`，默认 `none（不复权）`。

`adjustmentMode（复权方式）`写入策略方案参数、回测请求、版本快照和结果中的 `marketDataSnapshot（行情数据快照）`。后端枚举校验只允许 `none`、`qfq`、`hfq`。

L2 模式隐藏该下拉框，并显示“L2 盘口使用不复权真实价格”。若外部 API 为 L2 传入非 `none`，后端返回 422，禁止静默改写。

### 5.2 历史任务

历史任务未保存 `adjustmentMode` 时，历史页面展示“未记录（历史任务）”，不得伪造为 `none`。重新运行历史任务时，前端要求用户按当前规则选择复权方式，默认 `none`；新任务保存新的快照，不改变旧结果。

## 6. Bar 调整算法与失败规则

1. `none`：原始 Bar 原样透传。
2. `qfq`：原始 OHLC 与对应前复权价格因子相乘；成交量按前复权成交量因子处理。
3. `hfq`：原始 OHLC 与对应后复权价格因子相乘；成交量按后复权成交量因子处理。
4. 同一任务内所有 Bar 必须使用相同 `factorVersion`。读取到多个版本、缺失交易日因子、零值或非有限因子时，任务在运行前失败，并给出标的、日期和因子版本诊断。
5. 标准 Bar 的开盘成交、滑点、止损、收益计算均基于适配后 Bar；结果必须注明这是所选复权价格口径下的模拟结果。

## 7. 缓存与可追溯性

复权后的 Bar 缓存键至少包含：

```text
bar-adjusted:v1:{symbol}:{timeframe}:{tradeDate}:{adjustmentMode}:{rawDataVersion}:{factorVersion}
```

原始 Bar 缓存与复权 Bar 缓存分离。任何因子计算规则、因子版本或序列化结构变化时递增缓存命名空间版本。缓存未命中仅允许回源重建；不得回退到另一种复权方式或旧因子版本。

任务快照至少记录：

```json
{
  "provider": "qmt_kline",
  "adjustmentMode": "qfq",
  "rawDataVersion": "...",
  "factorVersion": "...",
  "factorSource": "..."
}
```

## 8. 实施步骤

1. 审计 QMT 导出参数、现有 `qmt_kline` 与 L2 数据，在除权日前后比对单位与价格比例，形成原始数据口径结论。
2. 建立幂等的复权因子表迁移、导入任务、版本与质量校验；补齐因子来源配置。
3. 在 `bar_data` 的统一 Provider 后新增 `BarAdjustmentAdapter`，实现三种模式、缺因子拒绝和行情快照记录。
4. 扩展策略方案、回测请求、Bar runner、任务持久化与结果模型，保存并校验 `adjustmentMode`。
5. 在前端标准 Bar 参数区加入复权方式；L2 固定显示不复权，外部错误请求可诊断。
6. 增加 Redis 复权 Bar 缓存命名空间与版本隔离。
7. 更新策略编写手册，说明 `bar（当前K线及账户数据）`价格口径、标准 Bar 复权收益限制与 L2 不复权约束。
8. 同批发布 backend、bar-runner、frontend、migrate 与缓存相关服务；发布前检查排队和运行中任务，发布后验证新任务、历史任务和缓存命中。

## 9. 验证标准

1. 对同一公司行为日验证 `none` Bar 与 L2 实际价格一致，`qfq`/`hfq` Bar 按因子计算一致。
2. 对 `1m`、`5m`、`60m`、`1d` 分别验证时间、OHLC、成交量和金额口径。
3. 标准 Bar 的三种模式分别创建任务，确认策略收到的价格、下一 Bar 开盘成交和结果快照一致。
4. L2 使用非 `none` 参数必须被 422 拒绝；L2 默认任务仍可运行且不受影响。
5. 因子缺失、异常和版本不一致必须在回测前失败，不能静默使用原始 Bar。
6. 同参数重复运行验证 Redis 命中；递增 `factorVersion` 后必须回源并使用新命名空间。
7. 打开旧历史任务确认结果保持原样，页面明确显示复权方式未记录。

## 10. 自审与风险

| 检查项 | 结论与处理 |
| --- | --- |
| 用户选择是否真实生效 | 由适配器输出实际 OHLC，禁止仅保存参数。 |
| L2 是否被错误复权 | 前端隐藏、后端拒绝非 `none`。 |
| 因子缺失是否导致结果失真 | 运行前失败，不回退。 |
| 历史任务是否被重算 | 只读展示旧快照；重跑生成新任务。 |
| 缓存是否混用价格口径 | 键中加入模式、原始版本、因子版本并独立命名空间。 |
| 复权价格是否等同真实资金清算 | 否；首期在页面和手册明确限制，真实跨除权持仓账本另行建设。 |
| 数据源口径不明 | 实施第一步先审计，不将原始表的“QMT 原始”误认为必然不复权。 |

## 11. 待确认前置条件

1. 复权因子的权威数据来源、授权与更新频率。
2. 复权因子表的部署位置、保留周期和增量补数方式。
3. 标准 Bar 复权模式是否仅用于策略研究，还是后续必须与真实公司行为账本联动。
