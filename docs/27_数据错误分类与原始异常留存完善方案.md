# 数据错误分类与原始异常留存完善方案

**日期：** 2026-08-24  
**状态：** 待确认  
**范围：** 回测错误分类、管理员诊断日志与原始异常留存；不处理或修复当前 L2 原始数据。

## 一、问题背景

近期 L2 回测任务 `a68cb91b-d923-43e9-878f-fef83fb7e228` 的实际异常为：

```text
L2DataError: 快照缺少稳定 sequence，且同一时间戳存在重复记录
```

该异常属于行情数据一致性问题，但管理员系统日志将其归为 `internal.unexpected`，无法从分类上快速判断应优先检查策略、执行器还是数据源。

同时，前端不适合直接展示完整 Python 堆栈，但数据库中的系统错误日志必须保留原始异常正文和原始堆栈，供维护人员定位。

## 二、目标与边界

### 目标

1. 将数据可用性、完整性、格式、顺序和映射错误统一归入 `data.*`。
2. 让管理员日志显示稳定的错误编码、分类和可读原因，缩小排查范围。
3. 在 `system_error_log.context_json` 保留原始异常消息与完整堆栈。
4. 前端接口仅返回脱敏后的安全上下文，不暴露原始堆栈。
5. 不改变正常回测的结果、撮合顺序、Redis 缓存行为或 ClickHouse 查询逻辑。

### 不在本次范围

- 不删除、去重、补齐或修复 `quant.tick_quote` 中的重复快照。
- 不将重复时间戳自动选取其中一条继续回放。
- 不调整数据供应、ClickHouse 表结构或数据入库流程。
- 不将网络连接、缓存连接等基础设施故障误归为数据错误。

## 三、错误分类边界

| 分类前缀 | 适用范围 | 示例 | 默认是否可重试 |
| --- | --- | --- | --- |
| `data.*` | 数据不存在、不完整、格式非法、字段映射错误、时间顺序/唯一性错误、单位异常 | 快照重复时间戳且无 sequence、Bar 缺失、价格字段无效 | 否 |
| `clickhouse.*` | ClickHouse 网络、认证、SQL、超时、协议或服务端故障 | DNS 解析失败、连接超时、查询被拒绝 | 视具体错误而定 |
| `cache.*` | Redis 连接、协议、缓存读写故障 | Redis 连接中断、缓存响应非法 | 是 |
| `strategy.*` | 用户策略脚本的语法、运行和返回值错误 | `on_bar` 抛异常、返回非法 action | 否 |
| `worker.*` | 子进程、会话、资源或任务执行器故障 | 策略子进程异常退出、执行被拒绝 | 视具体错误而定 |
| `config.*` | 系统或数据源适配配置非法 | 表名不在白名单、映射配置缺字段 | 否 |
| `internal.*` | 无法识别且不属于以上类别的程序异常 | 未预期代码缺陷 | 是 |

规则：`data.*` 表示“回测所依赖的数据不满足本次计算条件”，而不是“任何名字中包含 data 的异常都归为数据问题”。分类以异常类型和结构化上下文为准，不依赖错误消息中的字符串匹配。

## 四、分类编码设计

| 触发条件 | 错误编码 | 管理员可见原因 | 安全上下文 |
| --- | --- | --- | --- |
| L2 Quote 同一时间戳重复且无稳定 sequence | `data.l2_quote_duplicate_timestamp` | 快照缺少稳定 sequence，且同一时间戳存在重复记录 | `symbol`、`tradeDate`、`duplicateTimestamp`、`duplicateCount`、`sourceTable` |
| L2 Quote 日期或时段无有效数据 | `data.l2_quote_unavailable` | 所选交易日无可用 L2 快照数据 | `symbol`、`tradeDate`、`sourceTable` |
| L2 Bar 缺失或所选周期不可用 | `data.l2_bar_unavailable` | 所选区间没有可用 Bar 数据 | `symbol`、`timeframe`、`dateRange` |
| L2/Bar 字段、单位、时间格式不符合适配器要求 | `data.market_format_invalid` | 行情数据字段或格式不符合回测要求 | `symbol`、`field`、`sourceTable` |
| 数据源映射与表字段不匹配 | `config.data_mapping_invalid` | 数据源映射配置无效 | `profile`、`missingFields` |
| 现有 `L2DataCoverageError` | 保持 `data.unavailable` | 所选区间没有可用行情数据 | 保持现有安全上下文 |

对于无法精确归类的 `L2DataError`，先归入 `data.l2_invalid`，不得回落为 `internal.unexpected`。

## 五、实施步骤

### 1. 将关键数据异常结构化

在 `backend/l2/providers.py` 中，为重复时间戳、数据缺失和格式异常增加明确的 `L2DataError` 子类或结构化属性。

以重复时间戳为例，异常对象必须携带标的、交易日、重复时间戳、重复数量及源表名。异常信息仍保留中文可读描述，但分类不依赖这段描述文本。

### 2. 在错误目录中优先分类数据异常

在 `backend/services/system_error_catalog.py` 中，按“具体数据异常子类 → 通用 `L2DataError` → 其他异常”的顺序分类。

这样，任务 `a68cb91b-d923-43e9-878f-fef83fb7e228` 的同类失败会记录为 `data.l2_quote_duplicate_timestamp`，而不是 `internal.unexpected`。

### 3. 区分安全上下文与原始诊断

写入 `system_error_log` 时分两层保存：

- 安全上下文：分类所需的标的、日期、数据表、字段等，可由管理员页面读取。
- 原始诊断：原始异常消息、异常类型和完整 traceback，以 `__internal_raw_message`、`__internal_raw_type`、`__internal_raw_traceback` 等内部键保存在 `context_json`。

原始诊断不截断、不改写；数据库访问权限继续作为其安全边界。

### 4. 保持前端安全输出

在管理员系统日志 API 的序列化层过滤所有 `__internal_*` 键。前端展示：错误分类、错误编码、用户/任务/标的/周期、可读原因和安全上下文；不展示完整 Python 堆栈。

前台用户仍只看到与策略或数据问题相匹配的简洁提示，不展示内部数据表、连接信息或堆栈。

### 5. 保持历史记录兼容

不新增数据库迁移。既有 `context_json` 可直接承载原始诊断字段。

历史日志没有原始字段时按空值展示，不回填或伪造历史堆栈；新版本部署后产生的错误才具备完整原始诊断。

## 六、验证方案

1. 单元测试重复 Quote 时间戳：断言产生 `data.l2_quote_duplicate_timestamp`，且 `retryable` 为 `false`。
2. 单元测试 `L2DataCoverageError`：断言仍为 `data.unavailable`，防止已有分类回归。
3. 单元测试 ClickHouse DNS/超时和 Redis 连接错误：断言分别保持 `clickhouse.*`、`cache.*`，不得误归入 `data.*`。
4. 单元测试日志写入：断言数据库 `context_json` 含完整 `__internal_raw_*` 原始诊断。
5. 接口测试：断言管理员 API 与普通用户 API 均不返回 `__internal_*` 字段。
6. 使用当前重复时间戳数据复现失败：任务仍应被拒绝，但管理员日志应可直接定位为数据问题和重复时间戳；不修改原始数据。
7. 回归运行现有 L2 与标准 Bar 测试，确认错误分类改造不影响正常回测路径与性能。

## 七、验收标准

1. 任何 `L2DataError` 不再落入 `internal.unexpected`。
2. 重复时间戳无 sequence 的任务显示 `data.l2_quote_duplicate_timestamp`，管理员可看到标的、交易日和重复时间。
3. 数据库保留该任务的完整原始异常消息与堆栈；前端接口不泄露这些内部字段。
4. ClickHouse、Redis、策略脚本和 worker 故障仍按各自分类展示。
5. 当前原始数据完全不被改动，重复数据任务仍以“数据问题”安全失败。

## 八、方案自审

- 分类边界以异常类型与上下文为主，避免用中文错误文本匹配而产生误判。
- 原始堆栈只存数据库、仅通过受控数据库权限访问，兼顾排查能力与前端安全。
- 本方案只改善诊断与分类，不自动修正数据，因此不会破坏 L2 回放的可复现性。
- 具体数据修复、去重策略或入库校验应作为后续独立任务，避免与本次日志改造耦合。
