# 回测日期区间选择器交互优化方案

> 现行决策说明：日期选择交互仍按本文执行；其中依赖行情预检或提交校验阻止运行的描述已由 `docs/adr/0004-unified-preflight-and-loading.md` 的 2026-09-22 修订取代。

## 一、最终结论

本方案在讨论过程中曾采用双月日历、年月直选和日期可用状态展示。实际体验验证后确认，这种设计仍要求用户打开面板、定位月份并判断具体日期是否有数据，偏离了“快速设置回测边界”的核心任务。

最终执行方案修订为：保留页面现有的开始、结束两个横向日期框，不再打开日历；将日期字符串 `YYYY-MM-DD` 内的年份、月份、日期划分为三个选择片段。点击某个片段后，在该数字位置展开可滚动长列表，当前值固定在中间高亮轨道，用户可以滚动列表或直接点击可见候选值。日期框上方保留数据覆盖范围与常用快捷区间，下方提供“从最早日期开始”“取消”“应用”，所有选择先进入草稿，确认后一次性应用。

2026-09-23 修订：滚轮和快捷操作期间不校验、不报错；仅在用户点击“应用”时，按闭区间检查所选范围是否完整落在当前可回测起止日期内。端点允许选取，越界、倒置或范围不可用时保留草稿并提示，不更新正式参数。该检查只比较范围元数据，不恢复行情完整性预检。

此前文档中的双月日历和日级数据状态设计由本节所述最终方案取代；数据范围提示、快捷区间与确认操作继续保留，但不再依赖日历面板。

## 二、问题原因

原日期选择器把“设置回测时间边界”设计成了“在日历中寻找日期”：

1. 跨月、跨年需要多次翻页或额外打开年月选择器。
2. 开始和结束日期需要分别进入日历操作。
3. 日历展示每天的数据状态，迫使用户关注本应由系统处理的行情细节。
4. 日历还需要按可见月份额外请求预检数据，增加交互状态和请求复杂度。
5. 用户真正需要的是快速调整 `YYYY-MM-DD` 中的某一部分，而不是确认星期和月历位置。

## 三、目标与边界

### 3.1 目标

1. 保持现有横向布局和紧凑尺寸，不重做回测参数区域。
2. 年、月、日可以在当前日期数字上分别展开并独立选择。
3. 不显示日历，只显示锚定在活动数字上的纵向滚轮长列表。
4. 滚轮只处理公历日期，不承担行情数据可用性判断。
5. 保留可回测范围、近 1 月、近 3 月、今年、全部数据和从最早日期开始等高频入口。
6. 日期滚动和快捷选择先修改草稿，由取消或应用明确结束本次编辑。
7. 三处回测日期入口继续复用同一个组件，行为保持一致。

### 3.2 明确不做

- 不展示单月或双月日历。
- 不展示逐日的可用、缺失、未来或非交易日状态。
- 不为日期滚动额外请求行情数据。
- 不根据最早或最晚行情日期限制滚轮。
- 不在到达行情边界时显示额外提示。
- 不新增最近使用区间或自由文本输入。
- 不新增方向键、PageUp、PageDown 等键盘导航。
- 不修改后端接口、回测载荷、数据库、缓存或依赖。

## 四、最终界面

日期控件继续保持当前横向排列，完整结构为：

```text
可回测范围：2015-01-05 — 2026-09-18

[近1月] [近3月] [今年] [全部数据]

┌──────────────────┐  ┌──────────────────┐
│ 开始   2026-06-01 │  │ 结束   2026-06-26 │
└──────────────────┘  └──────────────────┘

[从最早日期开始]                  [取消] [应用]
```

日期字符串内部划分为三个独立选择区域，界面不增加“年、月、日”文字：

```text
开始   [2026]-[06]-[01]
         ↕     ↕    ↕
```

点击年份后的展开状态示意：

```text
开始   [2026]-06-01
         2024
         2025
       ───────
       > 2026 <
       ───────
         2027
         2028
```

长列表通过 Portal 锚定在活动数字中心，避免被回测配置区域裁剪。当前值上下始终保留候选上下文，列表边缘使用渐隐处理；日期框本身不改变尺寸或位置。

## 五、交互规则

### 5.1 可见滚轮列表

- 点击年份、月份或日期数字，展开对应的纵向长列表。
- 同一时间只展开一个列表，再次点击当前数字或点击列表外部时收起。
- 列表显示当前值上下的候选值；居中高亮项就是当前选中值。
- 用户可以直接滚动列表，也可以点击当前可见的候选值使其滚动到中间。
- 列表滚动时只消费自身滚轮，不带动页面滚动。
- 开始日期和结束日期的三个部分互相独立，选中后更新当前草稿，不立即改写已生效的回测参数。
- 年份使用虚拟长列表，只渲染视口附近的候选项，避免大量 DOM 节点。

### 5.2 公历日期合法性

- 年份列表显示四位年份；月份列表显示 `01–12`。
- 日期列表按当前年份和月份显示 `01` 至当月最后一天，不出现无效日期。
- 改变年份或月份后，如果原日期在目标月份不存在，则夹取到目标月份最后一天。
- 闰年 2 月 29 日改为非闰年时自动变为 2 月 28 日。
- 这些规则只保证日期格式和公历含义合法，不检查当天是否为交易日或是否有行情。

### 5.3 开始与结束日期独立

- 滚动开始日期只修改开始日期，不联动结束日期。
- 滚动结束日期只修改结束日期，不联动开始日期。
- “从最早日期开始”只修改开始日期，即使草稿暂时出现开始日期晚于结束日期，也不改写结束日期。
- 草稿允许暂时出现倒置区间；点击“应用”后日期组件提示“开始日期不能晚于结束日期”，不自行纠正或提交草稿。

### 5.4 数据范围职责

日期滚轮与行情数据范围完全解耦：

```text
日期滚轮       → 选择合法公历日期
页面范围提示   → 告知当前标的和周期的数据覆盖情况
既有回测校验   → 处理超出覆盖范围、数据缺口和不可运行区间
```

滚轮允许用户选择早于最早行情日期或晚于最新行情日期的合法日期。组件不逐段检测、不阻止滚动，也不显示“已到最早可回测日期”。超出数据覆盖范围时，继续由页面已有提示、预检和回测提交校验提供错误信息。现有数据范围只用于展示覆盖起止日期和计算快捷区间，不做逐日检查。

### 5.5 快捷区间与确认

- “近1月”和“近3月”以最新可回测日期为结束日，生成包含结束日在内的完整自然月跨度，并在早于最早数据日期时自动夹取。
- “今年”从最新可回测日期所在年份的 1 月 1 日开始，并在必要时夹取到最早数据日期。
- “全部数据”直接使用当前标的、周期的数据覆盖起止日期。
- “从最早日期开始”只把草稿开始日期改为最早数据日期，保持当前草稿结束日期不变。
- 滚轮或快捷操作产生草稿后，“取消”恢复本次编辑前的区间；“应用”先执行一次范围边界校验，通过后再一次性提交开始和结束日期，选择过程中不触发校验。

## 六、实现范围

### 6.1 日期组件

`frontend/src/components/BacktestDateRangePicker.tsx`：

- 删除日历、月份导航和日级状态逻辑。
- 将开始、结束日期拆分为年份、月份、日期三个可选择片段。
- 使用 Portal 在活动数字处显示纵向滚轮长列表，并使用虚拟滚动渲染年份。
- 实现候选值选择和月末夹取，开始、结束端点保持独立。
- 展示现有数据覆盖起止日期，并基于这两个边界生成快捷区间。
- 在组件内维护编辑草稿，通过 `onApplyRange(startDate, endDate)` 一次性提交。

### 6.2 页面适配

`frontend/src/components/BacktestPage.tsx`：

- 删除仅用于日历视窗的月份状态和按月预检请求。
- 三处日期入口统一传入现有数据状态的 `firstDate/lastDate`。
- 应用时同时更新 `params.startDate/params.endDate`，取消时不改变页面参数。
- 保留页面原有的数据覆盖状态、参数预检和运行校验。

### 6.3 样式

`frontend/src/styles/global.css`：

- 保留两个日期框的横向网格、边框、尺寸和字体层级。
- 为覆盖范围、快捷区间和底部确认区增加紧凑的视觉层级。
- 为年份、月份、日期片段增加克制的悬停、活动反馈。
- 为纵向长列表增加中间选中轨道、上下候选渐隐和滚动吸附。
- 数字使用等宽数字特性，滚动后不产生横向跳动。

### 6.4 文档与测试

- 更新本方案和 `docs/玄龄回测系统使用手册.md`。
- 重写组件测试，覆盖长列表上下文、滚动与点击选择、公历边界、区间同步和无日历结构。
- 不修改后端测试或接口契约。

## 七、验证计划

### 7.1 自动化测试

1. 页面渲染可回测范围、四个快捷区间、横向开始和结束日期框及底部操作，不存在日历。
2. 点击年份、月份、日期会分别显示带上下候选上下文的长列表。
3. 滚动列表和点击可见候选值时只修改对应部分。
4. 月末夹取和闰年转换正确。
5. 开始超过结束、结束早于开始时，另一端保持不变，点击应用后由日期组件提示。
6. 快捷区间计算、最早日期、取消和应用行为正确，未应用的草稿不会改写页面参数。
7. 没有数据边界时仍可使用日期滚轮，但范围提示显示读取状态且快捷按钮禁用。
8. TypeScript 检查、正式构建和完整前端测试通过；无关失败单独记录。

### 7.2 浏览器检查

1. 桌面端两个日期框保持横向排列，与改造前尺寸接近。
2. 范围提示、快捷区间和底部操作在配置栏内清晰可见，不挤压日期数字。
3. 年、月、日点击区域准确，长列表中心选中值与日期框同步。
4. 滚动长列表时页面本身不跟随上下移动。
5. 取消不改变已生效区间，应用校验通过后两个日期同时更新。
6. 三处回测日期入口交互一致。
7. 日期变化后，页面已有数据覆盖提示和回测运行校验仍正常工作。

## 八、验收标准

1. 用户无需打开日历即可调整开始和结束日期，并能看到当前值上下的候选上下文。
2. 控件显示可回测范围、近 1 月、近 3 月、今年、全部数据、从最早日期开始、取消和应用。
3. 控件外观继续显示为“开始 `YYYY-MM-DD`”“结束 `YYYY-MM-DD`”两个横向日期框。
4. 年、月、日三个数字片段可以独立展开可见滚轮长列表。
5. 滚轮和快捷选择只修改草稿且不触发校验，取消可还原，应用校验通过时两个日期一次性生效。
6. 开始、结束日期独立编辑，滚动任一端点不会联动另一端。
7. 控件只在点击应用时检查区间顺序和可回测闭区间边界，不检查逐日行情完整性。
8. 不再存在日历视窗专用的按月行情请求。
9. 数据覆盖提示和既有回测错误仍是数据范围问题的反馈入口。
10. 不新增键盘导航、最近使用区间或自由文本输入。
11. 三处日期入口、测试和使用手册与最终交互一致。

## 九、风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 用户不知道数字可选择 | 悬停时使用浅色背景和底线反馈，点击后立即展开带上下候选的长列表。 |
| 月末切换产生非法日期 | 年份和月份变化时统一执行目标月份末日夹取。 |
| 草稿出现倒置区间 | 保持两个端点独立，不静默改值；点击应用后由日期组件给出明确提示。 |
| 滚轮同时带动页面 | 长列表使用独立滚动容器和 `overscroll-behavior` 隔离页面滚动。 |
| 快捷操作导致参数反复预检 | 所有编辑先写入本地草稿，只在“应用”时一次性更新两个日期。 |
| 前端重复判断行情边界 | 日期组件仅使用现有覆盖起止日期展示范围和生成快捷值，不请求或判断逐日行情状态。 |
| 文档仍保留双日历描述 | 本文以最终修订版整体替换旧方案，使用手册同步更新。 |

## 十、自审结论

- 改动集中在日期组件、页面接线、作用域样式、测试和既有文档。
- 没有修改后端、接口、数据库、依赖或回测执行语义。
- 行情可用性仍由现有页面与回测校验负责，不在滚轮中复制逐日判断。
- 最终方案保持用户指定的当前横向外观，在外围补齐范围提示、快捷区间与确认操作，只在活动数字上展开可见滚轮长列表。
