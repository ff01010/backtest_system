# 策略广场与共享回测方案

日期：2026-09-15
状态：已实施，待远程样本与发布验证

## 1. 背景与问题结论

系统当前将策略方案、策略版本、回测任务、研究信号快照和结果附件按用户隔离。现有名称中容易产生两类误解：

- `strategy_config.published` 表示策略已固定为可运行版本，不表示其他用户可见。
- `/api/v1`“回测开放 API”使用 API Key 访问 Key 所属用户自己的资源，不提供跨用户公开读取。

当前历史回测已经冻结策略代码、参数、行情信息和结果，可作为共享内容来源；但同一记录还包含账户关联、内部路径、请求标识和系统诊断等不能成为公共业务契约的字段。历史回测还允许所有者永久删除，直接给 `backtest_run` 增加公开标记会令共享内容依赖原任务生命周期，并要求放宽已经建立的行级隔离。

本方案新增独立的“共享回测”领域对象和“策略广场”用户入口。共享回测是从一次成功回测生成的、带模式版本的不可变业务快照。它面向正常登录的内部用户，不改变原策略、原回测、开放 API 或任务执行链路的所有权语义。

核心结论为：

> 共享回测是独立、不可变、可撤回展示的组织内共享资产；策略副本是接收者独立拥有的完整策略，不能只是对原作者资源的持续引用。

## 2. 统一术语

| 术语 | 含义 | 不得混用 |
|---|---|---|
| 策略发布 | 将当前完整策略固定为可运行的不可变版本，不改变可见范围 | 共享、上架 |
| 共享回测 | 从一次成功回测生成的组织内不可变共享记录 | 开放 API 任务、原历史任务 |
| 策略广场 | 登录用户发现、查看、收藏和复制共享回测的区域 | 匿名公开站点、开放 API |
| 策略副本 | 接收者从共享回测生成并独立拥有的完整策略 | 原作者策略的引用或共同所有权 |
| 共享来源 | 策略副本及其衍生回测保留的原共享回测和原作者信息 | 当前策略所有者 |

页面、接口、测试和后续工单统一使用以上术语。“公共池”“上传策略任务”只作为原始需求表述，不作为正式产品命名。

## 3. 目标、范围与不做事项

### 3.1 目标

1. 用户可以将自己认为有价值的一次成功回测共享到策略广场。
2. 所有正常登录用户可以查看完整业务内容，收藏共享回测，并复制为自己的完整策略。
3. 共享内容与原任务生命周期隔离，作者修改或删除原策略、原回测时不改变已上架快照。
4. 策略副本与原作者资源解耦，作者撤回或管理员下架后仍可继续编辑和运行。
5. 保留明确作者署名和衍生来源，避免复制后丢失归属信息。
6. 不放宽个人策略、个人回测、附件或开放 API 的现有权限边界。

### 3.2 本期范围

- 成功回测的上架资格校验与共享快照生成。
- 策略广场列表、搜索、筛选、排序和详情展示。
- 共享标题、说明、标签及作者姓名快照。
- 收藏、复制次数与“一键复制到我的策略”。
- 私有研究信号快照和附件随共享、复制形成独立副本。
- 作者撤回、重新上架和“我的共享”。
- 管理员下架、填写原因和恢复。
- 历史成功回测按相同规则手动上架。
- 共享来源在策略副本、衍生回测和再次共享中的传递。

### 3.3 不做事项

1. 不提供匿名浏览、匿名下载或互联网搜索引擎索引。
2. 不自动公开任何新旧回测任务。
3. 不设置收益率、胜率或夏普比率上架门槛。
4. 不做事前人工审核；上架成功后立即对登录用户可见。
5. 不提供直接运行共享回测的能力；复制动作也不自动执行代码。
6. 不做点赞、评论、公开浏览次数、收益排行榜或推荐算法。
7. 不改变策略回调、撮合、行情、费用、仓位、收益和调度语义。
8. 不允许通过共享接口读取原作者账户、个人备注、内部错误或存储路径。
9. 不把相同内容物理绑定成可被多个用户共同修改的策略记录。

## 4. 产品行为

### 4.1 上架入口与资格

“历史回测”中仅对满足以下条件的任务显示可用的“共享到策略广场”操作：

1. 当前用户是任务所有者。
2. 任务状态为 `succeeded`。
3. 已保存策略代码快照、参数快照和完整结果。
4. 快照结构能够由当前共享快照构造器识别。
5. 复现依赖存在且能够复制，包括研究信号快照和附件。

功能上线前的旧历史任务同样适用。资料完整即可手动上架；缺少关键资料时拒绝，并提示“历史任务资料不完整，请重新运行后共享”。系统不得为旧任务补猜代码、参数、数据或结果，也不得批量自动公开。

上架表单包含：

- 共享标题：必填，用于列表和详情展示。
- 策略说明：必填，用于说明思路、适用范围和已知限制。
- 标签：可选，使用统一长度、数量和去重规则。
- 共享确认：明确代码、业务参数、结果和复现依赖将对全体内部登录用户可见，并提醒作者检查代码中自行写入的敏感内容。

现有回测 `note` 和 `tags` 继续作为个人历史元数据，不自动带入或公开。提交成功后无需审核，状态直接进入“已上架”。

### 4.2 策略广场列表

列表卡片至少展示：

- 共享标题、作者姓名快照和首次上架时间。
- 标的、周期、回测区间和策略类别。
- 总收益率、最大回撤和夏普比率。
- 复制次数、当前用户是否已收藏、是否已经复制。
- 来源标识；衍生共享显示原共享标题与原作者姓名。

列表支持：

- 按共享标题、作者姓名、标的和标签搜索。
- 按策略类别、周期筛选。
- 按首次上架时间倒序排列。
- 按复制次数倒序排列，复制次数相同再按首次上架时间和共享编号稳定排序。

本期不按收益指标排序，也不生成“冠军”“最佳”等平台背书标签。

### 4.3 详情展示

详情页提供以下业务信息：

1. 共享说明、标签、作者和来源。
2. 策略代码、入口类型、代码校验值和运行时版本。
3. 标的、周期、回测区间、初始资金、手续费、滑点、成交模型、执行算法、策略类别和完整业务参数。
4. 收益摘要、收益曲线、基准、每日持仓、闭环交易、成交记录、跳过信号、执行计划和运行警告。
5. 数据快照摘要、复现依赖清单和内容校验值。

页面固定展示“历史回测结果不代表未来表现”。策略指标必须与回测区间、成本模型、成交模型和数据范围同时展示，不能只突出收益数字。

代码、说明和标签均按纯文本或受控 Markdown 渲染，不允许执行任意 HTML。大量交易、信号、持仓和曲线数据通过分页或专用详情接口加载，列表接口不得返回完整代码和结果。

### 4.4 收藏

登录用户可以收藏或取消收藏已上架内容。收藏是个人书签，不表示点赞或平台质量背书。

共享回测撤回或下架后：

- 普通用户的收藏关系保留，以便原条目重新上架后恢复。
- 普通收藏列表不返回详情，只显示统一的“该共享回测已不可用”状态或从可用列表隐藏。
- 收藏关系和收藏数量不参与公开排序。

### 4.5 一键复制

点击“复制到我的策略”后，后端在同一业务事务中完成：

1. 校验共享回测仍处于“已上架”状态。
2. 复制策略代码、入口信息、策略参数、标的、周期、基准、成交模型、执行算法和运行参数。
3. 清除原作者账户 ID、账户名称和其他所有者专属关联。
4. 将研究信号快照及附件导入为接收者独立拥有的不可变依赖，不持续引用共享下载权限。
5. 使用现有“完整策略”服务创建新的策略方案、独立脚本身份和第一个不可变脚本版本。
6. 将策略命名为“共享标题-副本”；同名时按现有命名规则追加序号。
7. 保存共享来源，包括共享编号、原作者姓名快照和原共享标题。
8. 创建唯一复制记录并增加复制次数。
9. 返回新策略身份，由前端打开策略编辑器；不创建回测任务，也不自动执行代码。

同一接收者对同一共享回测只生成一个直接副本。重复请求或重复点击返回已有副本；用户需要更多实验副本时，使用个人策略编辑器的“另存为”。

复制后的策略可以自由修改和运行。其自行生成的新成功回测可以再次共享，但必须携带“源自某共享回测”的归属信息；系统不允许直接把别人的共享快照作为自己的新条目原封不动上架。

### 4.6 作者管理

策略广场提供“我的共享”，作者可以：

- 查看自己处于已上架、已撤回或已下架状态的条目。
- 修改共享标题、说明和标签。
- 撤回已上架条目。
- 将自己撤回的条目重新上架。
- 查看管理员下架时间和原因。

修改展示元数据不得改变策略代码、参数、依赖、结果、作者姓名快照、首次上架时间或共享摘要校验值。重新上架恢复原条目、原共享编号、收藏关系和复制次数，不生成新条目，也不通过重新上架刷新“最新”排序。

### 4.7 管理员处置

管理员可以下架当前已上架的共享回测，下架时必须填写原因。下架后：

- 普通用户无法再查看详情、下载依赖、收藏或复制。
- 作者在“我的共享”中可以查看状态、时间和原因，但不能自行恢复。
- 管理员可以恢复误下架内容，恢复后保留原统计数据和首次上架时间。
- 首期不新增站内通知系统，作者通过“我的共享”查看处置结果。

## 5. 领域模型与状态机

### 5.1 `backtest_publication（共享回测）`

建议新增独立聚合，核心字段如下：

| 字段 | 约束与用途 |
|---|---|
| `id` | 全局 UUID，作为共享编号和稳定链接身份 |
| `owner_user_id` | 原作者；账号删除后允许置空，不能级联删除共享内容 |
| `author_name_snapshot` | 首次上架时姓名快照，后续改名不追溯更新 |
| `source_run_id` | 原历史回测；删除原任务时置空，不删除共享回测 |
| `title`、`description`、`tags` | 独立共享展示元数据 |
| `status` | `active`、`withdrawn`、`removed` |
| `snapshot_schema_version` | 共享快照模式版本，首期为 `1` |
| `snapshot_json` | 按白名单生成的完整业务快照 |
| `snapshot_digest` | 规范化快照摘要，核心内容创建后不可变 |
| `source_publication_id` | 衍生共享的直接来源，可为空 |
| `source_author_name_snapshot`、`source_title_snapshot` | 即使来源撤回或账号删除仍可显示归属 |
| `copy_count` | 成功创建唯一直接副本后事务性递增 |
| `first_published_at` | 首次上架时间，重新上架不改变 |
| `withdrawn_at` | 作者最近撤回时间 |
| `removed_at`、`removed_by_user_id`、`removal_reason` | 管理员处置审计 |
| `created_at`、`updated_at` | 记录创建和展示元数据更新时间 |

同一 `source_run_id` 最多对应一个共享回测。原任务存在时由数据库唯一约束防止重复上架；原任务删除后共享回测仍保留，不再存在可被重复上架的来源任务。

### 5.2 状态机

```text
                       管理员下架
                  ┌─────────────────┐
                  v                 │
作者上架/重新上架 -> active ------> removed
       ^             │               │
       │             │ 作者撤回      │ 管理员恢复
       │             v               │
       └--------- withdrawn          └----> active
```

规则如下：

1. 新建共享回测直接进入 `active`，没有待审核状态。
2. 作者只能执行 `active -> withdrawn` 和本人 `withdrawn -> active`。
3. 管理员执行 `active -> removed` 和 `removed -> active`；下架原因必填。
4. `removed` 状态下作者不能修改状态或重新上架。
5. 所有状态变化记录操作者、时间和原因；状态变化不改写核心快照。
6. 作者账号停用或删除不自动改变状态；失去作者后只能由管理员管理。

### 5.3 收藏、复制与来源

建议增加以下关系：

- `backtest_publication_favorite`：以 `(publication_id, user_id)` 唯一，保存个人收藏。撤回或下架不级联删除。
- `backtest_publication_copy`：以 `(publication_id, recipient_user_id)` 唯一，关联创建的目标策略方案并保证复制幂等。
- 策略来源元数据：策略副本保存来源共享编号、作者姓名快照和共享标题快照；运行时将该归属信息冻结到回测快照，但不参与策略执行或草稿指纹。

复制次数只统计成功创建的唯一直接副本。重复点击、请求重试、事务失败和用户在个人编辑器中另存为均不得增加该数字。

### 5.4 共享附件

研究信号和附件不能继续依赖原 `artifact_file` 的所有者权限或原任务生命周期。建议新增共享附件记录，至少保存：

- 共享回测 ID、附件类型、展示名称、内容类型和字节数。
- 内容校验值、内部存储键和快照模式版本。
- 可选的来源附件 ID，仅用于审计，不作为读取前提。

上架时将需要复现的内容复制到共享命名空间；复制策略时再导入为接收者拥有的资源。共享读取接口只返回受控元数据和鉴权下载地址，不返回内部存储键。文件复制失败时不能留下可见的半完成共享条目；数据库失败时应清理暂存文件。

研究信号副本必须成为接收者可被正常回测预检识别的用户资源，并获得新的数据集身份。不得把原作者的外部授权、原数据集 ID 或临时下载地址直接写入接收者策略。若导入依赖失败，整个策略复制事务失败且复制次数不增加。

## 6. 共享快照契约

### 6.1 版本与不可变性

共享快照使用显式 `snapshot_schema_version`。首期写入版本 `1`，读取端按保存版本解释，禁止使用新默认值重算或改写旧共享内容。

创建快照时对规范化 JSON 计算摘要。除共享标题、说明、标签和生命周期字段外，任何策略、参数、结果、依赖清单或来源内容变化都必须来自新的历史回测和新的共享条目，不允许更新旧核心快照。

未来新增字段优先采用向后兼容的可选字段；需要改变既有字段语义时增加快照模式版本，并同时保留旧版本读取器。缓存结构若基于共享 DTO，必须使用独立版本命名空间。

### 6.2 业务字段白名单

`snapshot_json` 按明确白名单构造，建议分为：

1. `strategy`：策略名称、说明、入口类型、代码、代码校验值、脚本版本信息、运行时版本和能力摘要。
2. `configuration`：标的、周期、基准、回测区间、策略类别、资金、成本、成交模型、执行算法、持仓设置、预热设置和策略参数。
3. `data`：行情数据版本、实际数据范围、内容摘要、研究信号对齐摘要和依赖清单。
4. `result`：收益摘要、权益曲线、基准、每日持仓、闭环交易、成交、跳过信号、执行计划、实验清单和警告。
5. `origin`：直接来源共享编号、原作者姓名快照和原共享标题快照。

列表 DTO 仅从快照中投影卡片所需的少量字段；详情、图表、交易和信号使用独立 DTO 或分页接口。不得直接复用所有者历史详情 DTO，也不得把 `snapshot_json` 原样透传给前端。

### 6.3 必须排除的系统字段

无论内部用户关系如何，以下字段均不属于共享业务内容：

- 用户 ID、账户 ID、账户名称、登录名、邮箱和会话信息。
- API Key、授权码、外部服务凭据及任何认证摘要。
- `output_dir`、内部存储键、宿主机路径、容器路径和临时文件名。
- 请求键、任务租约、Worker 标识、队列尝试令牌和调度状态。
- 原始异常、堆栈、管理员诊断、系统错误记录和内部服务地址。
- 原作者的私人回测备注与私人标签。

作者写入策略代码、策略参数或共享说明的文本按确认内容原样向内部用户展示，系统不承诺自动识别其中所有秘密。上架表单必须提供明确提醒，日志仍不得记录完整代码或附件正文。

## 7. 权限边界

### 7.1 权限矩阵

| 能力 | 未登录 | 普通登录用户 | 作者 | 管理员 |
|---|---:|---:|---:|---:|
| 浏览 `active` 列表和详情 | 否 | 是 | 是 | 是 |
| 收藏、取消收藏 `active` 条目 | 否 | 是 | 是 | 是 |
| 复制 `active` 条目 | 否 | 是 | 是 | 是 |
| 查看本人非 `active` 条目 | 否 | 否 | 是 | 是 |
| 修改共享展示元数据 | 否 | 否 | 是 | 是 |
| 撤回、重新上架 | 否 | 否 | 是，仅本人撤回项 | 是 |
| 下架、恢复、查看处置原因 | 否 | 否 | 仅查看本人原因 | 是 |

普通用户访问撤回、下架或不存在的共享编号时统一返回“该共享回测已不可用”，不能据此区分作者撤回、管理员下架或资源不存在。作者和管理员使用独立管理读取接口获取真实状态。

### 7.2 数据库隔离

新增表必须启用并强制 RLS：

- 正常登录用户只能读取 `active` 共享业务投影及自己的收藏、复制关系。
- 作者可以读取和管理自己的所有状态记录，但不能写核心快照。
- 管理员可以读取全部状态并执行下架、恢复。
- 共享附件按所属共享回测状态和当前用户身份授权。
- 原 `user_strategy`、`strategy_config`、`backtest_run`、队列表和 `artifact_file` 策略保持不变。

后端查询仍显式写出所有权和状态条件，不能只依赖前端隐藏入口。API Key 开放接口继续只访问 Key 所属用户资源，不自动获得策略广场读取或复制能力；若未来需要开放，应新增独立 Scope 和版本化契约。

网页会话接口使用独立资源名，避免与 `/api/v1` 开放回测 API 混淆：

| `POST /api/backtest/runs/{run_id}/publication` | 校验并创建共享回测；重复请求返回现有条目 |

| `GET /api/shared-backtests/{publication_id}/chart` | 读取曲线和图表数据 |
| `GET /api/shared-backtests/mine` | 读取作者自己的全部状态条目 |
| `PATCH /api/shared-backtests/{publication_id}` | 修改标题、说明和标签 |
| `POST /api/shared-backtests/{publication_id}/withdraw` | 作者撤回 |

## 9. 关键事务

### 9.1 创建共享回测

1. 在所有者上下文锁定原回测并检查 `succeeded`。
2. 检查同一原回测是否已有共享条目；存在时幂等返回，不创建第二条。
3. 使用版本化构造器从已冻结数据生成业务白名单快照。
4. 校验快照完整性、结果结构、依赖存在性和支持的模式版本。
5. 将研究信号和其他复现附件复制到暂存共享命名空间并校验内容摘要。
6. 在数据库事务中写入共享回测、附件清单和审计记录。
7. 事务成功后使附件可读；任一步失败则清理暂存内容，不产生可见条目。

原回测删除时只将 `source_run_id` 置空。共享快照和共享附件不得被级联删除。

### 9.2 复制到我的策略

1. 锁定并确认共享回测仍为 `active`，当前快照模式受支持。
2. 查询 `(publication_id, recipient_user_id)`；已有复制记录则返回现有策略。
3. 导入研究信号和附件为接收者资源，校验内容摘要。
4. 调用现有完整策略写服务，在同一逻辑事务中创建独立脚本、脚本版本和策略方案。
5. 清除账户归属，写入不可变共享来源。
6. 写入唯一复制记录并原子增加 `copy_count`。
7. 任一步失败时回滚数据库记录并清理新建附件，不增加复制次数。

如果并发复制请求发生竞争，数据库唯一约束决定唯一成功者；失败请求重新读取已创建副本并返回，不能暴露数据库冲突。

### 9.3 来源传递

从策略副本提交回测时，共享来源作为展示元数据写入已保存方案快照和运行快照，不属于 `strategyParams（策略参数）`，不参与策略运行、方案草稿指纹或已保存参数一致性校验。

当衍生回测再次共享时，新共享条目的作者是当前任务所有者，同时保存直接来源共享编号、原作者姓名快照和原共享标题快照。来源条目撤回、下架或作者账号删除后，归属信息仍保留。

## 10. 前端方案

### 10.1 导航和页面

主导航新增“策略广场”，页面包含：

- “全部共享”：卡片列表、搜索、筛选、排序和分页。
- “我的收藏”：仅展示当前仍可用的收藏，并正确处理不可用条目。
- “我的共享”：展示本人全部状态和管理操作。

详情采用按需加载的分区或标签页：概览、策略代码、参数与数据、收益与持仓、成交与信号。大量明细不在首屏一次加载。

### 10.2 历史回测入口

成功且资料完整的历史记录显示“共享到策略广场”。不满足条件时操作禁用并显示具体原因。已经上架的记录显示“查看共享”，避免重复提交。

上架弹窗要求标题和说明，允许标签，并显示内部共享范围与敏感内容提醒。提交成功后跳转共享详情或显示稳定链接。

### 10.3 复制体验

详情页提供“复制到我的策略”：

- 首次复制显示复制内容和账户清除提示。
- 成功后打开新策略，提醒用户检查代码和选择自己的账户后再运行。
- 已复制时按钮改为“打开我的副本”。
- 复制失败显示可恢复错误；不得在前端先行增加复制次数。
- 衍生策略及其回测显示来源标签和原作者姓名。

### 10.4 不可用状态

普通用户从旧链接或收藏访问非 `active` 条目时，只显示统一不可用页面，不渲染已缓存代码、参数或结果。前端收到撤回或下架响应后应清理该条目的详情缓存。

作者和管理员管理页可以查看非 `active` 快照，但管理接口与普通详情接口分离，避免误用普通缓存或路由。

## 11. 安全、隐私与内容边界

1. 策略广场仍要求有效登录会话和状态正常的用户；内部人员身份不能替代鉴权和授权。
2. 共享说明、标签、代码和结果文本按不可信输入处理，防止脚本注入和存储型 XSS。
3. 附件下载校验当前共享状态，使用受控文件名与 `Content-Disposition`，禁止目录穿越和直接暴露存储地址。
4. 共享 DTO 使用白名单，增加回归测试证明账户、路径、错误和凭据字段不会出现。
5. 代码可能由作者主动写入敏感文字；系统提供明确确认和提醒，但首期不引入人工审核或声称能够自动发现所有秘密。
6. 复制只是创建用户资源，不直接运行第三方代码。用户必须先进入编辑器检查并主动提交回测。
7. 标题、说明、标签、搜索、分页、附件数量和总大小设置合理上限，防止内部误操作导致资源耗尽。
8. 日志和审计只记录共享编号、操作者、状态和内容摘要，不记录完整代码、参数正文或附件正文。

## 12. 历史兼容与删除语义

- 旧回测不迁移为共享回测，只在用户主动上架时按当前构造器生成版本 `1` 快照。
- 旧回测关键快照不完整时拒绝上架，不使用当前策略或当前默认值补齐。
- 新默认参数、新运行时和新结果字段不得重算已有共享快照。
- 原回测、原策略或原附件删除不删除共享回测和共享附件。
- 作者删除账号时 `owner_user_id` 置空，作者姓名快照和共享内容保留，后续仅管理员可管理。
- 共享撤回或下架不删除策略副本、接收者附件或来源归属。
- 共享快照若遇到未来不支持的模式版本，普通用户得到明确兼容错误，数据保持原样等待兼容读取器，不能静默降级。

已实现 `030_shared_backtest_publications.sql` 至 `036_shared_backtest_function_rls.sql` 七个幂等迁移，分别覆盖发布核心、收藏、复制、独立附件、作者生命周期、管理员生命周期和强制 RLS 下的受控函数写边界。不得修改已执行迁移。

迁移至少包括：

1. `backtest_publication`、共享附件、收藏和复制关系表。
2. 共享状态、快照版本、标题说明长度、复制次数和时间字段约束。
3. 同一原回测唯一共享、同一用户唯一直接副本和唯一收藏约束。

6. 列表查询所需的状态、首次上架时间、复制次数、作者、标的、周期和标签索引。

迁移不回填共享数据，不扫描或复制既有大型结果附件。迁移前后核对表、约束、索引、策略和授权是否完整，并验证普通用户不能读取其他用户未共享的任务。

## 15. 验收标准

1. 正常用户能从本人资料完整的成功历史回测创建唯一共享回测，无需审核即可在策略广场看到。
2. 其他登录用户能搜索、筛选、查看完整业务内容并收藏；未登录用户不能访问。
3. 列表和详情不泄露账户身份、内部路径、后台诊断或存储键。
4. 每个共享详情同时展示业绩指标、回测区间、成本、成交模型、数据摘要、运行时和风险提示。
5. 一键复制创建接收者独立拥有的完整策略和依赖，清除原账户关联，不自动运行。
6. 同一用户重复复制返回已有副本，复制次数准确且并发安全。
7. 副本运行产生自己的历史任务；再次共享时保留来源且不能直接重复上架原快照。
8. 作者可以修改展示信息、撤回和重新上架；重新上架不重置编号、统计或首次时间。
9. 管理员下架必须填写原因，作者可查看且不能自行恢复；管理员恢复后原统计不变。
10. 撤回、下架、删除原任务或作者账号变化均不破坏已复制副本。
11. 旧历史任务只有在关键快照完整时才能共享，历史内容不按新默认值重算。
12. 数据库约束、RLS、接口鉴权和前端入口共同阻止跨用户读取未共享资源。

3. 发布完整后端和前端入口；若研究信号或任务载荷契约影响 Runner，同批发布全部依赖服务。
4. 执行两个普通用户之间的权限冒烟测试及代表性复制运行。

回滚优先关闭前端入口和共享写接口，保留新增表、快照和附件，不执行破坏性降级迁移。旧后端必须忽略新增来源展示字段；已经复制的策略继续按个人策略运行。只有确认数据错误且无法前向修复时，才另行设计有审批和备份的数据回退，不直接删除共享资产。

## 18. 风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 完整结果和研究信号导致存储增长 | 内容摘要校验、附件大小限制、存储监控；只在用户主动上架和复制时创建，不批量回填 |
| 直接复用原任务导致删除后失效 | 独立共享快照和共享附件；原外键使用 `SET NULL` |
| 放宽 RLS 泄露个人资源 | 新增独立共享表与 DTO，保持原表策略不变，增加跨用户负向测试 |
| 作者代码中包含敏感文字 | 上架确认和明确提醒；系统字段白名单；日志不记录正文 |
| 不同条件下收益被错误比较 | 强制展示区间、成本、成交模型和数据范围，不提供收益排行榜 |
| 重复点击或并发导致副本和计数失真 | 唯一复制约束、事务性计数和幂等返回 |
| 原作者撤回导致接收者依赖失效 | 复制时导入接收者独立依赖，不保留临时共享引用 |
| 研究信号导入跨服务失败 | 内容摘要、分阶段暂存、完整回滚和孤立文件清理 |
| 快照格式演进改变历史展示 | 显式模式版本和旧版本读取器，禁止按新默认值重算 |
| 无事前审核产生不当内容 | 仅内部登录用户可见，保留管理员带原因下架与恢复能力 |
