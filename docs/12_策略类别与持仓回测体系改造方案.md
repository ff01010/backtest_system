# 策略类别与持仓回测体系改造方案

## 1. 背景与问题

当前系统已经具备单标的基础 L2 盘口回测与底仓做 T 能力，但“持仓收益”页面同时承载了两种不同策略语义：

- 有固定底仓、通过日内卖出和买回增厚收益的策略；
- 在判断时点开多、开空或平仓后跨日持有的策略。

前者的日终仓位通常恢复为固定底仓，真正应评价的是相对底仓持有的增厚收益；后者的实际持仓、组合收益和基准超额，才是评价选股或方向判断的核心。继续使用同一个持仓规则和同一组指标，会造成结果解释错误。

本方案将回测按策略业务语义分为两类，并为后续多标的选股组合与融券做空建立兼容的账户和结果模型。

## 2. 改造目标与边界

### 2.1 目标

1. 用明确的策略类别取代通过底仓、日内规则隐式推断策略行为。
2. 让底仓增强策略以做 T 增厚收益为核心指标，不再将日终底仓误解为选股持仓。
3. 让方向性持仓策略以真实仓位、组合净值和基准超额为核心指标。
4. 保留统一订单、成交、现金和权益账本，避免重复建设撮合核心。
5. 历史回测保持可读、收益不被重算或改写。
6. 预留多标的组合、调仓、融券卖空和借券成本的扩展边界。

### 2.2 不在本期实现的内容

- 多标的股票池选股与组合调仓；
- 融券券源、保证金、借券费率和强平规则；
- 逐笔成交队列模拟；
- 历史回测结果的批量重算。

上述能力在本期分类、结果契约和持仓身份模型稳定后分期接入。

## 3. 策略类别定义

### 3.1 `core_position_overlay（底仓增强策略）`

定义：先持有固定底仓，再围绕该底仓进行日内交易以增厚收益。

固定规则：

- 必须使用基础 L2 十档盘口成交模式；
- 必须填写 `baseQuantity（底仓数量）` 与 `baseCostPrice（底仓成本价）`；
- `initialCapital（初始资金）` 始终为独立可用现金，不扣减底仓成本；
- 日初冻结按 `symbol（标的）+ positionKey（持仓归属键）` 划分的可卖数量；当天买入不成为当日可卖库存；
- `t0Enabled（启用底仓做T）` 限制同一交易日内可卖、买回的累计额度；
- 收盘目标仓位为配置的底仓数量；使用 `14:57` 前最后有效盘口完成恢复，缺边或深度不足时记录系统结算成交与告警。

收益口径：

- 总账户收益：以初始现金加底仓初始市值为起点；
- 底仓持有收益：假设现金不动、底仓自始至终持有到期末价格；
- 做 T 超额收益：实际期末权益减去底仓持有基准；
- 做 T 超额收益率：做 T 超额收益除以底仓初始市值；
- 同时展示手续费、换手、系统强制结算金额与次数。

页面名称：`底仓增强收益`。日终仓位、现金和权益用于核对结算，不用于评价选股能力。

### 3.2 `directional_holding（方向性持仓策略）`

定义：策略在某个判断时点开多、开空或平仓，并让仓位按策略规则跨日持有。

首期规则：

- 不设置底仓，不执行尾盘恢复；
- 允许单标的开多、平多；开空与平空由 `allowShort（允许做空）` 控制，但完整融券成本模型在后续期实现；
- 收盘保留真实实际仓位和未实现盈亏；
- 可使用现有 Bar 收盘成交模型，L2 基础盘口成交作为可选执行模型。

收益口径：

- 组合总收益、年化收益、回撤、夏普；
- 基准收益和超额收益；
- 实际持仓数量、成本、市值、浮动盈亏和持仓天数；
- 后续多标的阶段增加换手率、集中度、行业暴露、选股命中率等组合指标。

页面名称：`持仓收益`。该页面服务于方向判断、买入持有和未来选股组合的评价。

## 4. 统一数据契约

### 4.1 回测请求

新增必填字段 `strategyCategory（策略类别）`：

```text
core_position_overlay | directional_holding
```

校验规则：

| 策略类别 | 底仓 | 持仓规则 | 成交模式 |
| --- | --- | --- | --- |
| `core_position_overlay` | 数量与成本必须有效 | 固定为日终恢复底仓 | 仅 `l2_quote` |
| `directional_holding` | 必须为 0 | 固定为允许跨日 | `bar_close` 或 `l2_quote` |

前端不再让用户在这两类策略之间手动组合互相冲突的参数。类别切换时，应重置不适用参数并显示其影响说明。

### 4.2 脚本账户上下文

公共字段保持不变：`cash（现金）`、`equity（权益）`、`position（当前净持仓）`、`strategyPosition（当前脚本净持仓）`。

仅底仓增强策略提供：

- `basePosition（初始底仓数量）`；
- `sellableQuantity（当日可卖数量）`；
- `t0AvailableQuantity（当日做T剩余额度）`。

方向性持仓策略中以上三个字段为 `null` 或 `0`，不得用于策略判断。后续融券模型稳定后，再新增保证金、可融券数量、借券费率字段。

### 4.3 账户与持仓身份

账本内部持仓的唯一身份统一为：

```text
symbol（标的） + positionKey（持仓归属键） + side（多空方向）
```

现有公开 `longPositionsByKey（按键多头持仓）`、`shortPositionsByKey（按键空头持仓）` 在单标的条件下可继续兼容；多标的实现前必须新增按完整持仓身份返回的明细结构，禁止仅以 `positionKey（持仓归属键）` 作为跨标的唯一键。

### 4.4 回测结果

保持 `summary（通用汇总）` 用于历史兼容，新增以下结构：

```text
strategyCategory
strategyMetrics
  ├─ t0Metrics
  └─ holdingMetrics
resultSchemaVersion
```

`t0Metrics（底仓增强指标）` 仅由底仓增强策略写入；`holdingMetrics（方向性持仓指标）` 仅由方向性持仓策略写入。前端只读取当前类别对应指标。

每条结果需保存：

- 策略类别、参数快照、脚本快照；
- 数据映射与版本快照；
- 结果结构版本；
- 每日权益和持仓快照；
- 系统结算、拒单、撤单和部分成交明细。

## 5. 前端交互与页面改造

### 5.1 参数面板

1. 在基础设置中首先选择策略类别。
2. 选择底仓增强策略后，只显示底仓、成本价、做 T 额度说明和 L2 成交模式。
3. 选择方向性持仓策略后，显示方向权限、持仓/调仓规则和成交模式；不显示底仓参数。
4. 参数校验在前端即时提示，后端使用同一规则二次校验。

### 5.2 概览页

底仓增强策略核心卡片：

- 做 T 超额收益；
- 做 T 超额收益率；
- 底仓持有收益率；
- 手续费与换手；
- 最大回撤；
- 系统结算告警。

方向性持仓策略核心卡片：

- 总收益率；
- 基准收益率；
- 超额收益率；
- 最大回撤；
- 夏普；
- 当前持仓数或单标的净持仓。

### 5.3 结果页与历史页

- 底仓增强策略将当前“持仓收益”入口改名为“底仓增强收益”；展示日终权益、底仓恢复、现金、费用和增厚收益。
- 方向性持仓策略保留“持仓收益”；展示真实持仓、成本、市值、浮动盈亏、持仓天数与每日净值。
- 历史列表、详情和对比视图显示策略类别；不同类别不得直接在同一指标表中比较做 T 超额和组合超额。

## 6. 兼容与迁移方案

### 6.1 历史记录

不修改数据库中已有 `requestedParams（请求参数）`、`resultJson（结果）` 或收益数值。

读取时适配：

- 旧记录若含有效 `baseQuantity（底仓数量）` 或 `t0Enabled（启用底仓做T）`，展示为“旧版底仓增强语义”；
- 其余旧记录保留原始 `holdingPolicy（持仓规则）` 展示为“旧版方向持仓语义”；
- 缺少 `resultSchemaVersion（结果结构版本）` 时使用旧适配器，不反向写库。

### 6.2 新记录

- 新提交请求必须明确 `strategyCategory（策略类别）`；
- 新结果写入 `resultSchemaVersion（结果结构版本）= 2`；
- 新历史详情使用类别和版本路由至对应结果适配器。

## 7. 分期实施

### 第一期：类别和页面语义

范围：

1. 新增策略类别字段、前后端校验、请求与历史快照；
2. 底仓增强策略固定参数规则和结果指标归类；
3. 方向性持仓策略固定跨日规则；
4. 概览、结果页、历史详情与对比页按类别显示；
5. 历史兼容适配与文档更新；
6. 账户内部持仓身份为多标的扩展做结构准备，但不实现多标的回放。

验收：

- 底仓增强策略只能使用 L2、必须有底仓、收盘恢复底仓；
- 方向性持仓策略不能填写底仓，跨日保留真实仓位；
- 两类策略不再共用“持仓收益”的评价语义；
- 旧 L2 和旧 Bar 回测均能查看，不改变保存结果；
- 单元测试覆盖参数冲突、历史回退、页面指标切换和 T+1 规则。

### 第二期：单标的方向性持仓完善

范围：

- 多空开平仓生命周期；
- 跨日市值、未实现盈亏和持仓明细；
- L2 与 Bar 两种成交模型下的一致结果结构；
- 为融券模型新增明确的“不支持”提示，避免将裸卖空当作真实融券回测。

### 第三期：多标的选股组合

范围：

- 股票池、因子过滤、选股排序与目标权重；
- 调仓日历、组合订单生成、多标的事件调度；
- `universeSnapshot（股票池快照）`、`selectionSnapshot（选股结果快照）`、`targetWeights（目标权重）`；
- 组合净值、基准、超额、换手、集中度与归因。

### 第四期：融券做空

范围：

- `borrowAvailability（可融券数量）`、`borrowRate（融券费率）`、`marginRequirement（保证金要求）`；
- 券源不足、借券成本、保证金不足、强平、停牌和涨跌停回补失败；
- 真实融券口径下的多空组合指标。

## 8. 风险与约束

1. 当前 L2 引擎是单标的订单驱动回放；在第三期前不得宣称支持组合级 L2 撮合。
2. 未引入券源与保证金前，`allowShort（允许做空）` 仅代表模拟开空权限，不能标识为真实融券回测。
3. 底仓恢复中的系统结算是回测假设，必须在明细和结果告警中保留来源标识。
4. 结果类别和版本必须存入历史快照；仅由当前页面参数推断会使旧回测不可追溯。
5. 多标的扩展前必须先消除按 `positionKey（持仓归属键）` 跨标的覆盖的风险。

## 9. 测试与交付

每一期至少包含：

- 后端 schema 与请求校验测试；
- 账本、撮合与结果适配单元测试；
- 历史旧结果兼容测试；
- 前端 TypeScript 类型检查；
- 前端页面条件渲染测试；
- 实际本地回测冒烟验证（仅在数据与服务均可用时执行）。

任何未执行的实盘、融券或组合级 L2 回放，不得标记为已验证。
