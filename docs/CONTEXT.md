# 标准 Bar 日线派生与方向性持仓 — 上下文与决策记录

本文件记录方案 32 的共同术语、已确认边界和待决架构决定。审验问题见 [QUESTIONS.md](QUESTIONS.md)。

## 范围

为标准 QMT Bar 自定义策略提供由完整分钟数据派生 `1d` Bar、状态预热和方向性持仓的历史回测运行能力。它不提供具体交易策略、预测研究能力或真实融券能力。

## 术语表

| 术语 | 定义 |
| --- | --- |
| 正式区间 | 用户选择并计入回测成交、费用、持仓和收益的日期范围。 |
| 预热区间 | 正式区间之前、仅用于运行 `on_bar` 初始化策略状态的完整交易日范围。 |
| 来源解析 | 针对某周期和完整目标范围，选择原始周期或派生周期，并返回可用性与缺失原因的统一过程。 |
| 原始日线 | QMT 以 `1d` 周期导入并被完整度记录判定为完整的 K 线。 |
| 分钟派生日线 | 只对完整 `1m` 交易日按上海交易日聚合得到的 `1d` Bar。 |
| 完整度 | 导入链路写入的 `qmt_kline_coverage` 完整状态，不由运行时按数据行数推断。 |
| 日线回调 | 一根完整日线完成后向用户策略调用 `on_bar(bar, state)` 的事件。 |
| 预热隔离 | 预热期只允许策略 `state` 改变，不允许订单、成交、资金、持仓、净值或结果事件产生。 |
| 来源快照 | 与任务结果一起保存的数据提供方、来源周期、派生版本、覆盖范围与哈希，用于解释和复现结果。 |

## 已知实现事实

- 标准 QMT 数据链路当前直接支持 `1m`、`5m`、`60m`、`1d`，仅对 `15m`、`30m` 做分钟聚合；现有分钟聚合器会按午前/午后时段分桶，不能直接用于 `1d`。
- 现有读取调度存在映射 Bar 数据源优先于 QMT 数据源的分支；方案中的 QMT 来源优先级必须明确该分支是否属于本期。
- 现有非 L2 日期可用性预检与实际 QMT 加载路径尚未完全共用来源判定，属于本次审验的 P0 收敛项。
- 交易日历表不应成为寻找预热日的唯一前置条件；回测数据完整性应以数据来源自身的覆盖记录为准。
