# 多用户策略平台与自包含运行时改造计划

## 1. 目标

将当前单用户、外部策略代码挂载的回测系统改造成可部署的多用户平台：

- 未登录访问统一重定向到登录页；不提供公开注册。
- 初始管理员为 `admin / 123456`，密码不强制首次修改。
- 管理员可创建、编辑、停用用户和重置密码。
- 普通用户只能查看和操作自己的策略、方案、版本、回测记录与会话。
- 策略、方案和版本保存在 PostgreSQL；普通用户必须发布策略版本后才能回测。
- 管理员允许对未发布草稿试跑，试跑记录必须保存完整脚本快照并标记为草稿试跑。
- 分钟行情缓存由所有用户共享：首次回测按需从东财拉取，后续回测直接复用 PostgreSQL 缓存。
- 删除 `/srv/quant-backtest/code`、`shared/` 和外部趋势网格代码的运行依赖。

## 2. 已确认决策

| 项目 | 决策 |
| --- | --- |
| 登录与注册 | 实现真实登录；仅管理员创建用户，不开放注册。 |
| 初始账号 | 种子管理员 `admin / 123456`；不要求首次改密。 |
| 人员管理 | 创建用户、编辑姓名/角色、停用/启用、重置密码。 |
| 策略所有权 | 用户可创建、编辑、运行自己的策略；严格按用户隔离。 |
| 发布规则 | 普通用户只可运行已发布版本；管理员可试跑未发布草稿。 |
| 初始策略 | 数据库为管理员初始化一个可运行示例策略；不保留外部内置策略包。 |
| 脚本能力 | 允许脚本导入工作容器内的全部预装模块。 |
| 脚本隔离 | 脚本在独立受限容器执行，无数据库凭据、无宿主机挂载、默认无网络。 |
| 行情缓存 | `1m/5m` 东财分钟数据全局共享；日志记录实际发起用户。 |
| 历史兼容 | 可不兼容现有测试策略、方案和回测记录。 |
| 文档读者 | 开发与部署人员。 |

## 3. 当前问题

当前后端通过 `TREND_GRID_CODE_ROOT` 从外部目录导入 `shared.calendar`、趋势网格引擎和中盘策略代码；这使容器无法在没有外部私有代码目录时启动。现有 API 又把默认用户 ID 写死，虽已有部分 RLS 表，却没有登录态和请求级用户上下文。

现有自定义脚本直接由后端进程执行。允许全部导入时，普通用户可以读取数据库环境变量、操作文件系统或访问网络，不能满足多用户隔离要求。

## 4. 目标架构

```text
浏览器
  │ HTTPS / 同源 Cookie
  ▼
Nginx ──► FastAPI API ──► PostgreSQL
              │              ├─ 用户、策略、版本、回测记录（按用户隔离）
              │              └─ 东财分钟数据缓存（全局共享）
              ▼
        strategy-worker（受限执行容器）
              ├─ 非 root、只读根文件系统
              ├─ 无数据库凭据、无宿主机挂载、默认无网络
              └─ 执行数据库脚本快照并返回回测订单/结果
```

### 4.1 认证与会话

- 使用 PostgreSQL `app_user` 与 `auth_session`，不引入公开注册。
- 新增密码哈希与校验服务，使用标准库 PBKDF2-SHA256、随机盐和固定迭代次数；不新增 Python 依赖。
- 登录成功后发放随机会话令牌；数据库仅保存令牌哈希、过期时间、用户状态和必要元数据。
- 使用 `HttpOnly`、`SameSite=Lax`、生产环境 `Secure` 的同源 Cookie。
- 新增当前用户依赖项；每个请求的数据库连接设置 `app.current_user_id` 与 `app.current_is_admin`，使 RLS 真正生效。
- 停用用户后立即拒绝其后续会话；管理员重置密码后撤销该用户现有会话。

### 4.2 人员管理

仅管理员可访问人员管理页面和 API：

- 新建用户：用户名、显示名称、角色、初始密码、启用状态。
- 编辑用户：显示名称、角色、启用状态。
- 重置密码：生成新 PBKDF2 哈希并撤销旧会话。
- 不允许删除用户，保留策略与回测审计轨迹。
- 禁止管理员停用或降权最后一个活跃管理员。

### 4.3 策略、方案与版本

- 保留数据库中的 `user_strategy`、`user_strategy_version`、`strategy_config`、`strategy_config_version`。
- 初始化时仅为管理员插入一个可运行示例策略及其发布版本；示例策略是普通数据库脚本，不是镜像外的内置 Python 包。
- 用户保存策略得到草稿；发布后生成不可变版本快照。
- 普通用户回测必须引用已发布方案版本。
- 管理员草稿试跑不生成正式版本，但回测记录保存脚本、参数和数据快照，并标记 `draft_test`。
- 策略页面仅展示当前用户资产；管理员可额外查看其策略库中的示例策略。

### 4.4 受限脚本执行器

- 新增 `strategy-worker` 服务，作为独立 Docker 镜像运行。
- API 将脚本快照、参数、标准化 K 线和账户约束发送给 worker；worker 不连接 PostgreSQL。
- worker 以非 root 用户运行，移除 Linux capabilities，设置只读文件系统、内存/CPU/PID 限制，禁用网络，且不挂载 Docker socket、项目目录、策略目录或数据目录。
- 脚本可导入 worker 镜像中已有的 Python 标准库与预装模块；不允许运行时安装软件包。
- worker 的唯一输出是经过结构校验的订单意图、警告和策略状态；后端仍负责撮合、成本、数据读取与回测记录。
- 若 worker 超时、异常退出或返回非法订单，回测失败并记录错误，不影响 API 容器。

### 4.5 市场数据

- 继续使用已新增的 `market_minute_bar` 与 `market_minute_coverage`。
- 回测时按需补齐目标标的和基准标的的 `1m/5m` 数据；缓存由全体用户共享。
- `market_fetch_log.requested_by_user_id` 记录触发下载的用户。
- 当前东财适配器继续作为临时数据源；未来只替换数据源适配器，不改策略、认证和缓存读取层。

## 5. 数据库迁移

新增版本化迁移，均要求可重复执行：

1. `004_auth_and_user_isolation.sql`
   - 清理旧本机默认账户语义，初始化 `admin` 用户与 PBKDF2 密码哈希。
   - 补充认证会话字段、会话索引、用户启用/管理员保护约束。
   - 对策略、方案、回测与会话表补齐/校验 RLS 策略。

2. `005_strategy_runtime.sql`
   - 增加草稿试跑状态、脚本快照与执行器元数据。
   - 插入管理员拥有的示例策略、示例方案和首个发布版本。
   - 不迁移旧策略记录；旧测试数据可清理或忽略。

3. 迁移完成后，数据库中不需要任何外部策略路径或 `shared` 模块配置。

## 6. 后端改造

1. 删除外部趋势网格加载、`shared` 导入、`TREND_GRID_CODE_ROOT` 依赖和旧内置策略适配器。
2. 将策略目录 API 改为数据库策略 API；无登录时不暴露策略、账户、回测或数据管理接口。
3. 实现登录、登出、当前用户、管理员人员管理 API。
4. 将所有 `state_store` 查询从固定默认用户改为请求认证上下文。
5. 将脚本校验和执行拆分：API 做输入/输出结构验证，worker 执行脚本。
6. 修改回测入口：普通用户仅接收已发布版本；管理员可显式 `draft_test`。
7. 保留市场数据缓存服务，拉取日志以当前登录用户写入。
8. 所有异常响应不得泄漏脚本源码、密码哈希、数据库 URL 或 worker 内部路径。

## 7. 前端改造

1. 新增登录页；未认证访问应用时跳转登录页。
2. 新增顶部用户菜单和退出登录。
3. 管理员新增“人员管理”入口；普通用户不可见且 API 受后端保护。
4. 策略工作台以空状态开始：新用户没有策略时引导创建脚本、保存方案、发布版本。
5. 管理员策略库显示示例策略；允许复制为自己的策略方案。
6. 将“管理员草稿试跑”和“正式版本回测”明确区分并展示记录标签。
7. 保留行情覆盖和东财缓存状态提示，不在页面初始化时批量拉取行情。

## 8. Docker 与部署改造

1. 删除 backend 的 `TREND_GRID_CODE_ROOT`、`TREND_GRID_HOST_CODE_ROOT` 和 `/code` 挂载。
2. 保留 PostgreSQL、backend、frontend；新增内部 `strategy-worker` 服务，不暴露宿主机端口。
3. worker 使用资源限制、只读文件系统、非 root 用户、无网络和无敏感环境变量。
4. `deploy/.env.example` 删除代码目录变量；保留数据库、HTTP 端口和可选信号目录配置。
5. 重写 README 的部署步骤：数据库迁移、worker 启动、初始管理员登录、人员创建、示例策略验证和分钟缓存验证。

## 9. 验收标准

### 认证与权限

- 未登录访问业务页面和 API 被拒绝或跳转登录页。
- `admin / 123456` 能登录；停用用户不能登录；重置密码后旧会话失效。
- 普通用户不能查看或调用其他用户的策略、方案、回测或会话。
- 普通用户不能调用人员管理 API。

### 策略

- 新用户初始没有策略。
- 管理员可看到示例策略；示例策略源码存在数据库而非宿主机目录。
- 普通用户保存草稿后可在数据库中查询到归属自己的脚本。
- 普通用户未发布时不能回测；发布后可以回测。
- 管理员草稿试跑成功，回测记录包含草稿标记和不可变脚本快照。
- 恶意或异常脚本只能影响 worker 自身，不能读取数据库凭据、访问宿主机或使 API 服务失效。

### 数据与部署

- 空的 `/srv/quant-backtest/code` 不再阻止后端启动；该目录将不再需要。
- 首次 `1m/5m` 回测从东财获取并写入 PostgreSQL。
- 相同请求第二次命中缓存，不产生重复上游请求。
- 服务器运行迁移、重建容器后，登录、策略保存和回测全流程可用。

## 10. 实施顺序

1. 建立认证上下文、用户迁移与人员管理 API。
2. 新增登录页与人员管理页面，完成权限测试。
3. 将策略存取和回测授权切换为当前用户。
4. 实现 `strategy-worker` 协议、镜像与隔离配置，迁移脚本执行。
5. 删除外部 `shared`/策略目录依赖，写入数据库示例策略。
6. 更新 Compose、环境模板和 README。
7. 运行单元、接口、权限、容器和真实东财缓存验收。
8. 在服务器依序迁移数据库、重建服务、验证管理员登录和首次/二次回测。

## 11. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 默认管理员密码弱 | 仅首次部署使用；README 明确要求上线后尽快重置。 |
| 用户脚本任意导入 | 独立 worker、无网络、无密钥、无挂载、资源限制、超时与结构校验。 |
| 东财数据不稳定 | 覆盖状态、失败重试、请求日志和未来适配器替换边界。 |
| 多用户数据泄漏 | API 身份依赖、数据库 RLS、服务端所有权校验及权限测试。 |
| 旧数据不兼容 | 明确允许不兼容；迁移只保证新架构可运行。 |

## 12. 自审

本计划已覆盖所有已确认需求：真实登录、管理员创建用户、无公开注册、用户数据隔离、草稿/发布规则、管理员草稿试跑、共享分钟缓存、数据库示例策略、移除 `shared` 外部依赖、任意预装模块导入以及开发部署文档更新。

唯一不能在本地单元测试完全证明的部分是 Docker worker 的实际隔离和东财真实网络响应；两者均列入容器验收与服务器验收，不会以单元测试通过替代。
