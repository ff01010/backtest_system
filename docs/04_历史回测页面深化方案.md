# 历史回测页面深化方案

## 1. 目标

将“历史回测”从记录列表升级为可检索、可比较、可复现的实验档案。用户应能快速找到某次回测、判断其表现，并确认比较双方使用的策略、参数和数据快照。

页面面向纯回测研究，不扩展模拟盘、实盘任务或后台调度能力。

## 2. 当前问题

- 列表已包含策略、标的、区间、收益和完成时间，但重要信息在宽表中密度较高。
- 选中记录、结果概览与参数差异之间的层级还可以更清晰。
- 回测快照的可复现价值存在，但策略版本、数据指纹和成本模型需要更聚焦地呈现。
- 用户在搜索、筛选、比较和复制配置之间缺少明确的操作路径。

## 3. 设计方案

### 3.1 页面结构

页面按“查找实验—阅读快照—比较差异—复用配置”组织：

1. **实验索引区**：搜索策略、标的、实验编号或标签；标的筛选和刷新操作与搜索置于同一区域。
2. **历史实验账本**：显示实验编号、策略版本、标的/基准、日期区间、核心表现、完成时间和标签；选中行以清晰但克制的状态突出。
3. **选中实验摘要**：展示收益、回撤、Sharpe、交易次数及策略、行情、成本模型的快照标识。
4. **实验对比区**：选择两条记录后显示核心指标差异和参数差异；强调差异来源而非仅展示数值。
5. **复用操作**：保留“复制”现有语义，用于把历史配置带回当前回测设置，不自动运行回测。

### 3.2 状态与视觉规则

| 内容 | 展示规则 |
| --- | --- |
| 当前选中实验 | 青绿色左侧标识与浅色背景 |
| 正收益 | 红色数值 |
| 负收益 | 绿色数值 |
| 数据或参数缺失的旧记录 | 琥珀色提示，说明其快照字段缺失 |
| 对比差异 | 提升项、下降项和仅一侧存在的配置分别标识 |
| 策略/数据指纹 | 使用短指纹和等宽字体，完整内容通过详情查看 |

颜色仅用于含义表达，不以收益颜色推断策略优劣；比较必须以相同或明确展示的回测条件为前提。

### 3.3 交互与响应式规则

- 搜索与筛选即时作用于本地已加载的历史记录，不改变或删除历史数据。
- 点击记录只切换详情与对比目标；“复制”才应用历史配置，且仍需由用户主动运行回测。
- 对比区应先提示两条记录的标的、周期和区间是否一致，再呈现收益与参数差异。
- 窄屏下实验账本保留关键列并允许横向滚动，详情和对比区依次纵向排列。

## 4. 实现边界

本阶段基于现有 `backtestRuns`、实验清单和参数快照，调整 `frontend/src/components/BacktestPage.tsx` 与 `frontend/src/styles/global.css` 的历史回测页面表现。

不修改：

- 历史回测的创建、保存、删除和数据持久化策略；
- 回测引擎、策略代码快照、行情数据指纹或成本模型计算；
- 后端 API、数据库表和权限模型；
- 自动调度、模拟盘或实盘功能。

## 5. 验收标准

- 用户能检索并选中任意历史实验，快速看到其核心表现和可复现信息。
- 两条历史记录的结果与参数差异可读，且前提条件清楚。
- “复制”操作仍不自动运行回测，历史记录不会因查看或对比而被修改。
- 旧记录的字段缺失有明确提示，不伪造不存在的快照数据。
- 前端测试、TypeScript 构建和差异检查通过。
