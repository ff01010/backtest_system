# 全局搜索查询与历史回测性能优化计划

日期：2026-10-17
状态：待实施；生产只读诊断与代码审查已完成

## 1. 背景与问题结论

当前搜索故障不是单一索引缺失，而是搜索输入、数据库访问路径、分页、附加统计和前端请求控制共同形成的系统性问题。

生产只读诊断确认：

- `backtest_run` 约 49 万条，单用户最多约 25.6 万条。
- `strategy_config` 约 47.9 万条，单用户最多约 25.4 万条。
- 历史回测完整模糊统计 SQL 在最大用户数据上单次约耗时 15.8 秒；历史分页接口还会继续执行第二次统计、详情页查询和全量标的去重，最终可能超过代理等待时间并返回 504。
- 策略方案名称“不命中”统计需要检查约 25.3 万条当前用户记录，生产只读执行计划显示主扫描约 0.46 秒；它尚未产生同等级超时，但已构成明显并发风险。
- 证券名称、策略广场和实验列表也存在前后模糊匹配，但当前数据规模较小，属于需要在增长前治理的潜在风险。

历史回测当前将以下字段放在一个 `%关键字%` OR 条件中：

- UUID 转文本；
- 展示编号转文本；
- 标的；
- 策略标识；
- 当前策略方案名称；
- 标签 JSON 转文本。

即使输入 `#100405`，SQL 仍保留其他模糊 OR 分支，因此已有的 `(owner_user_id, display_no)` 唯一索引不能形成稳定的精确访问路径。接口随后重复执行两次几乎相同的统计，并在每次搜索时重新扫描用户全部历史以生成标的筛选列表。

本计划以“可索引的搜索契约”为核心，同时治理查询结构、分页、附加数据、前端并发请求、错误语义和其他同类搜索入口。删除历史数据、提高 Nginx 超时或只增加单个索引不属于根治方案。

## 2. 目标与验收结果

实施完成后应满足：

1. 回测编号、完整 UUID 和完整证券代码走确定的精确索引路径。
2. 普通文字搜索使用专用 trigram 搜索投影，不再逐行转换 UUID、数字、JSON 或 JOIN 后模糊匹配。
3. 历史回测的列表、全选摘要、批量删除和信号明细导出使用同一个搜索定义，用户可见范围与最终处理范围完全一致。
4. 历史列表每次请求最多执行一次聚合统计和一次当前页详情查询；标的筛选选项不随每次搜索重复计算。
5. 历史列表使用游标翻页，深页不再通过 `OFFSET` 丢弃前面数十万行。
6. 搜索对比回测使用轻量候选接口，不再调用完整历史分页接口。
7. 策略方案、证券、策略广场和实验列表的非空文字搜索均具备可索引访问路径。
8. 旧请求契约在兼容期内仍可工作，迁移和代码可以独立回退，不重写历史结果。
9. 代理层 HTML 不再直接展示给用户；搜索超时返回稳定的结构化错误和可理解提示。
10. 生产规模下精确搜索 API P95 小于 300ms，普通文字搜索 API P95 小于 1 秒，冷缓存单请求不超过 2 秒。

## 5. 统一搜索契约

### 5.1 输入分类

新增纯函数搜索解析模块，建议文件：

```text
backend/services/search_query.py
```

模块输出 SQL 无关的不可变搜索描述，不直接拼接 SQL。历史回测输入按以下固定顺序分类：

| 输入 | 解释 | 查询方式 |
| --- | --- | --- |
| 空字符串 | 不启用文字搜索 | 仅使用用户、收藏、方案和标的筛选 |
| `#` + 数字 | 展示编号 | `display_no` 精确相等 |
| 完整 UUID | 运行 ID | UUID 主键精确相等，并继续校验所有者 |
| 六位数字加可选交易所 | 可能是展示编号或证券代码 | 两个精确候选分支 `UNION`，不使用模糊 OR |
| 其他纯数字 | 展示编号 | `display_no` 精确相等 |
| 其他文字，长度至少 2 | 普通文字 | 搜索投影 `ILIKE`，由 trigram GIN 支持 |
| 单个普通字符 | 信息不足 | 前端不发请求；后端返回空搜索或 422，不退化为全表扫描 |

普通文字中的 `%`、`_` 和 `\` 按字面量转义。搜索模式、归一化文本和过滤条件进入游标绑定，改变任一条件后旧游标必须失效。

### 5.2 历史快照语义

历史搜索使用任务运行时保存的快照：

- 标的：`requested_params->>'symbol'`；
- 策略：`requested_params->>'strategy'`；
- 方案名称：`params_snapshot->>'name'`；
- 标签：`tags`；
- 编号和 UUID：`display_no`、`id`。

不再依赖当前 `strategy_config.name` 参与历史搜索。用户后来重命名或归档方案，不应改变过去任务的搜索身份。旧记录缺失某个快照字段时按空字符串处理，不推测或覆盖历史内容。

### 5.3 过滤复用边界

新增统一的 `BacktestRunSearchSpec`，以下路径只能消费同一个解析结果和同一个数据库过滤构造器：

- 历史分页；
- 历史可选择数量；
- 全选摘要和摘要摘要值；
- 按过滤范围批量删除；
- 按过滤范围创建信号明细导出。

不得分别维护列表 SQL 和批量操作 SQL。单元测试必须证明同一条件在所有入口生成相同候选 ID 集合。

## 6. 数据库设计与迁移

实施前重新确认 `db/migrations/` 最大编号。按当前仓库状态预计新增两个幂等迁移：

```text
db/migrations/058_search_projection_foundation.sql
db/migrations/059_search_projection_backfill.sql
```

拆成两个事务的目的是降低单次失败的回滚范围，并把结构建立与大数据回填、建索引分开。两个迁移仍由 `migrate` 服务执行，不在应用启动时执行 DDL。

### 6.1 迁移 058：结构与新写入保护

迁移内容：

1. `CREATE EXTENSION IF NOT EXISTS pg_trgm`。生产当前未启用该扩展。
2. 为 `backtest_run` 增加可空 `search_text_v1 text`。
3. 新建稳定的数据库函数，根据运行快照生成规范化搜索文本。
4. 新建 `BEFORE INSERT OR UPDATE OF requested_params, params_snapshot, tags, display_no` 触发器，保证新写入和标签修改自动维护投影。
5. 为 `backtest_publication` 增加 `search_text_v1` 及维护触发器，字段覆盖标题、作者快照、标的和标签。
6. 不在本阶段设置 `NOT NULL`，保证新增列的结构锁时间最短。
7. 增加历史列表的 B-Tree 组合索引；只新增与确定查询路径对应的索引。

预计索引：

```sql
CREATE INDEX IF NOT EXISTS ix_backtest_run_owner_created_page
  ON backtest_run (owner_user_id, created_at DESC, id DESC);

CREATE INDEX IF NOT EXISTS ix_backtest_run_owner_status
  ON backtest_run (owner_user_id, status);

CREATE INDEX IF NOT EXISTS ix_backtest_run_owner_instrument_created
  ON backtest_run (owner_user_id, instrument_id, created_at DESC, id DESC);

CREATE INDEX IF NOT EXISTS ix_backtest_run_owner_config_created
  ON backtest_run (owner_user_id, config_id, created_at DESC, id DESC)
  WHERE config_id IS NOT NULL;
```

现有 `(owner_user_id, display_no)` 和收藏部分索引继续复用，不重复创建。

### 6.2 迁移 059：回填与搜索索引

迁移内容：

1. 只回填 `search_text_v1 IS NULL` 的历史记录，重复执行不会重写已完成行。
2. 回填结果不得修改 `updated_at`、任务状态、结果、标签或运行快照。
3. 回填完成后校验空值数量为 0，再设置 `search_text_v1 NOT NULL`。
4. 建立历史回测搜索投影 GIN 索引。
5. 回填并索引策略广场搜索投影。
6. 为策略方案名称、证券名称和实验搜索字段建立 trigram 索引。

预计索引：

```sql
CREATE INDEX IF NOT EXISTS ix_backtest_run_search_text_v1_trgm
  ON backtest_run USING gin (search_text_v1 gin_trgm_ops);

CREATE INDEX IF NOT EXISTS ix_strategy_config_name_trgm
  ON strategy_config USING gin (lower(name) gin_trgm_ops);

CREATE INDEX IF NOT EXISTS ix_market_instrument_name_trgm
  ON market_instrument USING gin (lower(display_name) gin_trgm_ops)
  WHERE is_active=true;

CREATE INDEX IF NOT EXISTS ix_backtest_publication_search_text_v1_trgm
  ON backtest_publication USING gin (search_text_v1 gin_trgm_ops)
  WHERE status='active';
```

实验搜索不复制整个 revision JSON。为三个实际搜索表达式分别增加 trigram 索引，并在查询中以候选分支 `UNION` 合并：

- `lower(backtest_experiment.name)`；
- 当前 revision 中保存的策略名称；
- 当前 revision 中保存的标的。

实施时必须先在真实 PostgreSQL 上验证表达式与索引定义完全一致；执行计划不能使用索引时不得仅以“已经建索引”为完成标准。

### 6.3 迁移演练与锁风险

生产已有约 49 万条历史回测和约 48 万条策略方案，普通 `CREATE INDEX` 会阻塞相关表写入。仓库迁移当前要求每个迁移包含 `BEGIN/COMMIT`，因此本期不擅自绕开迁移器使用非事务 `CREATE INDEX CONCURRENTLY`。

发布前必须：

1. 在最新生产结构的隔离副本演练 058 和 059，记录每一步耗时、锁等待、WAL 增长、索引体积和磁盘余量。
2. 设置迁移级 `lock_timeout`，无法及时获得结构锁时明确失败，不无限等待。
3. 检查 Bar/L2 排队和运行任务；迁移会影响 `backtest_run` 写入时，选择任务低谷或等待当前运行任务完成。
4. 备份数据库并保存迁移前行数、空值数和索引清单。
5. 演练结果超出可接受维护窗口时，停止实施并单独设计支持并发建索引的迁移器能力，不在生产临时手工建索引。

## 7. 历史回测后端改造

### 7.1 候选集查询

将当前 `_backtest_run_filter_clause` 拆为：

```text
parse_backtest_run_search(query)
  -> BacktestRunSearchSpec
  -> build_backtest_run_candidate_query(spec, filters)
```

候选查询只读取 `backtest_run`：

- 编号、UUID、标的使用精确 B-Tree 分支；
- 普通文字使用 `search_text_v1 ILIKE`；
- 多个精确含义通过 `UNION` 合并并去重；
- `owner_user_id`、收藏、`config_id`、`instrument_id` 和状态条件在候选阶段生效；
- 不 JOIN `strategy_config`、`market_instrument`、任务表或共享表。

对当前页 ID 完成排序和分页后，详情查询才 JOIN：

- 策略与代码身份；
- 标的和基准；
- Bar/L2 任务取消状态；
- 共享发布状态。

详情查询明确列出返回字段，不再使用 `SELECT r.*`，避免表新增列后无意扩大响应和 Python 序列化成本。

### 7.2 统计合并

把两次统计合并为一次：

```sql
SELECT
  count(*) AS total,
  count(*) FILTER (WHERE status=ANY(%s)) AS selectable_total
FROM backtest_run
WHERE <统一候选条件>;
```

第一页列表请求最多执行：

1. 一次统计；
2. 一次当前页 ID 和详情查询。

后续游标页由新前端发送 `includeTotals=false`，只执行当前页 ID 和详情查询，并保留第一页取得的总数。筛选条件、搜索词或收藏状态变化时重新请求第一页及统计。批量全选、删除和导出仍在执行前独立计算最新范围，不能复用页面缓存的旧总数。

`includeTotals` 默认为 `true`，保证旧前端仍能取得数字总数。`includeTotals=false` 时响应中的 `total` 和 `selectableTotal` 为 `null`；前端类型必须明确表达可空状态，不能用当前页长度代替总数。不得为同一请求再次执行相同模糊条件。

### 7.3 游标分页与兼容期

新前端使用不透明游标：

- 普通列表：`created_at + id`；
- 收藏列表：`favorited_at + id`；
- 游标绑定搜索模式、归一化查询、标的、方案和收藏条件；
- 条件不一致返回 422，不退化到错误页。

接口响应增加：

```json
{
  "runs": [],
  "total": 0,
  "selectableTotal": 0,
  "nextCursor": null,
  "limit": 20
}
```

为兼容发布时仍打开的旧浏览器窗口，`offset` 在本期保留为兼容参数，但新前端不再发送。兼容分支同样使用新的搜索投影和合并统计，只允许旧式深页性能退化；移除 `offset` 需要另行确认。

### 7.4 筛选选项接口

新增：

```text
GET /api/backtest/run-filter-options?configId=<optional>
```

职责仅为返回当前用户可用的标的筛选项。查询使用 `(owner_user_id, instrument_id)` 访问路径并 JOIN 小型证券目录，不读取任务结果。

接口支持 ETag 或短期内存缓存；缓存键必须包含用户和可选方案 ID。新建或删除任务后允许失效或重新读取。旧历史分页响应中的 `symbols` 在兼容期保留，新前端忽略；后续删除字段另开变更。

### 7.5 轻量对比候选接口

新增：

```text
GET /api/backtest/run-options?query=<query>&limit=20&cursor=<optional>
```

只返回：

- `id`；
- `displayNo`；
- `symbol`；
- 保存时的策略和方案名称；
- `createdAt`；
- 状态。

该接口不计算全量总数、不计算标的列表、不读取 `result_json`，只用于“搜索对比回测”等候选选择器。

### 7.6 查询超时与错误语义

对用户搜索事务设置本地 `statement_timeout`，初始上限 5 秒。该限制只是故障保护，不是性能验收标准。

捕获 PostgreSQL查询取消异常并转换为结构化错误：

```json
{
  "error": {
    "code": "search_timeout",
    "message": "搜索耗时过长，请缩小条件后重试"
  }
}
```

除已识别的查询超时外，数据库异常继续抛出，不能把权限、连接或 SQL 错误伪装成“没有结果”。

## 8. 其他搜索入口改造

### 8.1 策略方案

- 查询改为与索引一致的 `lower(name) LIKE lower(%s)`，并转义通配符。
- 非空查询使用 trigram GIN；空查询继续使用所有者和更新时间游标索引。
- 空查询总数在页面会话首次加载时获取一次；翻页通过 `includeTotals=false` 不重复统计。
- 非空搜索第一页返回匹配总数，“加载更多”通过 `includeTotals=false` 只读取下一页。该参数默认 `true` 以兼容旧调用方；省略统计时 `total` 为 `null`，新前端保留第一页总数。
- 列表摘要继续禁止返回代码和完整参数。

### 8.2 证券目录

- 保留六位代码和带交易所代码的精确分支。
- 名称和非完整代码搜索使用 `lower(display_name)` trigram 索引。
- 空输入只返回有限的默认候选，不扫描后排序全部证券。

### 8.3 策略广场

- 使用 `search_text_v1` 搜索标题、作者快照、标的和标签。
- 删除 `jsonb_array_elements_text(tags)` 的逐行搜索方式。
- 状态、策略类别、周期和收藏继续作为独立精确过滤条件。
- 保持当前人工提交搜索的交互，不改成每次按键立即请求。

### 8.4 实验列表

- 实验名称分支查询 `backtest_experiment`。
- 策略名称和标的分支查询当前 `backtest_experiment_revision` 的表达式索引。
- 使用候选实验 ID `UNION` 后再读取详情和阶段统计。
- 当前页统计子查询只对最终页项目执行，不对搜索前的全部实验执行。
- Trial 编号和关联回测展示编号继续使用现有精确数字搜索。

## 9. 前端改造

修改前必须遵守 `docs/agents/frontend-browser-runtime.md`。本期不使用依赖安全上下文的浏览器能力。

### 9.1 API 客户端

为只读请求增加可选 `AbortSignal`：

### 9.2 历史页面

- 普通文字至少输入两个字符后才搜索。
- 精确编号、UUID 和完整证券代码立即搜索。
- 普通文字使用约 300ms 防抖。
- 条件变化时取消上一请求、清空游标栈并回到第一页。
- 前后翻页使用页面维护的游标栈，不构造深层 `offset`。
- 标的筛选选项独立加载，不随文字、页码或收藏筛选变化反复读取。
- 对比选择器切换到轻量 `run-options` 接口。

### 9.3 其他搜索组件

- 策略方案和证券选择器在 effect 清理时取消旧请求。
- 实验和策略广场的手动搜索保留显式提交；翻页沿用同一查询快照。
- 组件卸载后不得继续更新加载或错误状态。

### 9.4 错误显示

通用错误解析器按状态码和 `Content-Type` 处理：

- 结构化 JSON：保留服务端错误码、消息和请求 ID。
- 502/503/504 或 HTML：显示稳定的中文代理错误，不回显 HTML 正文。
- 其他短纯文本：允许保留有限长度用于诊断。
- 当前操作区域必须展示错误；不能只写入另一个页面的通用错误状态。

建议用户提示：

```text
搜索服务暂时未能及时响应，请缩小条件或稍后重试。
```

## 12. 性能基准与验收阈值

准备合成数据：

- 至少一个用户 25 万条历史回测；
- 至少一个用户 25 万条策略方案；
- 标的、方案名、标签、状态和创建时间采用接近真实选择性的分布；
- 不复制生产用户源码、参数或标签。

分别测量冷缓存、预热缓存和 10 并发：

| 场景 | 数据库目标 | API 目标 |
| --- | --- | --- |
| 展示编号精确查询 | 小于 50ms | P95 小于 300ms |
| UUID 精确查询 | 小于 50ms | P95 小于 300ms |
| 证券精确查询 | 小于 100ms | P95 小于 500ms |
| 历史普通文字查询 | 预热小于 300ms | P95 小于 1 秒 |
| 策略方案普通文字查询 | 预热小于 300ms | P95 小于 1 秒 |
| 冷缓存普通文字查询 | — | 单请求小于 2 秒 |
| 10 并发有效搜索 | 无连接池堆积、无 5xx | 全部完成，无超时 |

通过标准同时包括：

- 非空查询实际使用预期索引；
- `Buffers` 和被过滤行数相较基线显著下降；
- 不出现因查询超时产生的代理 504；
- 查询性能不依赖删除历史数据或提高代理超时。

## 16. 回滚策略

1. 058、059 只增加扩展、列、触发器和索引，并回填派生搜索文本；不修改历史业务字段。
2. 后端保留旧 offset 参数和旧响应兼容字段，前端回滚后仍可使用新后端。
3. 新后端出现问题时可回滚代码继续使用旧 SQL；新增列和索引可以暂时保留，不影响旧代码。
4. 不提供自动删除搜索投影的逆向迁移，避免回滚期间持有长时间结构锁；确认稳定后再单独清理无效对象。
5. 搜索投影内容错误时，先禁用新搜索路径并前向修复生成函数，再幂等重建派生文本。
6. 只有迁移造成业务字段或约束异常且无法前向修复时，才停止写入并使用发布前数据库备份恢复。
7. 不通过删除历史记录、禁用权限隔离或提高代理超时进行“回滚”。

## 17. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |

| 方案重命名改变历史搜索 | 历史语义漂移 | 使用 `params_snapshot.name`，不 JOIN 当前方案名 |
| 列表和批量操作过滤不一致 | 删除或导出错误范围 | 统一 `BacktestRunSearchSpec` 和候选查询，集合一致性测试 |
| trigram 对极短文本选择性差 | 高 CPU 和大量匹配 | 普通文字最小两字符，精确输入单独分类 |
| 游标条件未绑定完整筛选 | 翻页重复或串页 | 游标签名包含全部过滤和搜索模式 |
| AbortController 只取消浏览器等待 | 同步数据库语句可能继续运行 | 快 SQL、输入防抖、数据库 `statement_timeout`；不把取消作为唯一保护 |
| 新旧浏览器契约不同 | 发布期间旧窗口失败 | offset 和兼容响应字段保留一个兼容期 |
| 结构化日志泄露搜索内容 | 用户策略信息泄露 | 只记录模式、长度、耗时、数量和请求 ID |
| 新增索引占用磁盘和写放大 | 数据库容量和写延迟上升 | 发布前测量体积；只保留执行计划实际使用的索引 |
