# 历史回测收藏功能方案

## 1. 背景与问题

历史回测列表已经支持分页、关键词搜索、标的筛选、备注和标签，但用户仍需记住记录编号或关键词。随着记录数量增加，表现较好或需要后续复盘的回测难以快速定位。

收藏状态必须跨分页、刷新和重新登录保留，因此不能仅保存在前端。历史列表采用服务端分页，收藏筛选也必须在数据库查询阶段完成，不能只过滤当前页。

## 2. 目标与边界

本次改造目标：

1. 用户可以收藏或取消收藏自己拥有的任意历史回测。
2. 历史列表可以只显示当前用户收藏的记录。
3. 收藏筛选可与关键词和标的筛选组合，并保持分页总数准确。
4. 收藏状态受现有回测所有者隔离保护，不允许跨用户读取或修改。

本次不包含：

1. 不新增收藏关系表。
2. 不提供批量收藏、收藏分类或收藏备注。
3. 不改变回测提交、任务调度、策略执行、撮合和结果结构。
4. 不复用策略广场的共享回测收藏关系；两者的数据归属和生命周期保持独立。
5. 收藏不作为删除保护，永久删除回测时收藏状态一并消失。

## 3. 数据设计

为 `backtest_run` 增加一个可空字段：

```sql
favorited_at timestamptz NULL
```

字段语义：

- `NULL`：未收藏。
- 非空：已收藏，字段值为最近一次从未收藏变为已收藏的时间。
- 重复设置为收藏时保留原收藏时间；取消后重新收藏时生成新的收藏时间。

新增部分索引：

```sql
CREATE INDEX IF NOT EXISTS ix_backtest_run_owner_favorited
  ON backtest_run (owner_user_id, favorited_at DESC, id DESC)
  WHERE favorited_at IS NOT NULL;
```

迁移文件使用下一个编号 `039_backtest_run_favorite.sql`，必须幂等。历史记录无需回填，默认均为未收藏。现有 `backtest_run` 行级隔离策略继续生效，不新增权限策略。

## 4. 后端设计

### 4.1 历史记录返回结构

历史列表和详情统一增加：

```text
isFavorited: boolean
favoritedAt: string | null
```

`isFavorited` 由 `favorited_at IS NOT NULL` 推导，不在数据库重复保存布尔字段。

### 4.2 收藏设置接口

新增幂等接口：

```http
PUT /api/backtest/runs/{run_id}/favorite
Content-Type: application/json

{
  "favorited": true
}
```

响应返回最终状态：

```json
{
  "runId": "回测 UUID",
  "isFavorited": true,
  "favoritedAt": "2026-09-16T10:30:00+08:00"
}
```

存储模块提供 `set_backtest_run_favorite(run_id, favorited)` Interface：

- 收藏时设置 `favorited_at=COALESCE(favorited_at, now())`。
- 取消收藏时设置 `favorited_at=NULL`。
- 更新条件同时包含回测 ID 和当前用户 ID。
- 记录不存在或不属于当前用户时统一返回 404，不暴露其他用户记录是否存在。

### 4.3 收藏筛选

历史分页接口增加可选查询参数：

```http
GET /api/backtest/runs?favoritesOnly=true
```

筛选规则：

- 默认值为 `false`，现有调用行为不变。
- 开启时在总数查询和分页查询中同时增加 `favorited_at IS NOT NULL`。
- 普通列表继续按 `created_at DESC, id DESC` 排序，收藏操作不会使当前行跳动。
- 只看收藏时按 `favorited_at DESC, id DESC` 排序，最近收藏的记录优先。

## 5. 前端设计

### 5.1 列表操作

在历史回测表格的编号前增加收藏图标列：

- 未收藏显示空心星标。
- 已收藏显示金色实心星标。
- 点击图标时阻止列表行点击和双击事件传播。
- 使用明确的无障碍名称，例如“收藏历史回测 #35”和“取消收藏历史回测 #35”。
- 单条记录提交期间禁用其收藏按钮，防止重复操作。

收藏成功后同步更新当前列表缓存和已加载的详情缓存；失败时保留原状态并显示错误信息。

### 5.2 只看收藏

在关键词和标的筛选区域增加“只看收藏”切换按钮：

- 切换时重置到第一页。
- 与关键词、标的筛选共同传给服务端。
- 在只看收藏状态下取消收藏后重新加载当前页。
- 如果取消收藏导致当前页超出有效页数，沿用现有分页校正逻辑返回上一有效页。

不增加独立页面或新的导航入口。

## 6. 实施步骤

1. 新增 `039_backtest_run_favorite.sql` 幂等迁移。
2. 扩展后端历史记录标准化、收藏写入和收藏分页筛选。
3. 增加收藏请求模型、收藏接口和分页查询参数。
4. 扩展前端类型、请求客户端和历史页面状态。
5. 增加收藏图标、“只看收藏”按钮及必要样式。
6. 更新《玄龄回测系统使用手册》的历史回测管理章节。
7. 运行与本次改动直接相关的最小测试集。

## 7. 最小验证范围

后端验证：

1. 收藏、重复收藏、取消和重复取消返回正确状态。
2. 非所有者不能修改收藏状态。
3. `favoritesOnly=true` 同时影响总数和分页查询，并使用收藏时间排序。
4. 默认历史查询排序和行为保持不变。

前端验证：

1. 收藏按钮展示正确状态并发送正确请求。
2. 点击收藏按钮不触发行选择。
3. “只看收藏”重置页码并向分页请求传递正确参数。
4. 收藏筛选状态下取消收藏会刷新列表。

仅运行：

- 收藏与历史分页相关的后端 pytest。
- `BacktestHistoryPagination.test.tsx` 相关 Vitest。
- 前端 TypeScript 类型检查。

不运行与本次改动无关的全量回测、Worker 或行情测试。

## 8. 发布与兼容性

迁移、后端和前端通过 `scripts/deploy-server.sh` 同批发布，执行顺序为迁移、后端、前端。新增字段为可空字段，旧历史记录和现有读取行为保持兼容。

本次不改变回测执行和结果语义，不需要重新计算历史结果。发布后验证历史列表默认查询、只看收藏、收藏和取消收藏，以及旧历史记录详情读取。

## 9. 验收标准

1. 用户收藏记录后刷新页面或重新登录，收藏状态仍然保留。
2. 用户可以取消收藏，重复操作不会反转为错误状态。
3. “只看收藏”能够跨全部历史记录筛选，而不是只过滤当前页。
4. 收藏筛选与关键词、标的筛选组合后总数和分页准确。
5. 普通列表收藏后不改变原有创建时间排序。
6. 用户不能读取或修改其他用户的收藏状态。
7. 永久删除回测后不存在独立收藏残留。
8. 策略广场的共享回测收藏行为不受影响。
