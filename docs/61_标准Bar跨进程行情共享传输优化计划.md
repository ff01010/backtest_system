# 标准 Bar 跨进程行情共享传输优化计划

- 日期：2026-10-17
- 状态：实施中（服务器继续保持 `legacy`）

## 1. 背景与结论

标准 Bar 用户脚本回测已经以 Runner 内的单任务 `spawn` 子进程作为执行隔离边界，但当前父进程在完成行情读取与 DataFrame 规范化后，会把每根 Bar 展开为 `list[dict]`。`spawn` 随后对完整载荷执行 pickle 序列化和跨进程复制，子进程再把全部字典转换为 `list[Bar]`。同一份行情在任务启动阶段以 DataFrame、字典列表、pickle 缓冲区和 Bar 对象列表等多种形式同时存在，增加请求构造时间、进程启动延迟和峰值内存。

本计划采用最小必要改造：保留 DataFrame、现有 Python 回测引擎和策略子进程，只将标准 Bar 用户脚本的行情数据面改为固定类型 NumPy 数组。小中型行情写入 `multiprocessing.shared_memory.SharedMemory`，超过共享内存安全额度的行情写入任务级只读 `.npy` 内存映射文件；`spawn` 只传递控制参数和行情引用。子进程挂载数组后，以 `rows[start:end].tolist()` 分块批量转换为原生 `list[Bar]`，随即关闭映射并清除传输引用，再使用现有引擎执行策略。

本计划不引入 Arrow、Rust、C++ 或 Numba，不改变用户策略代码、撮合规则、结果结构和前端页面，也不新增性能诊断指标。

## 2. 目标、范围与不变量

### 2.1 目标

1. 消除标准 Bar 用户脚本主链路中的全量 `list[dict]` 和完整 pickle 行情载荷；子进程长期只保留引擎原生 `list[Bar]`。
2. 保持父进程 DataFrame 的规范化、任务快照、后处理和基准计算职责不变；研究信号任务本轮继续走旧链路。
3. 在不扩大 `/dev/shm` 风险的前提下，小中型行情使用共享内存，大型行情自动使用只读 mmap。
4. 保持单任务策略子进程的凭据隔离、取消、超时、异常映射和结果回传机制不变。
5. 通过旧链路开关、新旧结果对照和可恢复发布实现用户无感切换。

### 2.2 本轮范围

- 不含 `_researchSignalByBarTime` 的 `user_script` 标准 Bar 回测；这是本轮 `auto` 新链路的唯一业务范围。
- DataFrame 到固定类型 Bar 数组的单次写入。
- SharedMemory 与 `.npy` mmap 的选择、创建、挂载、只读访问和清理。
- 子进程分块批量物化 `list[Bar]`，并在策略执行前关闭底层映射。
- `spawn` 子进程行情引用协议及其版本校验。
- Compose 共享内存上限、服务器 `.env` 增量配置说明和旧链路回退开关。
- 单元、真实跨进程集成、结果等价、资源清理和远程普通用户样本回归。

### 2.3 非目标

- 不取消 DataFrame，不改变 ClickHouse 查询和现有分批读取。
- 不增加数据库支持以外的 Bar 周期，不恢复运行时周期聚合。
- 不修改 L2 Bar、Quote 或 Trade 数据块传输。
- 不改造 `research_signal` 及任何带非空 `_researchSignalByBarTime` 的任务；这类任务继续使用 `legacy`，后续如需优化，应单独设计研究信号列式 sidecar，不能把大字典继续伪装成“小型控制载荷”。
- 不改写 Python 撮合、账户、手续费、滑点和日终结算引擎。
- 不改变 `on_bar`、`bar`、`state`、`action`、`quantity`、`reason` 或订单回报契约。
- 不新增数据库字段、迁移、缓存协议、结果字段、API 或前端页面。
- 不新增运行时性能打点、诊断指标或诊断页面字段。
- 不引入 Arrow、PyArrow、Rust、C++、Numba 或其他新依赖。

### 2.4 必须保持的不变量

1. Bar 来源、正式日期、预热日期和周期继续遵循现有 Provider、快照及 ADR 0009、0010。
2. DataFrame 继续完成时区、数值类型、稳定排序、日期边界、重复值和非有限值校验。
3. 预热 Bar 仍调用 `on_bar` 并保留策略状态，但不产生交易和正式结果。
4. 正式 Bar 的回调顺序、下一根 Bar 开盘成交、日终判断和区间结束未执行委托语义不变。
5. 用户可见 `bar["time"]` 继续使用现有 `YYYYMMDDHHMMSS` 字符串，不因内部整数存储发生时区或格式变化。
6. 相同脚本、参数、行情快照和运行时版本必须产生相同的信号、委托、成交、费用、持仓、净值、警告和错误分类。
7. 子进程仍不持有 PostgreSQL、Redis、ClickHouse 或其他外部服务凭据。
8. 历史成功任务只读取已保存结果，不重算、不改写。

## 3. 当前链路与目标链路

### 3.1 当前链路

```text
ClickHouse 分批读取
  ↓
父进程 DataFrame
  ↓ 逐行构造 Python 对象
父进程 list[dict]
  ↓ spawn pickle 序列化与复制
子进程 list[dict]
  ↓ 逐行构造 Python 对象
子进程 list[Bar]
  ↓
BarBacktestEngine
```

### 3.2 目标链路

```text
ClickHouse 分批读取
  ↓
父进程 DataFrame（规范化与后处理继续保留）
  ↓ 直接写入目标存储，不创建中间字典列表
固定类型 NumPy 数组
  ├─ SharedMemory：小中型行情
  └─ .npy mmap：大型行情
  ↓ spawn 只传 marketDataRef
子进程挂载只读数组
  ↓ rows[start:end].tolist() 分块批量转换
子进程 list[Bar]
  ↓ 立即关闭映射并清除传输引用
现有 BarBacktestEngine
```

结果仍通过现有单向 Pipe 返回。本轮不改变结果对象的构造与传输；若后续确认结果载荷成为主要瓶颈，应另立范围处理。

## 4. 行情数组契约

### 4.1 固定 Schema

定义内部版本 `bar-ipc-v1`，使用显式小端定长 dtype：

| 字段 | NumPy dtype | 含义 |
| --- | --- | --- |
| `time_key` | `<i8` | 十进制 `YYYYMMDDHHMMSS`，不是 Unix 时间戳 |
| `open` | `<f8` | 开盘价 |
| `high` | `<f8` | 最高价 |
| `low` | `<f8` | 最低价 |
| `close` | `<f8` | 收盘价 |
| `volume` | `<f8` | 成交量 |

每条记录固定为 48 字节。`symbol`、`warmupBarCount` 和任务级配置只保存一次，不在每条记录中重复。使用十进制 `time_key` 是为了无损恢复现有 14 位本地市场时间字符串，避免本轮引入时区和 Unix 时间戳语义变化。

父进程必须直接在 SharedMemory 或 mmap 对应的 ndarray 视图中填充数据，禁止先建立另一份完整结构化数组再复制到目标存储。写入完成后校验实际 `nbytes`、记录数、dtype 和首尾时间，但不重复扫描或序列化完整数组。

### 4.2 行情引用协议

`spawn` 参数继续使用小型字典承载控制信息，行情改为 `marketDataRef`：

```text
marketDataRef = {
  schemaVersion: "bar-ipc-v1",
  transport: "shared_memory" | "mmap",
  location: <共享内存名称或受管临时文件路径>,
  rowCount: <记录数>,
  dataByteSize: <数组有效数据字节数>,
  fileByteSize: <仅 mmap 使用，含 .npy 头部的实际文件字节数>,
  symbol: <任务标的>,
  warmupBarCount: <预热记录数>
}
```

引用不得包含数据库地址、访问凭据或任意用户提供的文件路径。子进程挂载前必须校验 Schema 版本、记录数、有效数据字节数、实际文件字节数、dtype、预热边界及 mmap 路径是否位于受管临时目录；mmap 加载固定使用 `allow_pickle=False`。

## 5. 传输选择与容量边界

### 5.1 常数级预估

在创建传输前使用以下公式计算所需空间：

```text
required_bytes = len(normalized_frame) × BAR_DTYPE.itemsize
```

`len(DataFrame)` 和 `dtype.itemsize` 均来自已有元数据，不遍历 Bar，也不通过 pickle 测量大小。

### 5.2 SharedMemory 安全额度

每个 Bar Runner 容器显式配置 `/dev/shm` 上限，初始建议 128 MiB。应用可使用的共享内存安全额度取以下较小值：

```text
safe_shared_bytes = min(
  配置上限 × 75%,
  当前 /dev/shm 可用空间 × 75%,
)
```

Windows 本地运行没有容器 `/dev/shm` 时，使用同一配置上限计算软额度。配置仅决定传输选择，不改变回测结果语义。

当 `required_bytes <= safe_shared_bytes` 时选择 SharedMemory。创建失败、实际可用空间不足或平台不支持时，必须清理可能已创建的部分资源，再切换 mmap；不得重新退化为全量 `list[dict]`。

SharedMemory 只在以下前提同时成立时启用：用户策略无法从公开上下文取得 ndarray、共享内存名称或传输对象；现有受限执行环境的对抗测试无法通过反射、模块全局变量或异常对象取得底层缓冲区；Linux Runner 仍保持单任务单容器和私有 IPC 命名空间。任一前提无法证明时，本轮 `auto` 不得启用，服务器继续保持 `legacy`；本计划不引入未经独立验收的 mmap-only 生产模式。`ndarray.flags.writeable = False` 只是 NumPy 层的防误写措施，不是操作系统级只读隔离。

容量判断与实际创建之间存在时序窗口，即使预估满足也可能因其他系统活动分配失败。普通创建或写入异常必须关闭并回收半成品后切换 mmap。Linux tmpfs 在 `ftruncate` 成功后仍可能在首次触页时触发不可由 Python 可靠恢复的 `SIGBUS`，因此不能把“捕获首次写入异常”作为保障：支持 `posix_fallocate` 时，在写入前对 SharedMemory 文件描述符原子预留全部空间，预留失败则清理名称并切换 mmap；不支持该能力的平台才使用短生命周期辅助进程预触全部页。POSIX 辅助进程使用干净的 `forkserver` 上下文，避免继承 Runner 的 DataFrame、策略代码、凭据或打开的服务连接。若空间预留、辅助进程隔离或 `SIGBUS` 压力测试无法通过，本轮 `auto` 不得启用。

父进程在创建 SharedMemory 前，先在当前 Runner 私有目录原子写入并 `fsync` 一份资源清单，记录待创建名称、预期大小、Runner 启动 UUID 和任务 UUID；创建完成后更新状态，子进程 ACK 并完成 unlink 后删除清单。父进程若在 ACK 前被强制终止，下次启动审计只对“无活动锁/租约、所有者 UID 匹配、名称前缀及大小与清单一致”的资源执行 unlink。名称使用产品固定前缀、启动 UUID 与随机令牌，不接受用户输入，也不扫描或处理不在清单中的共享内存。

### 5.3 mmap 回退

当行情超过共享内存安全额度时，在当前 Runner 容器的受管临时目录创建任务级 `.npy` 文件：

- 文件名使用不可预测任务令牌，不包含用户输入。
- 每个 Runner 实例使用带启动 UUID 的私有目录和所有者标记；文件以原子排他方式创建，拒绝符号链接、重解析点、非普通文件、目录越界和所有者不符的目标。
- 权限限制为当前 Runner；父进程完成写入、刷新并关闭写视图，子进程在降低权限前由可信加载器以只读句柄打开和映射。
- 文件只保存定长数值数组，不保存策略代码、数据库凭据或结果。
- 父进程完成写入并释放写映射后再启动子进程。
- 子进程退出并释放所有切片、ndarray 和 mmap 句柄后由父进程删除；Windows 因映射句柄暂时无法删除时执行有限重试。
- 启动清理只检查受管根目录下不属于当前启动 UUID、超过保守存活期限且未持有活动锁/租约的 Runner 私有目录；不得清理其他正在运行 Runner 的文件。
- 临时目录使用容器本地可写层，不写入用户可见的 `/runtime/artifacts`，也不作为长期缓存。

mmap 只解决容量与复制问题，不保证首次访问与 SharedMemory 等速。操作系统按页加载和回收数据，避免把完整大型行情同时驻留在子进程堆内存中。

## 6. 子进程生命周期与权限顺序

SharedMemory 和 mmap 都需要在降低子进程权限前完成可信挂载，否则父进程创建的资源可能因操作系统权限无法打开。子进程初始化顺序固定为：

1. 接收并校验小型控制载荷和 `marketDataRef`。
2. 清空继承环境并恢复受控数值线程环境。
3. 由平台代码挂载行情资源，不执行用户代码。
4. 将 ndarray 标记为 NumPy 层只读，并通过控制 Pipe 向父进程发送 `market_data_attached` 确认。
5. 以固定上限分块执行 `rows[start:end].tolist()`，将 Python tuple 批量转换为原生 `list[Bar]`。
6. 释放临时 tuple、ndarray 和底层映射，清空 `marketDataRef`、路径和挂载对象，再发送 `market_data_materialized` 确认。
7. 父进程收到物化确认后立即关闭 SharedMemory 父句柄或删除 mmap 文件，并向子进程返回释放确认。
8. 子进程收到释放确认后降低策略子进程权限。
9. 使用原生 `list[Bar]` 编译并执行用户策略，运行现有回测引擎。
10. 在 `finally` 中释放 `list[Bar]` 并关闭 Pipe。

父进程必须以单一上下文管理器覆盖创建、进程启动、正常完成、策略异常、取消、超时、非零退出和进程启动失败。SharedMemory 在 POSIX 子进程确认挂载后立即由父进程 `unlink`，子进程完成物化并关闭映射后，父进程收到确认并关闭父句柄；Windows 在子进程关闭映射后由父进程执行 `close + unlink`。子进程未确认挂载、物化失败、启动失败或提前退出时，父进程立即 `close + unlink`。实现必须显式处理 Python `resource_tracker` 的注册关系，正常路径不得产生重复清理警告；不得假设父进程或容器崩溃后所有命名资源都必然自动清理。

mmap 文件必须在子进程完成物化并释放映射后立即删除，不等待用户策略或子进程退出。父进程整体被终止或容器重启时，依靠私有目录所有者标记、活动锁/租约和下次启动审计清理，而不是扫描通用临时目录。

行情数组只读标记用于防止平台代码误写，不将其宣称为安全边界。用户策略仍只接收现有字典上下文，不直接获得 ndarray、SharedMemory 名称或 mmap 路径；mmap 的只读文件句柄提供操作系统级写保护，SharedMemory 是否启用则受本节的隔离门槛约束。

## 7. 分块物化与引擎兼容

子进程按固定上限切分只读数组，对每块调用 `rows[start:end].tolist()`，一次得到 Python tuple 列表，再构造不可变 `Bar` 并追加到最终列表。每块完成后立即释放临时 tuple 列表，避免对每行单独读取 NumPy 标量，同时限制转换阶段的额外内存峰值。

- 最终结果必须是引擎原生 `list[Bar]`，不保留 ndarray、memmap、SharedMemory 句柄或传输引用。
- `time_key` 恢复为零填充 14 位 Python `str`；`symbol` 来自任务级元数据。
- OHLCV 必须是 Python `float`，不得泄漏 `numpy.float64`；字段顺序、缺失值拒绝规则及 `-0.0` 的保留语义与旧链路一致。
- 分块大小只控制临时 tuple 列表峰值，不改变最终 Bar 顺序、预热边界或结果语义。

现有 `BarBacktestEngine.run()` 继续接收原生列表，不增加共享数组兼容分支。用户策略仍通过 `ScriptedBarStrategy` 获得现有 `bar` 字典上下文，不会看到 NumPy 标量、共享内存对象或 mmap 路径。

## 8. 代码改造范围

### 8.1 新增内部传输模块

建议新增 `backend/bar_market_data_transport.py`，职责限制为：

- 定义 `bar-ipc-v1` dtype 和引用数据结构。
- 根据 DataFrame 行数与容量边界选择 SharedMemory 或 mmap。
- 直接填充目标 ndarray。
- 在子进程中验证、挂载并提供分块物化为 `list[Bar]` 的受管接口。
- 统一管理父子进程句柄、临时文件及异常清理。
- 清理当前 Runner 启动前遗留的受管 mmap 文件。

该模块不得读取数据库、策略代码、任务状态或业务配置，也不得保存结果。

### 8.2 `backend/services/backtest_runner.py`

- 保留 `_load_user_script_bars()` 返回的规范化 DataFrame及其后处理用途。
- 删除用户脚本执行载荷中的逐行 `bars: list[dict]` 构造。
- 将内部执行器签名明确调整为 `Callable[[dict[str, Any], pd.DataFrame], dict[str, Any]]`：第一个参数只含策略与运行配置，第二个参数是已经规范化的完整 Bar DataFrame；生产 `BarStrategySession` 在同一父进程内从该 DataFrame 创建传输资源，DataFrame 绝不进入 `spawn` 参数。
- 将 DataFrame和任务级 `symbol` 交给新的传输入口。
- 在选择执行器前检查 `_researchSignalByBarTime`：非空时明确路由 `legacy`，不进入新传输模块；普通 `user_script` 才允许按配置进入 `auto`。保持实验清单、快照哈希、基准和每日持仓计算不变。
- 测试注入用 `script_executor` 调整为明确的内部执行接口，不通过生产代码保留全量字典兼容分支。

### 8.3 `backend/bar_strategy_session.py`

- 在启动 `spawn` 前创建行情传输资源，仅把 `marketDataRef` 放入子进程参数。
- 按第 6 节顺序挂载、分块物化、关闭资源、降权和执行策略。
- `_execute_script()` 接收原生 `list[Bar]`，不再进入逐 Bar NumPy 转换热循环。
- 将传输资源清理纳入现有取消、超时、EOF、非零退出和强制终止路径。
- 保持 Pipe 响应、受控错误、管理员诊断正文和退出原因映射不变。

### 8.4 `backend/backtesting/engine.py`

不改变公开协议或实现。新链路恢复原生 `list[Bar]`，撤销仅为共享数组按需访问增加的热循环兼容修改。

### 8.5 Runner、配置与部署

- `backend/bar_runner.py` 在领取任务前清理本容器上次异常退出遗留的受管 mmap 文件；不得扫描或删除受管目录以外的路径。
- `backend/services/state_store.py` 的 Bar 与 L2 领取事务在真正领取前尝试取得同一个 PostgreSQL 事务级共享 advisory lock；取得失败时本轮不领取任务。该锁只形成发布屏障，不改变队列、租约、并发槽位或 L2 执行语义，也不需要数据库迁移。
- `scripts/deploy-server.sh` 在本次不重建的 PostgreSQL 容器内启动受管 `psql` 会话，持有对应的会话级排他 advisory lock。排他锁取得后，所有已进入的领取事务均已结束，后续领取被阻止；该会话必须持续到新容器健康且允许恢复领取，脚本通过 PID/锁持有者双重检查确认屏障仍在，并在异常退出时通过 `trap` 结束会话释放锁。若本次发布还需要重建 PostgreSQL，必须改走独立数据库维护流程，本计划的静默发布步骤不得继续。
- `backend/settings.py` 增加共享内存配置读取和边界校验。
- `deploy/compose.infrastructure.yml` 为 `bar-runner` 设置显式 `shm_size`，不修改 L2 Runner。
- `deploy/.env.example` 增加带中文备注的配置示例；服务器私有 `deploy/.env` 只做带备注的增量追加，不被示例文件覆盖。
- 保留 `legacy` 与 `auto` 执行开关用于首次静默发布和回滚。第一阶段服务器显式使用 `legacy`，验证镜像健康后再切换 `auto`；稳定后另行决定是否移除旧链路。
- `legacy` 模式不因共享内存容量参数缺失而阻止启动；只有 `auto` 启用时才强制校验相关配置和受管临时目录。
- 每个新链路任务只写一条不含用户数据的结构化运维日志，字段限于任务 UUID、传输类型、行数、有效数据字节数、创建/挂载/清理状态和 fallback 原因；不记录阶段耗时，不写数据库，不新增产品指标或页面字段。

建议配置：

```dotenv
# 每个 Bar Runner 容器的 /dev/shm 上限；auto 模式按其中 75% 作为业务安全额度
TREND_GRID_BAR_RUNNER_SHM_SIZE_BYTES=134217728

# 标准 Bar 行情跨进程传输模式：legacy 使用旧字典载荷，auto 使用 SharedMemory/mmap
TREND_GRID_BAR_IPC_MODE=legacy
```

实施时必须保证 Compose 的 `shm_size` 与容器内应用读取的是同一个字节配置，避免两套独立参数漂移。

## 10. 测试计划

### 10.1 单元测试

测试层次为单元测试；真实运行 dtype、数组转换和分块物化，只替换容量查询等明确系统边界。至少覆盖：

1. DataFrame 写入 `bar-ipc-v1` 后字段、顺序、数值和 14 位时间完全一致。
2. 空数据、非法时间、非有限数值、错误 dtype、错误字节数和非法预热边界被拒绝。
3. 共享内存安全额度以内选择 SharedMemory，超过额度选择 mmap。
4. SharedMemory 创建失败时清理部分资源并选择 mmap。
5. 小于、等于和跨越分块边界的数组均转换为顺序一致的原生 `list[Bar]`。
6. 每块使用批量 `tolist()`，完成后释放临时 tuple 列表；非法分块大小被拒绝。
7. mmap 路径越界、Schema 版本不匹配和 `allow_pickle` 对象数组被拒绝。
8. 配置值为空、非整数、过小或超过容器内存边界时明确失败。
9. Python `str`、Python `float`、字典字段顺序、14 位时间、符号和 `-0.0` 与旧路径一致，不向用户上下文泄漏 NumPy 标量。
10. 非空 `_researchSignalByBarTime` 必须路由 `legacy`；空值或缺失时才允许进入 `auto`。

### 10.2 跨进程集成测试

测试层次为集成测试；必须通过 `multiprocessing.get_context("spawn")`、可导入的模块顶层目标函数真实运行 Pipe、SharedMemory 和 mmap，不得用 Fake/Mock 代替序列化、权限和生命周期机制。至少覆盖：

1. SharedMemory路径执行两根以上Bar并产生预期下一开盘成交。
2. 强制mmap路径产生与SharedMemory完全相同的结果。
3. 预热与正式区间跨越物化分块边界后，回调次数、状态和结果正确。
4. 普通策略读取 `bar["time"]` 和 OHLCV 时与旧链路一致；研究信号任务继续走 `legacy` 且结果不变。
5. 策略异常后返回既有错误分类和管理员诊断，父进程清理资源。
6. 无限循环被取消和强制终止后，共享内存或临时文件被清理。
7. 子进程非零退出、信号退出、进程启动失败和Pipe中断均不遗留资源。
8. 子进程在降权和执行用户代码前已完成物化并关闭映射，且无法取得父进程服务凭据。
9. Windows能够在子进程退出后删除mmap文件；暂时占用时有限重试和启动清理生效。
10. 并行运行多个独立Bar Runner测试实例时，资源名称和临时文件互不冲突。
11. POSIX 子进程发出挂载确认后，共享内存名称无法再次挂载；子进程发出物化确认前已关闭映射，父进程收到确认后立即关闭句柄或删除 mmap 文件。
12. 父进程分别在 SharedMemory 创建后、空间预留或兜底预触页后和策略子进程 ACK 前被强制终止，Runner 重启审计均依据资源清单回收旧名称；断言旧名称无法再次挂载，且不删除其他 Runner 活跃资源。
13. 正常、异常和强制终止路径不产生 `resource_tracker` 泄漏或重复清理警告。
14. 用户策略无法从公开上下文、异常对象或已允许模块取得底层数组、共享内存名称和 mmap 路径；若该对抗测试失败，服务器必须保持 `legacy`，不得启用 `auto`。
15. mmap 文件在挂载前被删除、替换为链接、改变大小或越界时安全失败并完成清理。
16. Linux `posix_fallocate` 真实预留全部 SharedMemory 空间；模拟 `ENOSPC` 时父进程保持存活、完成清理并改选 mmap。缺少该能力时，辅助进程必须真实预触全部页，且 DataFrame 不进入辅助进程参数。
17. 使用真实 PostgreSQL 并发连接验证发布辅助进程取得排他 advisory lock 后，Bar 与 L2 均不能领取新任务；锁前已领取任务可续租并正常完成，释放锁后排队任务恢复领取。
18. 部署辅助进程异常退出、数据库连接中断或脚本失败时锁自动释放，不会永久阻塞队列；部署脚本未取得锁或等待运行任务超时时必须中止发布。

Linux 的降权、私有 IPC 命名空间、文件权限和提前 `unlink` 测试必须在真实 Runner 容器中执行；Windows 本地测试只验证该平台的句柄和文件删除语义，不能替代 Linux 安全验收。

## 11. 验收标准

以下条件全部满足后才能切换服务器 `auto`：

1. 符合新链路条件的普通 `user_script` 任务，其 `spawn` 参数不再包含完整行情列表，只包含小型配置和 `marketDataRef`；研究信号任务作为明确的 `legacy` 例外。
2. SharedMemory 和 mmap 均通过真实跨进程集成测试；SharedMemory 隔离或所有权验收失败时保持 `legacy`，不得以 mmap-only 名义切换 `auto`。
3. 子进程以有界分块批量构造原生 `list[Bar]`，并在用户代码执行前关闭 ndarray、SharedMemory 或 mmap，清除行情引用和路径。
4. 新旧链路在普通固定样本、预热、成交、持仓、净值、警告和错误上结果一致；研究信号任务的旧链路结果保持不变。
5. 正常完成、异常、取消、超时和崩溃路径均通过资源生命周期测试；进程级异常依靠提前 unlink 或显式清理，容器级异常依靠受管目录启动审计，不能以“操作系统会自动清理”代替验证。
6. Windows本地和Linux容器验证完成。
7. 开发期性能验收达到第10.5节标准，或未达标时保持`legacy`并停止切流。
8. 两条远程普通用户样本回归通过；无法执行时如实标记待验证，不进行服务器auto切流。
9. 用户策略、API、结果结构和页面无需修改。
10. 现有诊断日志页面不新增字段且正常读取既有任务。

## 12. 发布与静默切换

### 12.1 受影响服务

直接受影响的是 `bar-runner`。代码位于共享backend镜像，服务器发布仍必须使用 `scripts/deploy-server.sh`，不得只复制文件或只重启某个容器。`backend`与其他使用同一镜像的服务需完成基础健康检查；L2执行语义和代码路径不变。

发布脚本当前会重建相互依赖的服务，因此发布前必须检查排队和运行中的标准 Bar 及 L2 任务。运行中任务应等待完成、由用户取消，或经明确确认后标记为发布中断；不得静默终止。正常发布按以下顺序执行：

1. 发布辅助进程取得第 8.5 节的 PostgreSQL 排他 advisory lock，原子阻止 Bar 与 L2 新领取；未取得锁不得继续。
2. 在保持锁连接的同时等待运行中任务和有效执行槽位归零；排队任务保留。等待超时则释放锁并中止发布，不终止任务。
3. 再次核验锁持有者与辅助会话 PID，然后通过 `scripts/deploy-server.sh` 同批发布并等待新容器健康；任一核验失败立即中止，不能在无屏障状态下继续。
4. 释放排他锁，新 Runner 才能恢复领取。

第一次部署时旧 Runner 尚未包含共享锁检查，因此使用一次性引导屏障：先确认运行中任务为 0，立即暂停全部旧 Bar 与 L2 Runner 容器，再次查询任务和有效执行槽位；若竞态中已有任务被领取，则恢复全部容器、等待其完成后重试。只有在 Runner 全部暂停且二次查询仍为 0 时，才允许部署脚本强制替换这些无任务容器。部署脚本必须显式支持替换已暂停容器并在失败时恢复服务；不满足任一条件则中止首次发布。

### 12.2 两阶段静默发布

第一阶段：部署代码但保持：

```text
TREND_GRID_BAR_IPC_MODE=legacy
```

完成镜像启动、Runner健康、历史任务读取和代表性旧链路回测检查。此阶段用户行为完全不变。

第二阶段：本地、远程样本和资源清理验收通过后，将服务器私有 `.env` 增量修改为：

```text
TREND_GRID_BAR_IPC_MODE=auto
```

按第 12.1 节取得排他领取屏障并等待运行任务归零后，仍使用 `scripts/deploy-server.sh` 同批发布相互依赖服务，不能只重建 Bar Runner。普通新任务自动选择 SharedMemory 或 mmap；带研究信号任务继续使用 `legacy`，既有已完成任务不受影响。前端不展示传输方式，不要求用户重新保存策略或方案。

观察周期定义为：服务器 `auto` 连续运行至少 24 小时且完成至少 100 个符合范围的标准 Bar 任务，其间 IPC 资源泄漏和新增传输错误均为 0；另至少完成 1 个受控 mmap 任务。观察期开始和结束时各运行一组冻结输入 canary，通过隔离 Runner 分别强制 `legacy`、SharedMemory 和 mmap，三者结果差异必须为 0。普通生产任务不重复执行旧链路，不将其统计为“结果差异为 0”的证据。未达到任务量或 canary 对照未完成时继续观察，不以经过 24 小时单独判定稳定。

### 12.3 发布后检查

1. 检查backend、bar-runner和部署脚本涉及服务的健康状态。
2. 运行一个包含预热的标准Bar用户脚本任务。
3. 运行一个研究信号驱动的标准 Bar 任务，确认仍走 `legacy` 且结果不变。
4. 通过测试装配运行一个强制 mmap 的受控验证任务，不向生产 API 暴露传输选择参数。
5. 检查成功、失败和取消任务均无受管IPC资源遗留。
6. 打开标准Bar、L2和共享历史成功任务，确认结果仍可读取。
7. 确认任务排队、领取、续租和并发槽位数量没有变化。

未实际执行的服务器验证必须标记为待验证。

## 13. 回滚策略

本轮没有数据库迁移、结果结构或缓存版本变化。优先回滚方式是将：

```text
TREND_GRID_BAR_IPC_MODE=legacy
```

并按第 12.1 节取得排他领取屏障、等待运行任务归零后，仍通过 `scripts/deploy-server.sh` 同批发布配置。该回滚只影响后续新任务；已完成任务无需处理。

如果新代码影响容器启动、旧链路或共享镜像中的其他服务，则恢复上一稳定镜像。回滚前后均不得删除或重算历史任务。SharedMemory 正常路径由父进程按平台语义显式回收，POSIX 在子进程挂载确认后提前 unlink；mmap 遗留文件由受管目录启动审计回收，不需要数据库或 Redis 清理。不得依赖“进程退出后操作系统必然清理”作为回滚保障。

## 14. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 子进程降权后无法打开共享资源 | 任务启动失败 | 可信平台代码先校验并挂载，再降权执行用户代码；真实Linux容器测试。 |
| SharedMemory超过`/dev/shm`容量 | 分配失败或进程异常 | 使用75%安全额度，读取实际可用空间，失败时清理并切换mmap。 |
| SharedMemory只有逻辑只读而非操作系统只读 | 用户代码若取得缓冲区可能篡改行情 | 在用户代码执行前关闭映射、清除引用并增加对抗测试；隔离、空间预留或所有权验收失败时服务器保持legacy，不启用auto。只有SharedMemory总体门槛已通过后，单任务容量超限或普通分配失败才允许回退只读mmap。 |
| 父进程或容器在清理前崩溃 | 命名共享内存或临时文件遗留 | POSIX挂载确认后提前unlink；mmap使用实例私有目录、活动锁/租约和启动审计，并覆盖强制终止测试。 |
| SharedMemory首次触页触发`SIGBUS` | Bar Runner父进程被直接终止 | Linux优先用`posix_fallocate`原子预留tmpfs空间，失败时改选mmap；不支持时才由隔离辅助进程预触页，压力测试失败则不启用auto。 |
| DataFrame、临时数组和共享数组同时存在 | 峰值内存收益不足 | 直接填充目标映射数组，不创建中间完整结构化数组。 |
| mmap磁盘不足或首次访问慢 | 大任务失败或回退收益不足 | 使用容器本地受管目录、创建前检查空间、开发期基准和明确失败；不使用legacy掩盖资源不足。 |
| Windows映射句柄阻止文件删除 | 本地遗留临时文件 | 子进程退出后释放所有视图，有限重试删除，Runner启动时清理本目录遗留文件。 |
| `time_key`转换改变时间 | 回调、日终和成交变化 | 保存14位十进制时间键，逐条等价测试首尾、跨日、午休和预热边界。 |
| 分块物化顺序或边界错误 | 预热、日终或成交语义变化 | 对跨分块边界的预热、正式区间和结果等价执行真实引擎集成测试。 |
| 完整`list[Bar]`常驻内存 | 峰值内存降幅不足 | 只长期保留`list[Bar]`，逐块释放临时tuple并在物化完成后立即关闭映射；性能门槛失败则保持legacy。 |
| 策略通过未公开内部对象观察到变化 | 个别非标准脚本行为变化 | 用户策略继续只获得现有字典上下文，不暴露NumPy或传输引用。 |
| mmap文件包含任务行情 | 容器内临时数据泄漏 | 随机名称、受限权限、本地目录、任务后删除和启动清理，不写共享artifact目录。 |
| 启动清理误删其他Runner活跃文件 | 正在运行的任务失败 | 每实例私有目录和所有者标记，只清理超期且无活动锁/租约的目录，禁止扫描受管根目录之外。 |
| 检查任务为空后又领取新任务 | 发布重建静默中断回测 | PostgreSQL共享/排他advisory lock形成原子领取屏障；首次部署用暂停旧Runner并二次核查的引导屏障。 |
| 研究信号时间映射仍是大字典 | 新链路并未消除全部spawn大载荷 | 本轮带非空研究信号任务固定走legacy；后续单独设计列式sidecar，不在本轮隐式兼容。 |
| 新旧路径长期并存 | 维护成本增加 | 仅作为观察期回滚手段；稳定后单独评审删除legacy，不在本轮提前移除。 |

## 15. 方案自审结论

- **是否针对已确认问题**：是。直接消除父进程`list[dict]`和完整行情pickle，并撤销逐Bar NumPy转换热循环。
- **是否改变数据准备职责**：否。DataFrame继续承担规范化和后处理，数据库读取与周期规则不变。
- **是否改变用户策略逻辑**：否。用户仍接收相同bar字典和state，回调及撮合语义不变。
- **是否引入容量新瓶颈**：否。SharedMemory只处理安全额度内任务，大型行情使用mmap。
- **是否依赖新增第三方包**：否。使用Python标准库与现有NumPy。
- **是否扩大到L2**：否。L2继续使用现有数据块链路。
- **是否新增诊断指标**：否。只保留每任务一条必要的资源生命周期运维日志和开发期外部基准，不进入数据库或诊断页面。
- **是否支持静默发布**：是。通过legacy/auto开关、结果对照、两阶段切换和镜像回滚控制风险。
- **是否与既有ADR冲突**：无。计划保持预热、实际Bar日期、历史快照、原生周期和下一开盘成交边界。

## 16. 完成定义

以下条件全部满足后，本计划才能标记完成：

1. 符合范围的普通标准 Bar 用户脚本生产路径不再构造全量 `list[dict]` 或通过 spawn 传输完整行情；研究信号例外已明确路由 `legacy`。
2. 子进程通过有界分块构造原生`list[Bar]`，在用户代码执行前关闭映射并清除传输引用。
3. SharedMemory、mmap、资源清理、取消和异常路径已通过真实跨进程测试。
4. 新旧路径结果等价测试、本地Windows和Linux容器验证已完成。
5. 必要后端测试与发布契约测试已实际通过，未执行项已如实记录。
6. 两条远程普通用户样本已通过隔离Runner回归，或因真实阻塞明确标记待验证且未切换服务器auto。
7. 服务器私有`.env`以带备注的增量方式配置，未被`.env.example`覆盖。
8. 发布前已处理运行中的Bar与L2任务，相关服务同批发布并完成发布后检查。
9. `auto` 模式达到第 12.2 节定义的观察周期，期间未发现结果差异、IPC 资源遗留或新增传输错误。
10. 实施后重新检查`docs/玄龄回测系统使用手册.md`；只有实际出现用户可见行为变化时才同步更新并重新验收。
11. advisory lock 发布屏障、首次部署引导屏障和部署失败自动解锁已通过真实数据库及脚本测试，发布过程不依赖“检查为零后的时间窗口”。
