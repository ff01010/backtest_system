# 回测工作台布局与视觉改造方案

## 1. 目标与边界

本方案将前端改造成借鉴 TradingView 的浅深搭配回测工作台。目标是让用户先看到行情与结果，再按需查看参数、明细和快照；页面以浅色为主，用少量深色建立导航和工作区重点，保持专业、紧凑、可长时间阅读，不做全局暗黑主题，也不复制 TradingView 的品牌、图标或代码。

本次只改前端的信息架构、布局、组件样式和交互反馈，不改以下内容：

- 不修改登录、权限、策略保存、回测运行和历史快照的业务规则。
- 除“回测交易点图层”所需的只读查询接口外，不修改后端 API、PostgreSQL、ClickHouse 或策略执行器。
- 不引入新的前端依赖或图表库。
- 不改变 A 股配色习惯：上涨/盈利使用红色，下跌/亏损使用绿色。

## 2. 当前问题

当前应用已经采用浅色主题，但存在三个主要问题：

1. 全局页面使用主题变量，回测页仍存在大量硬编码颜色、边框和背景，视觉难以统一。
2. 回测前的参数编辑与回测后的结果阅读混在同一套左右栏结构中，结果页容易被不再可编辑的参数挤压。
3. 指标、图表、交易记录和历史回测的层级不一致，卡片较多、圆角和浅色底块较多，缺少交易终端式的密度与数据对齐感。

## 3. 设计原则

### 3.1 图表和结果优先

结果页的核心区域优先分配给净值、基准、回撤、每日盈亏、交易明细和持仓表格。参数不再作为持续可见的结果页侧栏，只以一行上下文或按需展开的快照出现。

### 3.2 用分区代替卡片堆叠

使用白色画布、浅灰分区、细边框和 4px 小圆角区分内容。只对需要强调的指标、错误和运行状态使用背景色，避免每个内容块都成为独立卡片。

### 3.3 数据对齐优先于装饰

数字采用右对齐或等宽数字显示；表头、图例和筛选控件紧凑排列。颜色只用于表达状态、方向和风险，不能仅用于装饰。

### 3.4 编辑与阅读分离

策略管理页承担脚本和方案编辑；概览、信号明细、持仓收益、历史回测承担只读研究。已完成回测的参数来自不可变快照，不能在结果页直接修改。

### 3.5 桌面优先，兼顾窄屏

回测研究以桌面屏幕为主，优先适配 1280px 以上宽度；在平板和手机上将多列指标、表格筛选和次要元数据逐步折叠，而不是硬压缩。

### 3.6 浅深搭配建立视觉锚点

浅色用于图表、表格和长时间阅读区域；深色只用于顶栏、工作区标题、活动标签、代码编辑器和少量关键摘要。深色区域总面积应明显小于浅色区域，避免把回测报告变成暗黑终端，也避免整页浅灰导致重点不清。

## 4. 目标信息架构

```text
顶栏：产品名 | 策略回测 | 信号可视化 | 数据管理 | 人员管理 | 当前用户

策略回测
├─ 概览：核心指标 | 净值与基准 | 回撤/每日盈亏 | 回测口径
├─ 信号明细：本次回测摘要 | 筛选/导出 | 交易表格
├─ 持仓收益：本次回测摘要 | 每日持仓、现金、市值、日盈亏
├─ 历史回测：回测列表 | 实验快照 | 结果对比
└─ 策略管理：策略列表 | 代码编辑 | 方案参数与保存

信号可视化
├─ 顶部工具栏：标的、日期、周期、回测编号、刷新
├─ 主区：K 线、买卖点、十字光标
└─ 底部状态栏：数据状态、告警、加载状态
```

## 5. 布局改造

### 5.1 全局框架

- 顶栏固定高度 `44px`，使用深蓝黑结构色和低对比度分隔线，不使用悬浮阴影。
- 产品名保持在左侧；一级导航紧随其后；用户信息与退出按钮保持右对齐。
- 一级导航使用浅色文字；激活项以蓝色下边框和较亮文字表示，不使用整块胶囊按钮。
- 主画布背景为浅灰，业务内容区域保持白色或透明，让页面分区自然显现。
- 页面内容采用统一的 `max-width` 规则：普通管理页 `1440px`，图表工作台与宽表允许使用完整可用宽度。

### 5.2 策略回测：运行前区

- 仅在“概览”标签上方显示运行条。
- 运行条从左到右依次为：策略方案选择、运行模式、状态文字、运行按钮。
- 标的、基准、日期、资金、成本和持仓规则只在概览左侧的编辑区显示。
- 运行前检查紧邻运行参数底部，使用简短状态行显示数据覆盖、基准覆盖和保存状态。
- 用户切换到结果标签后，不再显示可编辑运行参数。

### 5.3 策略回测：概览页

第一屏固定为以下顺序：

1. 六项核心指标横条：总收益、年化收益、超额收益、最大回撤、Sharpe、交易次数/胜率。
2. 主图区域：净值曲线与基准曲线；右上或同图叠加时间范围切换。
3. 辅图区域：回撤曲线与每日盈亏柱状图，共用日期范围和悬浮提示。
4. 回测口径：放在图表下方的单行说明，包含成交模型、持仓规则、手续费、滑点和实验指纹。

核心指标保持一行，宽度不足时横向滚动或折成两行，不能缩小到难以阅读。完整指标保留在“详细分析”折叠区或二级区域，不抢占第一屏。

### 5.4 信号明细页

- 取消固定实验设置侧栏，使用顶部的回测上下文条：`#编号 · 策略方案 · 标的 · 周期 · 日期区间`。
- 上下文条下方放置紧凑的筛选工具条：买卖方向、盈亏状态、按日期分组、导出 CSV。
- “显示字段”改为折叠面板，默认收起。
- 交易表格使用粘性表头；价格、数量、盈亏右对齐；时间和备注左对齐。
- 当未来接入 K 线交易点后，点击交易行应定位到信号可视化页对应时间；本阶段只预留交互入口，不要求实现跨页定位。

### 5.5 持仓收益页

- 取消固定实验设置侧栏，复用与信号明细相同的回测上下文条。
- 主区优先展示每日持仓、现金、多空市值、总资产和日盈亏表格。
- 表格上方预留“持仓曲线 / 资产构成”图表槽位；当前没有数据时显示简洁空状态，不以大面积说明文字占位。
- 大表格支持横向滚动，首列日期可在后续阶段设为粘性列。

### 5.6 历史回测页

- 左侧为可筛选的历史列表，右侧为选中记录详情；在窄屏时改为上下排列。
- 列表只保留：编号、策略/方案、标的、区间、收益、回撤、Sharpe、状态、时间。
- 详情按“实验摘要、指标、参数快照、数据快照、备注与标签、对比”分组，默认仅展开实验摘要和指标。
- 所有历史编号显示用户自己的 `#01`、`#02`，不在界面中显示 UUID。

### 5.7 策略管理页

- 保留“策略列表 | 代码编辑 | 参数与保存”三列工作区。
- 移除外层重复的脚本摘要侧栏，工作区居中显示，最大宽度 `1440px`；宽屏保留左右留白。
- 左列用于选择或新建策略与方案，中列为代码编辑，右列为方案参数、保存状态和运行前检查。
- 保存按钮固定在右列底部或工作区顶部，始终可见；不新增“草稿/发布版本”按钮。

### 5.8 信号可视化页

- 保留当前“工具栏 + 图表 + 状态栏”工作台结构。
- 删除早期信号 CSV 的标的下拉、策略、信号文件、模块 A/B、理论信号对比和价格标签控制，避免与回测成交点语义混杂。
- 工具栏只保留只读标的、交易日、周期、回测编号和刷新；日期只显示日期本身，不再显示“无信号”状态。
- 用户从某条回测记录进入时，图层默认显示该回测的已成交订单；切换回测应回到策略回测页，在交易明细中重新选择记录。
- 从信号明细点击某笔交易时，自动带入回测编号、标的、周期、交易日和实际成交时间，并定位到该 K 线。
- 图表继续承担完整复盘；回测概览不重复嵌入完整 K 线图，只提供“查看 K 线”入口。

### 5.9 回测交易点图层与明细联动

本功能借鉴 TradingView Strategy Report：已成交订单直接覆盖在价格图上，交易明细与同一批标记相互定位。

#### 交互路径

```text
回测概览 / 信号明细中的交易行
  └─ 点击“查看 K 线”
       └─ 打开信号可视化页
            └─ 请求当前用户的回测 #编号、交易日 K 线和成交点
                 └─ 将视口定位到 executionTime（实际成交时间）所在 K 线
```

#### 标记规则

| 成交动作 | 图形 | 文字 | 位置 | 色彩 |
| --- | --- | --- | --- | --- |
| `buy_open` | 向上箭头 | 买开 | K 线下方 | 红色系 |
| `sell_close` | 向下箭头 | 卖平 | K 线下方 | 绿色系 |
| `sell_open` | 向下箭头 | 卖开 | K 线上方 | 绿色系 |
| `buy_close` | 向上箭头 | 买平 | K 线上方 | 红色系 |
| 同一 K 线多笔成交 | 聚合圆点 | `3 笔` | K 线附近 | 中性蓝灰 |

- 第一阶段只绘制已成交的买卖订单，不绘制跳过信号、手续费或盈亏。
- 标记位置按 `executionTime（实际成交时间）` 对齐。当前没有成交撮合，`signalTime（信号时间）` 与 `executionTime` 相同；两者仍应作为独立字段保存，为后续撮合延迟预留兼容性。
- 当回测周期与查看周期不一致时，标记吸附到包含实际成交时间的最近一根 K 线；悬浮说明保留真实成交时间，不能将 K 线时间误作成交时间。
- 标记必须同时包含箭头方向和文字，不可仅靠 A 股红涨绿跌颜色表达动作。
- 鼠标悬停只显示：回测编号、买卖动作、成交价、数量、策略原因、信号时间和实际成交时间；不在 K 线图层展示手续费或盈亏。
- 密集标记自动聚合；点击聚合标记后列出该 K 线内的所有交易，并可跳转到信号明细中对应行。
- “仅箭头 / 箭头加文字 / 隐藏标记”作为图表显示偏好，不影响回测数据和导出结果。

## 6. 视觉样式改造

### 6.1 主题令牌

所有页面必须使用统一 CSS 变量，禁止在业务组件继续新增色值。建议在 `frontend/src/styles/global.css` 中建立以下浅色令牌：

| 类型 | 建议值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#f7f8fa` | 应用背景 |
| `--surface` | `#ffffff` | 主内容表面 |
| `--surface-muted` | `#f0f3f7` | 次级分区、表头、禁用区 |
| `--surface-hover` | `#e9edf3` | 行悬停、工具按钮悬停 |
| `--chrome` | `#131722` | 顶栏、工作区深色结构层 |
| `--chrome-raised` | `#1e222d` | 深色结构层的悬停、活动背景 |
| `--chrome-text` | `#d1d4dc` | 深色结构层中的次要文字 |
| `--text` | `#131722` | 主文字 |
| `--text-muted` | `#5d606b` | 次要文字 |
| `--text-subtle` | `#8a8f98` | 辅助文字 |
| `--border` | `#e0e3eb` | 默认边框和分隔线 |
| `--border-strong` | `#c9cdd4` | 输入框与激活边框 |
| `--accent` | `#2962ff` | 主操作、激活标签、链接 |
| `--accent-soft` | `#e8f0fe` | 激活背景 |
| `--profit` | `#f23645` | A 股上涨、盈利 |
| `--loss` | `#089981` | A 股下跌、亏损 |
| `--warning` | `#f59e0b` | 数据缺失、需注意状态 |
| `--danger` | `#d64c4c` | 错误、不可恢复操作 |

### 6.2 字体与数字

- 中文正文优先使用 `Microsoft YaHei`、`PingFang SC`、`Segoe UI` 等系统字体，避免大面积衬线字体。
- 产品名可保留当前有辨识度的宋体风格，但不得用于表格、指标和表单。
- 金额、收益率、数量、日期和编号使用 `font-variant-numeric: tabular-nums`，保证数字纵向对齐。
- 标题使用 16px/600，区块标题使用 14px/600，正文 13px，辅助文字 12px；不要用过大的标题制造空白。

### 6.3 边框、圆角与阴影

- 默认使用 `1px` 边框与 `4px` 圆角。
- 表格、图表和代码区不使用明显投影。
- 弹窗、下拉面板和浮动提示可使用轻微阴影，避免漂浮卡片感。
- 区块之间优先通过 12px～16px 间距和分隔线区分，不依赖彩色背景块。
- 深色结构区只与相邻浅色内容区形成明确分界，不在同一页面连续叠加多个深色大面板。

### 6.4 按钮、输入与标签

- 主按钮为蓝色实底，仅用于“运行回测”“保存策略”“创建账号”等主要动作。
- 次按钮使用白底细边框；危险操作仅使用红色文字或二次确认后的红色按钮。
- 输入框高度统一为 32px，聚焦状态使用蓝色描边与轻微外发光。
- 标签页使用文本 + 2px 底部激活线；禁止大面积圆角胶囊标签。
- 状态标签使用低饱和背景和文字颜色，不承担导航功能。
- 深色工作区中的次按钮使用透明底和深色边框，主操作仍保持蓝色，避免出现多种互相竞争的强调色。

### 6.5 图表与表格

- 图表背景白色，网格线使用低对比度灰色，坐标轴与图例采用次要文字色。
- 策略净值使用蓝色，基准使用灰黑色，超额收益使用紫蓝或靛蓝色；回撤使用低饱和红色面积。
- 每日盈亏柱状图遵循 A 股红涨绿跌，悬浮提示必须同时显示日期、值和单位。
- 表头使用浅灰背景，正文行仅在悬停和选中时变色；不使用斑马纹作为默认样式。
- 表格中的负数和亏损数字以绿色表示，正数和盈利数字以红色表示，并保留 `+/-` 或文字含义，避免仅依赖颜色。
- 代码编辑器采用深色编辑区，便于长时间阅读代码；它是独立工作区，不改变其他回测结果页面的浅色基调。

## 7. 组件与代码改造方式

### 7.1 先建立基础样式层

1. 在 `global.css` 统一补全主题令牌、表单焦点、数字字体和滚动条规则。
2. 新增可复用的样式常量或轻量组件：`Panel`、`MetricStrip`、`ContextBar`、`DataTable`、`StatusBadge`、`SectionTabs`。
3. 将 `BacktestPage.tsx` 中的硬编码色值逐步替换为变量，不在一次提交中重写全部业务状态。

### 7.2 再按页面迁移

| 顺序 | 页面/组件 | 改造重点 |
| --- | --- | --- |
| 1 | `App.tsx`、`global.css`、`BacktestTabs.tsx` | 全局顶栏、画布、导航标签与主题令牌 |
| 2 | `BacktestPage.tsx` 概览 | 指标横条、图表分区、回测口径与上下文条 |
| 3 | `BacktestPage.tsx` 信号/持仓/历史 | 表格、筛选、快照分组与对比布局 |
| 4 | `BacktestPage.tsx` 策略管理 | 三列工作区、居中宽度和保存操作层级 |
| 5 | `backend/app.py`、`schemas.py`、`api/client.ts` | 新增仅查询当前用户回测交易点的接口与类型 |
| 6 | `Toolbar.tsx`、`Sidebar.tsx`、`KlineChart.tsx` | 信号可视化工作台统一主题、交易点图层与定位交互 |
| 7 | `UserManagementPage.tsx`、`LoginPage.tsx` | 管理页面和登录页的统一收尾 |

### 7.3 不改变的数据边界

- 除交易点图层外，UI 只消费现有的回测结果、历史快照、数据覆盖和权限接口。
- 历史记录仍使用数据库 UUID 作为 API 标识，页面只显示 `displayNo`。
- 结果页展示的手续费、滑点和持仓规则必须来自 `experimentManifest` 或历史快照，不能读取正在编辑的方案值。
- 任何样式改造不得改变策略保存、回测运行、CSV 导出和历史对比的行为。
- 交易点查询必须按当前登录用户过滤回测记录；不能仅依据前端传来的 `runId（回测唯一标识）` 返回数据。

### 7.4 K 线实现参考：LangAlpha

`C:\Users\zhongying\LangAlpha` 的 K 线实现可作为本项目的架构参考，重点借鉴其“图表容器、数据加载、图层标记”分层方式，而不是直接复制页面或业务代码。

| LangAlpha 的做法 | 本系统中的落地方式 |
| --- | --- |
| `MarketChartSurface` 负责图表周边工具栏和工作区 | 新增或整理 `BacktestChartSurface`，只负责标的、日期、图层开关、加载与空状态。 |
| `MarketChart` 专注创建 K 线和指标序列 | 保持 `KlineChart.tsx` 只负责绘制、缩放、十字光标与图表生命周期。 |
| `useChartOverlays` 集中校验、排序并一次性写入所有标记 | 新增 `useBacktestTradeMarkers`，第一阶段只处理已成交买卖点；未来若加入策略信号图层，仍在同一位置统一排序、聚合与清理。 |
| 标记包含时间、上下位置、形状、颜色和文本 | 回测标记使用本方案第 5.9 节的动作语义；时间必须对齐 `executionTime（实际成交时间）`。 |
| 标记变更时清除旧图层，避免残留 | 切换回测编号、日期、标的或关闭图层后，必须显式清空旧标记，不能显示上一次回测的成交点。 |

实现时还应采用其两个关键细节：

1. 标记时间先映射或吸附到已加载的最近一根 K 线，再渲染，避免交易时间与周期边界不完全一致时标记丢失。
2. 由于底层图表 API 通常以“整组覆盖”方式设置标记，所有来源的标记必须先在同一 Hook 中合并、校验和按时间排序，不能让多个组件分别写入图层。

本项目当前不因参考 LangAlpha 而直接复制其代码，也不在本次视觉改造中新增图表依赖。若后续确认需要使用其采用的 `lightweight-charts`，这是会修改 `package.json` 的独立技术决策，应先单独确认；在此之前，优先在现有 `KlineChart.tsx` 中实现相同的标记协议和交互效果。LangAlpha 使用 Apache-2.0 许可证，若未来确需复制其源代码片段，必须保留相应许可证和声明。

## 9. 验收标准

### 布局

- 概览页第一屏能同时看到六项核心指标和主净值图。
- 信号明细、持仓收益页不再出现实验设置侧栏，主内容宽度明显增加。
- 策略管理页没有重复脚本摘要栏，工作区在宽屏居中并保留侧边留白。
- 历史回测不显示 UUID，所有页面统一显示用户独立的 `#01` 格式编号。
- 从任意已成交交易行点击“查看 K 线”后，信号可视化页能定位到同一标的、周期、交易日和实际成交 K 线。
- 图表上的买开、卖平、卖开、买平和聚合标记可辨识，且悬浮信息与回测明细一致。

### 视觉

- 回测、数据、人员管理、登录和信号可视化均使用相同主题令牌。
- 业务组件中不再新增硬编码主色、背景色和边框色。
- 主操作为蓝色；A 股涨跌与盈亏为红涨绿跌；错误和警告颜色不与涨跌颜色混用。
- 表格、图表、输入框、标签页和按钮具有统一的边框、圆角、字体和悬停状态。

### 功能回归

- 登录、退出、人员管理、策略保存、运行回测、查看历史、比较历史、交易筛选和 CSV 导出均可正常使用。
- 运行结果与历史快照数值不因视觉改造发生改变。
- `npm test`、`npm run build` 通过；对关键桌面和窄屏页面进行浏览器截图检查。

## 10. 实施风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 单个超大组件改动导致回归 | 先抽离纯展示组件，保留现有状态与 API 调用，再逐段替换布局。 |
| 使用硬编码颜色导致主题再次分裂 | 新增颜色必须先定义为主题令牌；代码审查禁止新增散落色值。 |
| 宽表在窄屏溢出 | 使用受控横向滚动和粘性表头，不能压缩数值列。 |
| 视觉改造掩盖状态含义 | 盈亏、错误、数据缺失均同时保留文字和颜色。 |
| 全周期分钟 K 线传输过大 | 图表接口只请求选中交易日或有限时间窗口，禁止一次将整段回测的分钟数据返回浏览器。 |
| 信号时间与成交时间混淆 | 图表定位和标记使用 `executionTime（实际成交时间）`；悬浮说明单列 `signalTime（信号时间）`。 |
| 通过回测 ID 越权查看他人记录 | 新接口在后端按当前用户和 RLS 查询回测，未授权记录返回不存在，不泄漏其标的、时间或成交信息。 |
| 历史 K 线与原回测快照不一致 | 第一阶段标记以保存的成交记录为准，K 线读取当前 QMT 数据；严格复现需要额外保存可定位的数据版本或 Bar 快照，不能假装已经实现。 |
| 多个组件分别更新图表标记，导致标记被覆盖或残留 | 只允许 `useBacktestTradeMarkers` 写入交易点图层；切换回测或日期时先清空，再写入经过校验和排序的新标记。 |
| 快速切换回测、日期或标的时，旧请求晚于新请求返回 | 使用 `AbortController` 或请求序号丢弃过期响应；切换时立即清空旧标记和加载状态。 |
| 旧回测记录只有 `BUY / SELL`，没有开平动作 | 安全兼容为“买入 / 卖出”标记；不虚构开仓或平仓语义。 |
| 旧回测记录缺少成交时间、价格或数量 | 接口返回明确的“该历史记录不支持交易点复盘”状态；不猜测时间或静默画错位置。 |
| 一次性改动过大，难以定位问题 | 按第 7.2 节顺序拆分提交，每阶段完成构建和页面验证后再进入下一阶段。 |

## 11. 自审：交易点图层的难点与决策

### 11.1 这不是纯视觉改造

当前 `/api/chart` 按标的和日期读取图表数据，当前 `/api/backtest/runs/{runId}` 返回历史回测及其成交结果，但没有“以回测记录驱动图表”的接口。因此交易点图层需要新增一个受权限保护的只读接口，最小返回内容为：

- 回测上下文：用户自己的 `runId（回测唯一标识）`、`displayNo（展示编号）`、标的、周期、日期范围。
- 指定交易日或时间窗口的 QMT K 线。
- 已成交交易及其 `signalTime（信号时间）`、`executionTime（实际成交时间）`、买卖动作、成交价、数量和原因。

推荐按“`runId + date`”查询，而不是把整段回测的 1m 数据和全部标记一次返回。点击交易行时由该行的实际成交日期决定 `date（交易日）`。

### 11.2 时间与成交语义必须统一

当前回测尚未引入成交撮合，因此 `signalTime` 与 `executionTime` 相同；图表仍必须以 `executionTime` 绘制成交箭头，`signalTime` 仅作为说明。未来引入下一根 Bar 成交、滑点或撮合延迟后，两个时间可能不同，现有接口和图层语义无需重做。

### 11.3 历史复现边界需要明示

回测记录已保存策略、参数与数据哈希快照，但当前 ClickHouse 读取的是已导入 QMT 的现行数据。若未来重新导入并修订同一根 K 线，历史图形可能与原回测时的 K 线不同，但成交点仍对应原回测记录。

推荐分两阶段处理：

1. 第一阶段：展示不可变成交记录叠加当前 QMT K 线，并在数据版本不一致时提示“当前行情与回测快照可能不同”。
2. 严格复现阶段：在回测记录中保存可查询的数据版本，或保存回测实际使用的 Bar 快照；只有完成这一项后，才可宣称历史图表完全可复现。

### 11.4 性能与交互边界

- 单日 1m K 线约数百根，适合浏览器交互；数年分钟数据不适合一次加载。
- 首次进入交易点图层时默认定位到用户点击的交易日；日期切换才重新请求 K 线。
- 同一根 K 线上交易很多时必须聚合，避免文字标签遮挡 K 线和十字光标。
- 图表图层、交易明细和 URL 查询参数应共享同一 `runId（回测唯一标识）`、`date（交易日）` 和 `executionTime（实际成交时间）`，保证浏览器刷新后仍能回到相同位置。

### 11.5 完成前的验证清单

1. 对 1m、5m 回测分别验证每笔箭头落在实际成交 K 线和实际成交价附近；跨周期查看时验证标记吸附规则与真实成交时间提示。
2. 对买开、卖平、卖开、买平和部分平仓分别验证文字、方向、数量和悬浮内容；确认图层不展示跳过信号、手续费或盈亏。
3. 用两个不同账号验证：用户 A 不能通过修改 URL 中的 `runId` 查看用户 B 的任何 K 线或成交信息。
4. 对交易密集的一日验证聚合标记、展开列表和图表缩放性能。
5. 对历史记录重新导入修订后的 QMT 数据，验证版本不一致提示或严格复现机制符合实际实现。

## 12. 最终效果定义

最终系统应呈现为浅色主画布、深色结构层、紧凑且图表优先的 A 股回测工作台：用户在概览页快速判断策略表现，在交易和持仓页追溯结果，在历史页比较实验，在策略管理页完成下一次研究。界面应服务于研究判断，而不是把参数、卡片和装饰持续堆叠在屏幕上。
