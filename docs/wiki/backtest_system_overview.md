# 回测系统说明

## 1. 系统用途

本系统用于编写、保存和运行 A 股策略回测。它把用户账号、策略、方案和回测记录分开管理，并使用服务器已导入的 QMT 历史行情进行回测。

系统不提供自助注册。管理员创建账号、管理账号状态；每位用户只维护和查看自己的策略库与回测历史。

## 2. 使用入口

打开管理员提供的系统地址后会先进入登录页。使用管理员创建的用户名和密码登录即可。

首次部署的管理员登录信息由部署管理员单独保管，不应放在 Wiki、代码仓库或聊天记录中。管理员首次登录后应立即重置密码。

## 3. 账号与权限

### 管理员

- 创建账号、重置密码、启用或禁用账号。
- 使用自己的策略库、方案、账户和回测记录。
- 初始管理员策略库中保留一个可运行的均线示例策略。

### 普通用户

- 新建、修改和保存自己的策略脚本与回测方案。
- 运行并查看自己的回测记录。
- 管理自己的常用标的和回测账户。
- 不能查看或修改其他用户的策略代码、方案、账户和回测结果。

禁用账号不会删除该账号原有的策略和历史记录，只会阻止其继续登录。

## 4. 策略与方案

一次可执行回测由两部分组成：

- **策略脚本**：Python 代码，负责在每根 K 线到来时生成交易指令。
- **回测方案**：标的、周期、资金、手续费、滑点、交易方向和策略参数等配置。

使用流程如下：

1. 在“策略回测”页新建或选择策略脚本。
2. 填写策略名称、说明和 Python 代码。
3. 填写方案名称及回测参数。
4. 点击“保存策略”。
5. 选择日期范围后点击“运行回测”。

系统没有“草稿 / 发布版本”流程。保存后的当前内容可以直接回测；每次回测都会把当时的代码、方案参数和行情范围保存为快照。因此后续修改策略，不会改变已有历史结果。

策略脚本的入口函数为：

```python
def on_bar(bar, state):
  return []
```

`bar` 提供当前 K 线和当前持仓，`state` 用于保存策略运行状态。脚本返回订单列表；没有信号时返回空列表 `[]`。

支持的订单动作：

- `buy_open`：开多仓
- `sell_open`：开空仓
- `sell_close`：平多仓
- `buy_close`：平空仓

策略在独立执行容器中运行，不能访问服务器宿主机目录、系统数据库或其他用户的文件。

## 5. 行情数据与回测周期

行情来源是管理员事先从本地 QMT 导出并导入服务器 ClickHouse 的原始历史数据。

- 当前回测页面支持 `1m` 和 `5m` 周期。
- 导入数据后，所有用户可以共用同一份行情。
- 回测只读取已导入且覆盖完整的区间，不会在运行时请求东财、新浪或其他外部行情接口。
- 所选标的、周期或日期没有数据时，系统会提示缺失原因；请联系管理员补充对应 QMT 数据后再试。

“数据管理”页用于查看个人常用标的以及各标的的 QMT 数据覆盖情况。常用标的是个人配置，QMT 行情本身是全局共享数据。

## 6. 查看回测结果

回测完成后可查看：

- 收益、收益率、最大回撤、胜率等汇总指标。
- 权益曲线和基准曲线。
- 成交明细、每日持仓和资金变化。
- 本次回测使用的策略、方案和行情快照。

每位用户的回测记录从 `#01` 开始独立递增。该编号仅用于页面展示和日常沟通；系统内部仍使用唯一标识保存记录。其他用户的回测不会影响自己的编号。

## 7. 常见问题

### 为什么不能运行回测？

请依次检查：是否已保存策略方案、标的代码和日期范围是否正确、所选周期是否有完整 QMT 数据、策略脚本是否定义了 `on_bar(bar, state)`，以及订单数量是否为正整数。

### 为什么看不到其他人的策略或回测？

这是系统的权限隔离设计。每个账号只访问自己的策略库、方案、账户和回测记录。

### 为什么没有“发布新版本”按钮？

策略以当前保存内容为准。历史回测已经保留当时的完整快照，因此可以准确回溯，无需为每一次小改动创建版本。

### 为什么管理员不能删除账号？

系统使用“禁用”代替物理删除，避免账号的策略与回测历史被误删。

## 8. 使用边界

- 回测结果用于策略研究和验证，不构成交易建议。
- 数据覆盖范围以服务器已经导入的 QMT 原始文件为准。
- 行情导入、服务器部署、数据库迁移和容器维护由部署管理员处理，不在普通用户页面执行。
