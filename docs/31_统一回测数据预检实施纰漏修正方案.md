# 统一回测数据预检实施纰漏修正方案

## 一、目的与边界

本方案是 [30_统一回测数据预检与可用性引导方案](30_统一回测数据预检与可用性引导方案.md) 的实施修正，不改变 30 号方案的目标、数据安全边界和“保存完整策略前必须预检”的原则。

本次只修复已在本地测试发现的以下四项实施偏差：

1. 日期选择控件没有把缺失交易日置灰或禁止选择。
2. 预检将 Redis（内存缓存）中派生 Bar 的缓存未命中误判为原始数据缺失。
3. 标准 Bar 回测页面只显示 `1m`（1 分钟）和 `5m`（5 分钟）两个周期。
4. 回测区间包含未来交易日时，仍可能被错误判定为完整并允许保存策略。

不在本次范围内：导入或修复原始行情、修改撮合规则、调整 Redis TTL（缓存时长）、修改依赖清单或改写历史回测任务。

## 二、问题复盘与根因

| 偏差 | 现状根因 | 造成的结果 |
| --- | --- | --- |
| 日期未置灰 | 页面使用浏览器原生 `input[type=date]`（原生日期输入框）；它不支持禁用单个日期。现有灰色标签不属于日期选择面板。 | 用户只能在保存或运行时才知道日期不可用。 |
| Redis 聚合周期误判 | 预检只读取 `qmt_kline_coverage`（QMT K 线覆盖记录），而 `3m`、`15m` 等派生 Bar 的可用性来自 Redis 缓存或 L2 原始十档快照聚合。 | 缓存未命中或 QMT 无该周期覆盖时，被错误显示为数据缺失。 |
| 标准 Bar 周期过少 | `BACKTEST_TIMEFRAMES`（标准 Bar 回测周期白名单）仍是旧值 `1m、5m`，周期接口和页面均直接使用该白名单。 | 标准 Bar 无法选择已被统一 Bar 读取器支持的周期。 |
| 未来日期可保存 | 覆盖校验仅验证“已查到的记录是否为 complete（完整）”，没有按交易日历构造应覆盖日期集合并求差集。 | 未来交易日或中间无记录交易日不会被识别为缺失。 |

## 三、修正后的统一规则

### 3.1 周期与 Bar 来源

标准 Bar 和 L2 回放均展示以下运行周期：

```text
1m、3m、5m、15m、30m、45m、60m、1d
```

周期“受引擎支持”与“当前区间数据可用”必须分开表达：全部支持周期始终可见；当前数据不完整的周期置灰并说明缺少的数据类型。

派生 Bar 的来源规则如下：

| Bar 类型 | 权威原始输入 | 加速层 | 预检判定 |
| --- | --- | --- | --- |
| `1m` 及以上运行周期 | L2 原始十档快照 | Redis 中按 `symbol（标的）+ tradeDate（交易日）+ period（周期）+ aggregationVersion（聚合版本）+ mappingVersion（映射版本）` 缓存的聚合结果 | 先检查缓存；缓存未命中时检查原始十档快照按交易日的轻量覆盖元数据；不得因缓存未命中判缺失。 |
| 标准 Bar 回放 | 与统一 Bar 来源解析规则一致 | 同上 | 不要求 L2 撮合，但 Bar 本身必须完整。 |
| L2 盘口回放 | 完整 Bar + 原始十档快照 | 同上 | 在 Bar 完整外，再验证十档快照完整性；需要逐笔成交的执行配置再增加 Trade 覆盖。 |

Redis 是派生结果缓存，不是数据完整性的唯一依据。缓存命中可直接确认对应交易日可用；缓存未命中必须转为原始 L2 快照覆盖查询，而不是直接显示缺失。

### 3.2 交易日全集和未来日期

对任一预检请求，后端先从交易日历取出 `[startDate, endDate]`（开始日期、结束日期）内全部应交易日期，再逐日匹配 Bar、Quote（十档快照）和必要的 Trade（逐笔成交）状态。

规则：

1. 非交易日不属于缺失日期，沿用现有日期语义。
2. 日期晚于当前上海日期的交易日直接视为不可用；不依赖数据表中是否意外存在记录。
3. 当前日和历史交易日没有完整覆盖记录时均视为缺失。
4. 查询返回的少量完整记录不能证明整个区间完整；必须以“应交易日期集合减去完整日期集合”的差集为准。
5. 当交易日历不可用时，预检结果为 `unknown`（待确认），保存和提交一律拒绝，不能降级为可用。

## 四、目标设计

### 4.1 后端预检模型

将预检结果固定为按周期、按交易日的事实模型：

```text
PreflightResult
  status: available | incomplete | unknown
  timeframes[]
    timeframe
    status
    missingDataTypes[]
    missingDates[]
  calendarDays[]
    date
    tradingDay
    status: available | incomplete | future | non_trading | unknown
    missingDataTypes[]
  checkedAt
  dataSourceVersion
```

普通页面文案仅使用 `missingDataTypes`（缺失数据类型），例如“缺少 L2 十档快照”；`missingDates`（缺失日期）仅提供给日历置灰和管理员诊断。

预检服务拆分为四个内部适配器：

1. `TradingCalendarResolver`（交易日历解析器）：给出应交易日期全集和未来日期。
2. `DerivedBarAvailabilityResolver`（派生 Bar 可用性解析器）：读取 Redis 缓存键状态，并对缓存未命中日期做单次按日聚合覆盖查询。
3. `QuoteAvailabilityResolver`（十档快照可用性解析器）：按日期聚合 L2 原始快照的覆盖与质量。
4. `TradeAvailabilityResolver`（逐笔成交可用性解析器）：仅在执行配置需要时参与。

页面预览只调用轻量适配器，不拉取完整行情明细。保存/提交前复用同一个预检服务；Runner 仍执行实际读取作为最终兜底。

### 4.2 日历交互

以自定义双月日期面板替换三处回测参数中的原生日期输入框，三处共用同一个 `BacktestDateRangePicker`（回测日期区间选择器）组件。

交互规则：

1. 打开日期面板时，按当前标的、模式、周期加载当前展示月份及相邻月份的 `calendarDays`。
2. `incomplete`（数据不完整）和 `future`（未来）交易日统一灰色、不可点击，并附带无障碍说明。
3. `non_trading`（非交易日）维持与缺失交易日不同的视觉样式，避免用户误以为周末是数据故障。
4. 若当前已选区间后来包含不可用日期，在日期区域显示区间不完整状态；保存和运行守卫保持拦截。
5. 周期下拉不展示具体日期；右下角只提示缺失数据类型。日历承担“哪天不可用”的信息职责。

### 4.3 周期矩阵与标准 Bar

1. 引入唯一的 `BAR_RUN_TIMEFRAMES`（统一 Bar 运行周期）配置，标准 Bar 与 L2 模式均从此配置取周期。
2. 删除页面以旧 `BACKTEST_TIMEFRAMES`（旧标准周期白名单）构建周期选项和数据状态的逻辑。
3. 标准 Bar 的每一个周期均由 `DerivedBarAvailabilityResolver`（派生 Bar 可用性解析器）判定；L2 模式在此基础上再增加 Quote/Trade 要求。
4. 周期矩阵始终展示全部支持周期；可用周期正常显示，不完整周期显示“缺少 Bar 数据”“缺少 L2 十档快照”等类型说明并置灰。

### 4.4 保存、提交与原子性

策略页面当前先保存脚本、再保存策略配置；仅在后一步校验会留下“代码已保存、完整策略未保存”的半完成状态，不符合 30 号方案目标。

修正为 `save-complete-strategy`（保存完整策略）原子接口：

1. 接收脚本、参数、标的、周期和日期范围。
2. 先执行权威预检；`incomplete` 或 `unknown` 返回结构化 HTTP `422`，不写入脚本、配置或版本。
3. 预检通过后在同一事务中写入脚本和策略配置/版本快照。
4. 网页保存按钮只能调用该接口；旧的独立脚本接口保留给“不构成完整策略”的脚本草稿用途，不能绕过完整策略保存规则。
5. 网页/API 回测提交前再次调用同一预检服务；任何缺失或未来交易日均不得创建任务。

## 五、实施步骤

1. 补齐交易日历读取器，定义未来日期和交易日历不可用的失败语义；先为未来日期、区间中间缺口、周末边界写测试。
2. 将 Redis 聚合缓存检查和原始 L2 快照按日覆盖查询抽为派生 Bar 可用性适配器；实现缓存命中、缓存未命中但可聚合、原始快照缺失三种结果。
3. 以统一 Bar 运行周期配置替换标准 Bar 的 `1m、5m` 白名单、数据状态接口与前端周期选项；保留 L2 特有 Quote/Trade 依赖。
4. 重构预检接口：返回周期矩阵和月度 `calendarDays`，支持页面按月加载，不因查看日历拉取完整行情。
5. 实现可复用自定义日期区间组件，并替换所有回测开始/结束日期编辑入口；实现灰色不可选日期、未来日期和非交易日的视觉区分。
6. 增加完整策略原子保存接口，将网页保存操作迁移至该接口；在网页/API 提交与两个 Runner 保持同一预检规则。
7. 更新错误映射与前端右下角提示；数据错误不显示内部细节、日期列表或“系统异常”。
8. 补齐单元、接口、前端交互和服务器集成测试；通过后再发布所有相互依赖服务。

## 六、验收标准

1. 选择日期时，缺失交易日和未来交易日在日历中灰色且无法点击；非交易日视觉上可区分。
2. 任何包含未来交易日、历史缺失交易日或数据质量不合格交易日的区间，均无法保存完整策略、无法提交回测、无法进入队列。
3. Redis 缓存未命中但原始 L2 十档快照完整时，预检显示可用；缓存命中不触发原始聚合查询。
4. Redis 缓存未命中且原始快照不完整时，预检准确置灰对应日期并只说明“缺少 L2 十档快照”等数据类型。
5. 标准 Bar 和 L2 页面均显示 `1m、3m、5m、15m、30m、45m、60m、1d`；标准模式不再受旧 `1m、5m` 白名单限制。
6. 完整策略预检失败时，数据库中不新增脚本、策略配置、版本或回测任务。
7. 页面预览仅执行交易日历、Redis 键检查和按日覆盖聚合查询；不读取完整 Quote/Trade 明细。
8. Runner 在预检结果过期或数据源变化时仍以 `data.*`（数据错误）安全拒绝。

## 七、风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 自定义日期组件引入边界错误 | 使用单一组件替换所有回测日期入口，并补充键盘操作、跨月、周末、未来日期测试。 |
| Redis 未命中导致预检变慢 | 对同一标的、模式、周期、月份使用短 TTL 缓存；未命中仅做按日覆盖聚合，不读取明细。 |
| 交易日历缺失造成错误放行 | 交易日历不可用统一为 `unknown`，禁止保存和提交。 |
| 标准模式扩展周期改变来源语义 | 每项任务保存最终来源和聚合/映射版本；禁止跨来源拼接。 |
| 原子保存接口影响旧页面 | 先保留草稿接口，页面迁移完成并通过回归后才限制旧完整策略保存路径。 |

## 八、执行前确认

执行将修改后端预检、交易日历和统一 Bar 周期配置，新增或调整完整策略原子保存接口，替换回测页面日期控件，并修改相关测试；不修改原始行情、Redis 中已有缓存内容、依赖清单或服务器私有配置。
