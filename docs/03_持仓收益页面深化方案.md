# 持仓收益页面深化方案

## 1. 目标

将“持仓收益”从每日快照表升级为回测期间的仓位与资产归因视图。用户应能判断某日资金处于空仓、做多或做空状态，并看清现金、持仓市值、总资产和日盈亏的关系。

本页面只解释已完成回测产生的持仓快照，不新增实时持仓、模拟盘或实盘交易功能。

## 2. 当前问题

- 页面当前以宽表直接列出每日数据，难以快速把握仓位变化与资金暴露。
- 总资产、净市值、现金和日盈亏缺少摘要层级，用户需要逐行读取。
- 空仓、做多、做空等仓位状态不够突出，难以识别持仓切换的日期。
- 宽表在窄屏下虽然可横向滚动，但缺乏阅读引导。

## 3. 设计方案

### 3.1 页面结构

保留现有结果上下文条，页面由三层组成：

1. **资产摘要区**：显示期末总资产、期末现金、期末净市值、累计盈亏和持仓天数；数据直接来自已有每日持仓快照。
2. **仓位演变区**：用紧凑的时间序列展示多头数量、空头数量与净市值变化，强调仓位由零转为非零、方向反转和回到空仓的节点。
3. **每日资产账本**：保留当前每日表格，按“日期、仓位、资金与市值、总资产、日盈亏”分组显示。

### 3.2 状态与数值规则

| 内容 | 展示规则 |
| --- | --- |
| 空仓 | 中性灰色，显示“空仓” |
| 净多仓 | 使用低饱和红色状态标记，符合 A 股收益习惯 |
| 净空仓 | 使用低饱和绿色状态标记 |
| 日盈利 | 红色数值 |
| 日亏损 | 绿色数值 |
| 现金与总资产 | 使用等宽数字与右对齐，便于比较 |

净市值为已有快照中的多头市值与空头市值净额；不在前端重新计算回测资产或收益。

### 3.3 交互与响应式规则

- 新增日期范围与仓位状态筛选，只过滤现有快照，不重新运行回测。
- 表头保持可见；桌面端允许按日期查看，窄屏保留横向滚动并固定日期、仓位与总资产等关键列。
- 用户可在“资金构成”和“资产账本”两种密度间切换；切换仅影响显示，不影响任何结果数据。
- 无每日持仓快照时，明确提示需运行回测，并说明该页面展示的是历史快照而非实时账户。

## 4. 实现边界

本阶段只使用现有 `result.dailyHoldings` 数据，调整 `frontend/src/components/BacktestPage.tsx` 与 `frontend/src/styles/global.css`。

不修改：

- 回测引擎的持仓、估值、手续费、滑点和日盈亏计算；
- 后端 API、数据库、历史回测快照结构；
- 策略脚本与交易信号生成逻辑；
- 实时账户、模拟盘或实盘能力。

## 5. 验收标准

- 用户可在不逐行阅读表格的情况下确认期末资产与仓位状态。
- 仓位切换、空仓日和显著日盈亏能在视觉上快速识别。
- 过滤与显示密度切换不会改变回测结果或原始快照。
- 无数据状态能清楚说明数据来源与下一步操作。
- 前端测试、TypeScript 构建和差异检查通过。
