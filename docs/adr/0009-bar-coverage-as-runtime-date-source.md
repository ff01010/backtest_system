# ADR 0009：Bar 覆盖是回测运行日期的唯一事实来源

- 状态：已接受
- 日期：2026-09-28（同日修订旧 QMT 来源退役语义）
- 取代：ADR 0002、ADR 0003、ADR 0004 中依赖交易日历识别正式日期和预热候选日的部分

## 决定

当前单标的回测没有独立市场时钟，只有实际 Bar 才会触发策略事件。因此，标准 Bar、L2 回放和预热统一以任务选定的单一 Bar 来源为日期事实：正式日期取请求区间内状态完整且实际可加载的 Bar 日期；预热日期取同一来源在正式开始日前最近 `N` 个状态完整的日期；L2 十档摘要只校验实际回放 Bar 日期。

Worker 必须按所选来源的 `firstDate/lastDate` 校验 `sourceFirstDate <= startDate <= endDate <= sourceLastDate`。边界内没有 Bar 的周末、休市日或停牌日不生成回调，也不单独阻断任务；范围越界、范围内无完整覆盖、覆盖存在但实际 Bar 为空、来源读取失败和预热不足仍是不同的内部失败原因。

新任务快照继续记录 Provider、物理库表、来源周期、派生规则、正式日期、预热日期和版本信息。快照指向当前受支持来源时按冻结来源读取，不根据当前默认值重算或改写。尚未执行的任务如果快照指向已退役的 QMT 数据库，则明确失败；平台不为保持旧快照可执行而保留已退役数据库的运行依赖，发布前必须先排空或处理这类任务。已完成任务继续读取已保存结果。

交易日历不再参与回测预检、执行、预热、L2 摘要预热或发布门禁。历史 `market_trade_calendar` 表及数据保留，仅用于旧版本回滚兼容。

## 后果

- 行情覆盖与实际 Bar 日期成为当前执行模型的唯一运行日期事实，消除行情与日历更新不同步导致的误拒绝。
- 系统不承诺识别交易所开市但整日漏采的情形；该完整性由行情导入、发布和质量校验链路负责。
- 如果未来引入多标的组合、无 Bar 日事件或统一估值时钟，应作为新的市场时钟领域能力设计，不能直接把历史日历表重新接回 Worker。
