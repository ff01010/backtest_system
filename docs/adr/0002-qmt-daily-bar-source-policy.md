# ADR 0002：标准 QMT Bar 的单一来源选择

- 状态：已接受
- 日期：2026-08-29（2026-09-23 修订标准 Bar 行情质量边界）

## 决定

标准 QMT Bar 链路不改变 L2 映射链路。界面只展示元数据声明的可回测范围，保存和提交不做行情完整性预检。Worker 按标的已发布的覆盖日期选择单一来源：沪、深、北交所统一优先使用 `qmt_history_dev` 对应的原生六周期表；新库在请求区间内无可用日期或预热天数不足时，整次任务回退到 `raw_historical_data.qmt_kline`。两者均不足时任务执行失败，并向用户统一提示“行情数据异常，请联系管理员”。

两套完整度语义保持独立：新库由 `qmt_ingest_runs` 的发布校验结果与 `qmt_universe_snapshot` 的标的成员关系共同表达可用范围，旧库沿用 `qmt_kline_coverage` 的 `complete` 状态。保存和提交不依赖交易日历；Worker 执行阶段使用交易日历识别开市日、寻找预热候选日，但不因某标的在开市日没有 Bar 就判定行情缺失（例如停牌）。标准 Bar 回放读取所选来源中已定稿的原始行，不按 `quality_status` 筛选，不核对已选覆盖日期是否逐日都有实际 Bar；完全无 Bar、字段无法解析或查询失败仍属于执行错误。行情质量由数据发布与维护流程负责，L2 质量规则不在本次变更范围内。

页面范围查询同样遵循来源优先级：新版元数据存在该标的时只展示新版范围，不查询或合并旧版范围；仅当新版查询成功但明确没有该标的时，才展示旧版范围。查询超时和临时网络错误使用有限重试；重试耗尽或发生 SQL、权限、表结构等确定性错误时按数据源异常终止，不能按“无标的”静默回退。

## 后果

- 同一任务不会跨新旧数据库或不同原始周期拼接数据。
- 平台 `60m` 映射新库物理 `1h`；`3m`、`45m` 在所选数据库内由完整 `1m` 数据派生。
- L2 日线复用需求需独立评审，避免扩大本期回归范围。
