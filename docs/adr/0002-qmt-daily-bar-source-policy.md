# ADR 0002：标准 QMT Bar 的单一来源选择

- 状态：已接受
- 日期：2026-08-29（2026-09-22 更新范围展示与执行时机）

## 决定

标准 QMT Bar 链路不改变 L2 映射链路。界面只展示元数据声明的可回测范围，保存和提交不做行情完整性预检。Worker 实际执行时先计算预热与正式区间合并后的目标范围，再选择一个完整覆盖该范围的来源：沪、深、北交所统一优先使用 `qmt_history_dev` 对应的原生六周期表；新库不能覆盖时，整次任务回退到 `raw_historical_data.qmt_kline`。两者均不足时任务执行失败，并向用户统一提示“行情数据异常，请联系管理员”。

两套完整度语义保持独立：新库由 `qmt_ingest_runs` 的发布校验结果与 `qmt_universe_snapshot` 的标的成员关系共同表达可用范围，旧库沿用 `qmt_kline_coverage` 的 `complete` 状态。保存和提交不依赖交易日历；Worker 执行阶段使用交易日历确定请求范围内应读取的交易日，并在实际加载后拒绝缺日结果。

页面范围查询同样遵循来源优先级：新版元数据存在该标的时只展示新版范围，不查询或合并旧版范围；仅当新版查询成功但明确没有该标的时，才展示旧版范围。查询超时和临时网络错误使用有限重试；重试耗尽或发生 SQL、权限、表结构等确定性错误时按数据源异常终止，不能按“无标的”静默回退。

## 后果

- 同一任务不会跨新旧数据库或不同原始周期拼接数据。
- 平台 `60m` 映射新库物理 `1h`；`3m`、`45m` 在所选数据库内由完整 `1m` 数据派生。
- L2 日线复用需求需独立评审，避免扩大本期回归范围。
