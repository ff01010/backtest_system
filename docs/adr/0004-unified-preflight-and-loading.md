# ADR 0004：范围展示与实际加载的职责分离

- 状态：已接受
- 日期：2026-08-29（2026-09-22 修订）

## 决定

此前“日期可用性、保存校验、提交校验和 Worker 共用完整性预检”的决定由本修订取代。页面只读取覆盖元数据并展示可回测起止日期；保存和提交不做行情完整性预检。Worker 执行阶段使用交易日历识别开市日和预热候选日，以标的覆盖元数据选取实际回放日期；标准 Bar 不比较日历、覆盖及实际 Bar 的逐日集合来推断行情缺失，完全无可回放 Bar 或读取失败仍终止任务。

Bar 页面范围不合并新旧来源：优先展示 `qmt_ingest_runs` 与 `qmt_universe_snapshot` 声明的新版范围，只有新版查询成功且没有该标的时才查询并展示 `qmt_kline_coverage` 的旧版范围。单一来源查询对超时和临时网络错误进行有限重试；重试耗尽后终止范围查询，不切换来源掩盖故障。

日期滚轮和快捷操作只修改本地草稿，不在编辑过程中校验。用户点击“应用”时，页面使用已经取得的范围元数据校验 `可回测开始日期 ≤ 选择开始日期 ≤ 选择结束日期 ≤ 可回测结束日期`；两个端点均可选取。校验失败时保留草稿并提示，不更新正式回测参数，也不新增行情查询。

## 后果

- 页面范围查询不扫描原始 Bar 或 L2 行情；“应用”只校验所选闭区间是否落在元数据范围内，保存和提交仍不执行行情完整性预检。
- 范围是元数据声明的日期边界，不承诺范围内每次执行成功。
- Worker 保留独立错误码和完整服务端诊断，对用户统一显示“行情数据异常，请联系管理员”。
