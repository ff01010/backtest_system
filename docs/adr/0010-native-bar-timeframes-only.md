# ADR 0010：回测仅提供数据库原生 Bar 周期

- 状态：已接受
- 日期：2026-10-14
- 取代：ADR 0002 中由 `1m` 派生 `3m`、`45m` 的决定

## 决定

标准 Bar 与 L2 回测统一只接受 `1m`、`5m`、`15m`、`30m`、`60m`、`1d`。标准 Bar 分别读取 `qmt_history_dev` 的 `1m`、`5m`、`15m`、`30m`、`1h`、`1d` 原始表，平台 `60m` 映射物理 `1h`；运行时不再读取 `1m` 后聚合 `3m`、`45m`。

ClickHouse 行仍转换为 DataFrame，用于时区转换、数值类型规范化、稳定排序、日期边界、重复值和非有限值校验。该规范化步骤不改变 Bar 周期，也不执行 `groupby` 聚合。任务快照与预检响应继续保留 `derivation` 字段，新任务固定记录 `null`，避免改变既有读取契约。

页面、完整策略保存、开放 API、普通回测提交、L2 Provider 和共享策略复制使用同一周期白名单。已保存的 `3m`、`45m` 方案继续可读，页面必须保留原值并明确提示已停止支持，不能静默迁移；用户主动选择原生周期并重新保存后方可运行。已完成任务继续读取已保存结果、参数、快照和共享详情，但不能重新执行，也不为 K 线复盘重新生成派生行情。

L2 回放仍需把三秒快照整理为所选原生周期 Bar，这是盘口回放的事件模型，不恢复 QMT 的跨周期派生能力。`3m`、`45m` 不再进入 L2 分桶或缓存路径。

## 后果

- 标准行情查询量与 Worker 内存不再因派生周期扩大，回测性能只受请求的数据库原生周期数据量影响。
- 用户失去 `3m`、`45m` 新建、保存、复制、重跑和图表重建能力，历史已保存结果仍保持可读。
- 不需要数据库迁移；旧派生缓存不再读取，按既有过期策略自然淘汰。
- 发布必须同批更新 Backend、Bar Runner、L2 Runner 和前端，并在发布前排空、取消或经确认处理仍在排队或运行的 `3m`、`45m` 任务。
