# L2 回测结果字段兼容修复方案

## 1. 问题背景

L2 回测会话隔离改造后，`l2-runner` 与单任务策略会话通过 Pipe 传输 Python 对象。成交记录中的 `OrderSide` 枚举不再经过 HTTP JSON 编码器自动转换，适配层将其转为字符串后得到 `OrderSide.BUY`、`OrderSide.SELL`。

前端信号明细与信号可视化接口约定的方向字段为 `BUY`、`SELL`。字段不一致导致买入被显示为卖出，图表接口将成交记录视为不兼容并过滤，最终没有买卖点。

## 2. 目标与边界

- 将 L2 回测结果中的方向字段统一为 API 契约值 `BUY`、`SELL`。
- 兼容已经保存的历史 L2 回测结果，不修改数据库记录，也不要求重新回测。
- 修正图表接口的异常记录统计，使字段不兼容时返回明确错误而非静默空点位。
- 不修改策略脚本、委托规则、盘口撮合、价格、数量、收益计算或并发模型。

## 3. 实施方案

### 3.1 结果适配层归一化

在 `backend/l2/result_adapter.py` 新增方向字段归一化：

- `OrderSide.BUY` 与 `BUY` 统一为 `BUY`。
- `OrderSide.SELL` 与 `SELL` 统一为 `SELL`。
- 新产生的成交记录、跳过信号和历史结果中的 `trades`、`skippedSignals` 均经过同一规则。

归一化位于引擎结果到 API 结果的边界，避免依赖 HTTP、Pipe 或未来其他传输方式的隐式序列化行为。

### 3.2 信号可视化校验

图表接口使用紧凑日期 `YYYYMMDD` 判断成交是否属于当前交易日。字段不兼容时正确计入异常数量，由既有接口返回清晰提示，不再静默返回空点位。

### 3.3 历史兼容

读取 L2 历史任务时仍会经过结果适配层，因此发布后重新打开历史任务即可展示正确方向和点位，无需数据迁移。

## 4. 验证项

- 枚举字符串 `OrderSide.BUY/SELL` 可转换为 `BUY/SELL`。
- 标准 `BUY/SELL` 保持不变。
- 已保存结果的成交与跳过信号均可被重新规范化。
- 图表接口可接受规范化后的买开、卖平、卖开、买平记录。
- 图表接口对不兼容字段在同一交易日正确报告异常。
- 执行 L2 相关单元测试与图表接口测试。

## 5. 发布注意事项

本次变更涉及后端接口返回结构与历史结果读取。服务器应通过 `scripts/deploy-server.sh` 同批发布 backend、l2-runner 与 frontend；发布前检查运行中的 L2 任务，避免重建 runner 中断任务。发布后抽查 #104 等历史任务的信号明细方向和图表点位。
