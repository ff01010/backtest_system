# 系统错误分类与管理员诊断日志改造方案

日期：2026-08-17  
状态：已确认，实施中

## 1. 问题

当前管理员系统日志只对少量网络异常分类；其余错误统一显示为 `system.unclassified（未分类系统错误）`。例如 `ResponseNotReady: Request-sent` 是明确的 ClickHouse HTTP 连接状态问题，却没有错误编码、具体原因或正确的重试建议。

普通用户需要安全提示，不应看到堆栈和内部服务信息；管理员则需要足够的脱敏诊断信息定位问题。

## 2. 目标

1. 为每类系统错误提供稳定的 `errorCode（错误编码）`、`category（错误分类）` 与 `retryable（是否可重试）`。
2. 管理员日志保存 `reason（管理员原因）`、`exceptionType（异常类型）`、`context（上下文）` 与 `rawLogRef（原始日志索引）`。
3. 普通用户仅看到安全中文提示、是否建议重试和任务编号。
4. 不保存或直接展示无限制原始容器日志、SQL、凭据、内部 URL 或 Python 堆栈。
5. 兼容历史 `system_error_log（系统错误日志）` 记录。

## 3. 错误目录

| 分类 | 错误编码示例 | 可重试 |
| --- | --- | --- |
| ClickHouse 网络 | `clickhouse.host_unresolved`、`clickhouse.connection_refused`、`clickhouse.timeout` | 按编码定义 |
| ClickHouse 连接状态 | `clickhouse.connection_state_invalid` | 否 |
| ClickHouse 查询/响应 | `clickhouse.query_failed`、`clickhouse.response_invalid` | 按编码定义 |
| 数据可用性 | `data.unavailable`、`data.mapping_invalid` | 否 |
| 缓存 | `cache.unavailable`、`cache.protocol_invalid` | 通常是 |
| 策略 worker | `worker.unavailable`、`worker.timeout`、`worker.execution_rejected` | 按编码定义 |
| 任务执行 | `job.lease_lost`、`job.queue_unavailable` | 按编码定义 |
| 配置 | `config.invalid`、`config.missing` | 否 |
| 未预期内部异常 | `internal.unexpected` | 否 |

本次 `ResponseNotReady` 应映射为 `clickhouse.connection_state_invalid（ClickHouse HTTP 连接状态异常）`，`retryable（是否可重试）` 为 `false（否）`。

## 4. 数据与接口契约

系统错误日志新增以下字段：

| 字段 | 含义 |
| --- | --- |
| `category` | 受控错误分类。 |
| `retryable` | 对相同任务直接重试是否合理。 |
| `raw_log_ref` | 容器、任务和阶段组成的原始日志检索索引。 |

历史记录通过数据库默认值显示为 `internal（内部）`、不可重试、无原始日志索引。管理员 API 返回全部字段；普通回测失败接口继续只返回安全的 `errorDetail（结构化错误详情）`。

## 5. 管理员页面

列表展示错误编码、分类、可重试状态和管理员原因，支持按错误编码筛选。详情展示异常类型、来源、阶段、上下文和可复制的 `rawLogRef（原始日志索引）`。

页面不直接读取 Docker 日志；运维人员使用日志索引在受控服务器环境中查询完整堆栈。

## 6. 实施步骤

1. 新增数据库迁移，扩展 `system_error_log（系统错误日志）`。
2. 建立后端错误目录，将底层异常映射为受控记录。
3. 补充任务 ID 到日志索引，避免只凭时间窗口排查。
4. 扩展管理员 API 类型和页面详情。
5. 为 ClickHouse 连接状态、网络、worker、未知异常和历史记录编写测试。
6. 更新策略使用手册中的管理员排错说明。

## 7. 验收

- `ResponseNotReady` 显示为 `clickhouse.connection_state_invalid`，不可重试。
- 管理员可通过页面看到分类、原因、异常类型、阶段和日志索引。
- 普通用户不接触内部错误正文或日志索引。
- 历史日志与失败任务仍能正常读取。
- 错误分类与可重试规则均由自动化测试覆盖。
