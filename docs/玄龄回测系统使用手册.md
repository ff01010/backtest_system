# 玄龄回测系统使用手册

> 版本：1.0  
> 适用对象：在策略代码编辑器中编写、回测或维护 K 线策略的使用者和维护者。

## 1. 先读这一页

策略代码编辑器采用“已完成 K 线触发、返回委托列表”的方式运行。系统在每根指定周期 K 线结束后调用策略函数，策略读取当前 K 线和账户快照，再返回本根 K 线需要执行的委托。

### 1.1 先记住这 6 条

1. 只使用**已完成**的 Bar；不能把未收盘价格当作确认信号。
2. 每次回调必须返回委托列表；没有委托时返回 `[]`，不能省略 `return`。
3. 默认“标准 Bar 回放（快速）”在本 Bar 收盘生成信号，并在下一根可交易 Bar 的开盘价加 `slippage（滑点）` 成交；这不等于实盘成交价。
4. L2 订单只能使用**严格晚于**信号 Bar 或信号快照的后续十档盘口成交；同一时间戳绝不成交。
5. 当天买入不会增加 L2 的当日可卖数量；科创板 `688/689` 标的开仓至少 200 股。
6. 策略错误会给出可修改提示；系统错误只展示任务编号，需由维护人员在系统错误日志或容器日志中定位。

### 1.2 普通 Bar 回测

- `on_bar(bar, state)`（K线回调函数）会在每根**已完成**的当前所选周期 K 线上调用一次。
- 默认标准模式中，信号在本 Bar 收盘时生成；买入在下一根可交易 Bar 开盘价基础上上调滑点，卖出在该开盘价基础上下调滑点。午间信号会在下午首根 Bar 开盘成交；最后一根 Bar 的新开仓信号不会跨任务成交。
- `bar_close（Bar 收盘成交）` 已废止。历史任务仍按原始结果展示，但重新运行时统一使用标准 Bar 回放，不能按旧规则复现。
- `bar`（当前K线及账户数据）可读取 `time`、`datetime`、`tradeDate`、`hhmm`、OHLC、`volume`、`cash`、`equity`、`position`、`strategyPosition`、`basePosition`、`sellableQuantity`、`t0AvailableQuantity` 和 `params`。
- `time` 固定为 `YYYYMMDDHHMMSS`；`tradeDate` 固定为 `YYYY-MM-DD`；交易时段判断使用 `hhmm`，例如 `931`。

### 1.2.1 指标预热与连续历史数据

标准 Bar 自定义策略如需在正式区间开始前初始化指标，应在代码模块顶层声明整数常量，例如 `WARMUP_TRADING_DAYS = 140`。系统不会在前端显示或允许编辑该值；保存策略时写入版本快照，运行时重新从代码解析。

预热 Bar 仅用于更新策略内部状态，不产生订单、成交、费用或收益。系统要求正式开始日前紧邻的预热交易日均有完整数据；出现任何缺口时任务会明确报错，而不会跳过缺失日期继续运行。未声明时默认不预热。`l2_quote（基础L2盘口回测）` 不支持声明大于 `0` 的预热交易日。

### 1.3 L2 回放与成交

- 选择 `l2_quote（基础L2盘口回测）` 后，`on_bar` 仍在已完成 Bar 结束时调用，但订单不再按本 Bar 收盘价直接成交。
- L2 回放在创建策略会话前，会一次性检查每个实际 Bar 交易日是否至少有一条连续竞价有效盘口；缺失日期会立即拒绝任务，不会用旧盘口、收盘价或零价替代。
- `slippage（滑点）` 仅用于标准 Bar 的虚拟成交；L2 以十档最优可成交价和可用深度撮合，不再额外叠加固定滑点，避免重复计入买卖价差。
- 结果中的“有效委托数”是撮合接受的订单数；“成交笔数”是实际成交记录数。同一 L2 委托分次成交时，成交笔数可能大于有效委托数。
- 市价单和可立即成交的限价单，按后续十档盘口逐档撮合；允许部分成交、继续等待后续快照或日终撤单。
- 定义 `on_quote(quote, state)`（3秒盘口回调函数）后，脚本自动使用 `continuous（连续快照）`：每条可见 3 秒快照依时间顺序回放，先处理旧订单与成交回报，再调用当前 `on_quote`。
- `on_quote` 新产生的订单只能从**下一条**快照开始成交。未定义 `on_quote` 时保持 `order_driven（订单驱动）`，无待成交订单的区间不会读取盘口。
- `on_order_event(event, state)`（委托回报回调函数）用于根据部分成交、完全成交、拒绝或撤单更新状态；不要在提交订单时假定已成交。
- 3 秒快照只表达可见采样点，不能替代一秒 Tick 或逐笔成交 `tick_data`。

### 1.4 执行方式：立即成交与 TWAP

- `immediate（立即成交）` 是默认方式。策略产生委托后，标准 Bar 使用下一根可交易 Bar 的开盘价加滑点成交；L2 使用严格晚于信号时点的第一条可成交盘口撮合。
- `twap（时间加权执行）` 仅可在 L2 盘口回放中使用。系统将一条策略委托拆为等时间间隔的子单，并且每个子单只可使用其计划时点之后的 3 秒盘口成交。
- TWAP 参数位于回测参数的“执行方式”，不传给策略脚本：执行时长、子单间隔（必须为 3 秒倍数）、最小子单数量。执行窗口结束未成交部分会撤销，不会进入后续时段。
- “信号明细”会保留实际子单成交，并在“执行追溯”中显示每个母单的申请、成交、撤销和拒绝数量。图表仍按实际成交绘制。

### 1.5 Bar 聚合、价格与缓存

- Bar 来源按“正式映射 Bar 表 → QMT 原生或派生 K 线 → `quant.tick_quote（L2三秒十档快照表）` 临时聚合”选择；一个任务只使用其中一个来源。临时聚合支持 `1m/3m/5m/15m/30m/45m/60m/1d`。
- 分桶只覆盖连续竞价 `09:30–11:30` 与 `13:00–14:57`；上午、下午分别从时段起点对齐。`14:57–15:00` 集合竞价不使用十档盘口撮合或聚合。
- `45m` 保留时段尾部 Bar；日线合并上午和下午连续竞价时段。仅已收盘历史交易日可运行。
- Bar 无有效价格或出现负量额会明确失败，不会退回为收盘价成交；快照间隔仅作观测，不决定 Bar 是否可用。
- 聚合 Bar 按规则和映射版本隔离缓存到 Redis；缓存淘汰或不可用时自动从 ClickHouse 重建，回测语义不变。
- `last_price（最新价）` 使用元价格；十档 `bid_price_*（买价）`、`ask_price_*（卖价）` 使用万分之一元整数，适配器会统一换算为元。

### 1.6 策略类别与账户规则

- `directional_holding（方向性持仓策略）` 可开多、开空或平仓后跨日持有真实仓位；使用“持仓收益”评价方向判断与买入持有结果。
- `core_position_overlay（底仓增强策略）` 围绕固定底仓做日内 T，日终保留底仓；可选择标准 Bar 回放或 L2 盘口回放，使用“底仓增强收益”评价相对底仓的增厚收益。
- `allowShort（允许做空）` 同时决定策略能否产生开空信号，以及 L2 撮合是否接受开空委托。
- 底仓增强策略中，`initialCapital（初始资金）` 是独立可用现金；底仓成本不从其中扣除，但总收益和回撤起点会计入底仓初始市值。
- 账户分别记录 `baseQuantity（底仓数量）`、`longQty（策略开多仓位）` 与 `shortQty（策略开空仓位）`。`t0Enabled（启用底仓做T）` 时，所有开多、开空成交都会消耗 `t0AvailableQuantity（当日做T剩余额度）`；平仓不会恢复额度。
- 尾盘会将策略多仓、策略空仓分别清零，只保留底仓。标准 Bar 模式按尾盘收盘价结算；L2 模式若封板、盘口缺边或深度不足，则以最后可观察最优价生成明确标识的强制结算；这是回测假设，不代表实盘可成交订单。

### 1.7 结果、日期与错误处理

- 当前费用使用全局“默认 A 股费用”：佣金 `0.008%`（单笔委托最低 5 元）、过户费 `0.001%`（双边）、印花税 `0.05%`（仅卖出）。成交明细会记录实际费用；L2 同一委托分次成交时，最低佣金只在该委托的累计佣金不足时补收。
- L2 回测是异步任务：页面自动轮询，成功后自动打开概览和信号明细。明细会保留成交、方向限制跳过、撮合拒绝、日终撤单及部分成交的剩余数量。
- L2 首版不计算基准曲线，超额收益显示为 `--` 并在结果告警中说明。
- `directional_holding` 展示实际持仓、组合收益、基准收益与超额收益；`core_position_overlay` 展示总账户收益、底仓持有收益和做 T 超额收益。
- 收益详情默认筛选本次回测起止日期，并展示初始总资产与期末总资产。方向性持仓策略的初始总资产等于初始资金；底仓增强策略则等于初始资金加底仓初始市值。
- `strategy_error（策略错误）` 会展示回调、事件时间、标的、安全原因和修改建议；应据此检查字段、变量、盘口档位、返回值和下单动作。
- `system_error（系统错误）` 不回显服务地址、SQL 或 Python 堆栈，只给出安全提示和 `taskId（任务编号）`；管理员可在“系统错误日志”查看 `errorCode（错误编码）`、分类、是否可重试、脱敏原因和 `rawLogRef（原始日志索引）`，维护人员据此查询容器日志。
- `data（数据错误）` 会说明缺少的行情数据类型；缺失交易日和未来交易日会在回测日期面板中置灰且不可选，不会显示为“系统错误”。
- 保存完整策略时，系统会先校验标的、周期和回测区间的数据完整性；校验未通过不会保存脚本或策略配置。单独保存的脚本仅作为草稿，不能绕过完整策略校验。

## 2. 系统使用流程

回测日期统一填写为 `YYYY-MM-DD（ISO交易日格式）`，例如 `2026-06-01`。历史记录中的旧 `YYYYMMDD（紧凑交易日格式）` 会在读取时自动兼容转换；策略、接口和任务结果均以 ISO 格式显示。

### 2.1 编写前

1. 明确交易周期。当前契约示例为 5 分钟 K 线；若编辑器的周期配置改变，先确认回调频率与成交规则是否同步变化。
2. 明确策略只做多、只做空还是双向。最小示例只覆盖多头。
3. 明确每笔数量、最大持仓、止损和交易时段。没有写出的风控规则不会由示例自动补上。

### 2.2 编写与运行

1. 在策略代码编辑器中定义 `on_bar(bar, state)`（K线回调函数）。
2. 只读取当前契约明确提供的 `bar`（当前K线及账户数据）字段。
3. 根据条件返回一条或多条委托字典；没有信号时返回 `[]`。
4. 运行回测后，逐笔检查信号 K 线、成交价、仓位变化和委托原因。
5. 确认结果符合预期后，再评估是否进入实盘流程。

若需要盘中盘口触发：

- 增加 `on_quote(quote, state)`；`quote` 可读取时间、标的、`lastPrice`、`bids`、`asks` 及与 `bar` 相同的账户字段，每档盘口含 `price（价格）` 与 `volume（可见量）`。
- 使用 `on_order_event(event, state)` 根据 `accepted（已受理）`、`partial_fill（部分成交）`、`filled（完全成交）`、`cancelled（已撤销）`、`rejected（已拒绝）` 更新状态；成交事件含数量、累计成交量、价格、手续费和 `clientOrderKey（客户订单键）`。
- 从 QMT 迁移时，移除账户号、固定标的、订阅、`passorder`、文件持久化和监控目录；只保留已确认的交易判断、仓位规则和风控条件，并改用当前回测请求的标的、账户字段、方向权限与行情事件。

### 2.3 管理历史回测

- “历史回测”会保存每次任务的代码、参数、行情数据与结果快照；可查看结果、复制参数重新运行或保存备注和标签。
- 已成功、失败或取消的历史回测可在列表的操作区域点击“删除”。确认后，系统会永久删除数据库中的该回测记录及其关联任务、事件和错误记录，无法恢复。
- 可勾选当前筛选结果中的多条已结束回测，再点击“删除所选”批量删除。系统会先校验所有选中记录；只要其中有排队、运行中或无权限记录，整批不会删除。
- 排队或运行中的任务不能删除；应先取消并等待任务进入取消状态。
- 删除历史回测不会删除策略脚本、策略方案或其发布版本。

### 2.4 发布前检查

- 确认不会在空仓时发送平仓动作。
- 确认平仓数量不超过实际持仓。
- 确认多头和空头的动作没有写反。
- 确认每一个分支都返回列表，而不是返回单个字典或 `None`。
- 确认策略对连续多根满足条件的 K 线不会重复开仓，除非这正是设计目标。
- 确认回测中的“下一根 Bar 开盘虚拟成交”或 L2 后续盘口成交与 `slippage（滑点）` 配置符合策略预期；该规则不代表实盘一定能以同样价格成交。

## 3. 策略编写指南

### 3.0 提供给 AI 的完整指南地址

系统在当前部署主机下提供不需要登录的只读 Markdown 地址：`/strategy-guide.md`。例如服务器地址为 `http://192.168.251.1:28601` 时，完整地址为 `http://192.168.251.1:28601/strategy-guide.md`。

- 在策略编辑器的“策略编写指南”中，可使用“打开 Markdown”查看原文，或使用“复制公开链接”将地址提供给可访问该服务器的 AI。
- 该地址只提供本手册，不提供任意项目文件、用户策略、回测记录或系统配置。
- 要求 AI 生成策略时，应明确要求其完整阅读本手册，并只使用当前文档定义的回调、字段和委托动作。

### 3.1 先选择回调场景

| 场景 | 必须定义的函数 | 何时使用 | 成交时点 |
| --- | --- | --- | --- |
| 标准 Bar 回放（快速） | `on_bar(bar, state)`；可选 `on_order_event(event, state)` | 只依赖已完成 K 线的策略 | 下一根可交易 Bar 开盘价加滑点；虚拟成交后发送完全成交回报。 |
| L2 订单驱动 | `on_bar(bar, state)` | 信号只依赖 Bar，但希望用十档盘口模拟主动成交 | 严格晚于信号 Bar 的后续快照。 |
| L2 连续快照 | `on_bar(bar, state)`、`on_quote(quote, state)` | 盘中止盈止损、开盘触发、盘口条件、分批下单 | `on_quote` 新订单严格从下一条快照开始成交。 |

新用户应从“普通 Bar 回测”开始。记住以下边界：

- 普通 Bar 策略看不到未完成 K 线。
- 标准 Bar 会执行 `on_bar` 与成交后的 `on_order_event`，但不会执行 `on_quote`；写在 `on_quote` 中的盘口止损、止盈和开平仓逻辑不参与标准 Bar 结果。
- L2 订单驱动策略不会每 3 秒调用一次。
- 只有定义 `on_quote` 才会启用连续快照回放。

### 3.2 最小模板：普通 Bar、单标的、只做多

适用范围：无底仓、普通股票、只做多、按当前所选周期的已完成 Bar 产生信号，并在下一根 Bar 开盘成交。

```python
# on_bar 会在每根已完成的 Bar 调用一次；周期由回测页面选择。
# bar['time'] 为 YYYYMMDDHHMMSS，bar['tradeDate'] 为 YYYY-MM-DD。
# 本模板只使用已完成 Bar 的 OHLC 和当前策略净仓位。
def on_bar(bar, state):
  if bar['position'] == 0 and bar['close'] > bar['open']:
    return [{'action': 'buy_open', 'quantity': 100, 'reason': '阳线开多'}]
  if bar['position'] > 0 and bar['close'] < bar['open']:
    return [{'action': 'sell_close', 'quantity': bar['position'], 'reason': '阴线平多'}]
  return []
```

这段代码只是最小示例，不是通用策略模板：

- 科创板开仓至少 200 股。
- L2 底仓增强策略还受 T+1 与做 T 额度限制。
- 资金不足、未启用方向或数量不合规则会被拒绝并写入明细。

### 3.3 最小模板：L2 盘口内止盈

适用范围：入场信号仍由已完成 Bar 确认，但持仓后需要在每条 3 秒快照检查止盈。定义 `on_quote` 后自动启用连续回放；标准 Bar 模式会忽略该函数，但仍可执行 `on_bar` 信号和 `on_order_event` 回报。

```python
def on_bar(bar, state):
  if bar['position'] == 0 and bar['close'] > bar['open']:
    return [{'action': 'buy_open', 'quantity': 100, 'reason': 'Bar 确认开多', 'clientOrderKey': 'entry'}]
  return []

def on_quote(quote, state):
  entry_price = state.get('entryPrice', 0.0)
  if quote['position'] > 0 and entry_price > 0 and quote['lastPrice'] >= entry_price * 1.01:
    return [{'action': 'sell_close', 'quantity': quote['position'], 'reason': '3秒快照止盈', 'clientOrderKey': 'take-profit'}]
  return []

def on_order_event(event, state):
  if event['type'] == 'filled' and event.get('clientOrderKey') == 'entry':
    state['entryPrice'] = event['price']
  if event['type'] == 'filled' and event.get('clientOrderKey') == 'take-profit':
    state.pop('entryPrice', None)
```

不要在 `on_bar` 提交订单时就写入成交价或推进分批阶段：

- 订单可能部分成交、被拒绝或被撤销。
- 应在 `on_order_event` 的 `partial_fill（部分成交）`、`filled（完全成交）` 事件中更新状态。

### 3.4 `state（策略状态）` 的正确使用

`state` 是当前一次回测会话内的可读写字典：

- 会跨同一任务中的 Bar、Quote 与委托回报回调保留。
- 任务结束、重跑或 worker 重启后不承诺恢复。
- 适合保存已成交均价、阶段序号、待处理 `clientOrderKey（客户订单键）` 和当日标记。
- 不应用它替代系统账户、持仓或现金。

### 3.5 下单前检查清单

1. `quantity（下单数量）` 是大于 0 的整数；普通股票通常按 100 股，科创板开仓至少 200 股。
2. `buy_open（买入开多）` 受现金限制；`sell_open（卖出开空）` 要求回测方案启用 `allowShort（允许做空）`。
3. `sell_close（卖出平多）` 不得超过可平仓位；L2 中当天买入不增加当日可卖数量。
4. 底仓增强策略的 `position（净持仓）` 不等于可自由交易仓位；应使用 `strategyPosition（策略净持仓）`、`basePosition（底仓数量）`、`sellableQuantity（当日可卖数量）` 和 `t0AvailableQuantity（当日做T剩余额度）`。
5. L2 中任何新订单都不能使用产生该订单的同一条快照成交；这是无前视规则。

### 3.6 从 QMT 迁移策略

迁移时请按下面边界处理：

- 保留交易判断、仓位比例、风控阈值和开平仓顺序。
- 删除账户号、固定标的、订阅、`passorder`、QMT 回调对象、文件持久化、监控目录和平台日志。
- 改用当前回测的 `bar['symbol']`、`quote['symbol']`、账户字段、标准 action 和委托回报。
- QMT 一秒 Tick 在本系统中只能映射为可见的 3 秒 `on_quote` 快照；不能假定两次快照之间的价格路径存在。

## 4. 最小可运行策略

```python
# 此示例等同于 3.2 的普通 Bar、单标的、只做多模板。
def on_bar(bar, state):
  if bar["position"] == 0 and bar["close"] > bar["open"]:
    return [{"action": "buy_open", "quantity": 100, "reason": "阳线开多"}]
  if bar["position"] > 0 and bar["close"] < bar["open"]:
    return [{"action": "sell_close", "quantity": bar["position"], "reason": "阴线平多"}]
  return []
```

这段代码的行为是：

1. `position`（当前持仓数量）为 `0` 且收盘价高于开盘价时，返回 100 股开多委托。
2. `position`（当前持仓数量）大于 `0` 且收盘价低于开盘价时，返回全部平多委托。
3. 其他情况不产生委托。

## 5. 函数与字段参考

### 5.1 `on_bar(bar, state)`（K线回调函数）

| 项目 | 说明 |
| --- | --- |
| `bar`（当前K线及账户数据） | 当前已完成 K 线与账户快照。只应读取当前契约提供的字段。 |
| `state`（策略状态） | 当前回测会话内可读写的字典；跨同一任务的回调保留，不承诺跨任务或 worker 重启恢复。 |
| 返回值 | 委托字典组成的列表，例如 `[{...}]`；无委托时为 `[]`。 |

### 5.2 `bar`（当前K线及账户数据）字段

| 字段 | 含义 | 使用提示 |
| --- | --- | --- |
| `time` | 当前已完成 K 线的完成时刻 | 固定紧凑格式 `YYYYMMDDHHMMSS`，例如 `20260727093000`；存量策略可继续切片，新策略不应依赖字符串位置。 |
| `datetime` | 当前已完成 K 线的完成时刻 | 固定 ISO 格式 `YYYY-MM-DD HH:MM:SS`，例如 `2026-07-27 09:30:00`。 |
| `tradeDate` | 当前交易日 | 固定 ISO 格式 `YYYY-MM-DD`；用于跨交易日重置策略状态。 |
| `hhmm` | 当前完成时刻的时分 | 整数，例如 `931`、`1300`、`1457`；用于交易时段和尾盘规则。日线为 `None`。 |
| `open` | 开盘价 | 与 `close`（收盘价）比较可判断阳线或阴线。 |
| `high` | 最高价 | 可用于基于已完成 K 线的止损、突破或波动计算。 |
| `low` | 最低价 | 可用于基于已完成 K 线的止损、突破或波动计算。 |
| `close` | 收盘价 | 信号判断可使用该价格；标准 Bar 模式的实际成交以严格后续 Bar 的 `open`（开盘价）为基准并受 `slippage（滑点）` 调整。 |
| `volume` | 成交量 | 可用于成交量过滤。单位以编辑器实际数据定义为准。 |
| `cash` | 账户可用资金或资金快照 | 具体口径未在最小契约中定义；下单前不可据此臆测冻结资金规则。 |
| `equity` | 账户权益快照 | 可用于记录或风控计算；具体口径未在最小契约中定义。 |
| `position` | 当前净持仓数量 | 包含底仓和脚本成交仓位；多头为正、空头为负。 |
| `strategyPosition` | 当前脚本净持仓数量 | 仅当前脚本以自身委托形成的仓位，不含底仓。 |
| `basePosition` | 初始底仓数量 | 底仓增强回测配置的底仓；未设置时为 `0`。 |
| `sellableQuantity` | 当日可卖数量 | L2 中按 T+1 计算；当天买入不增加该数值。标准 Bar 模式不提供该字段。 |
| `t0AvailableQuantity` | 当日做T剩余额度 | 启用底仓做 T 时为非负整数；标准 Bar 与 L2 均按开多、开空消耗额度。 |
| `params` | 策略参数 | 参数结构、默认值和编辑方式需以编辑器实际配置为准。 |

### 5.3 委托字典

每条委托至少使用以下字段：

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `action`（交易动作） | 下单方向与开平含义 | 必须是下表中的一个值。 |
| `quantity`（下单数量） | 本次委托数量 | 应为正数；平仓不得超过可平持仓。最小单位与是否允许零股由系统规则决定。 |
| `reason`（下单原因） | 供日志和结果分析使用的说明 | 推荐填写简短中文说明，例如“均线上穿开多”。 |
| `clientOrderKey`（客户订单键） | 策略自定义的未终结订单标识 | 可选；同一键未终结时不可重复下单，回报用它关联状态。 |

### 5.4 `action`（交易动作）对照表

| 值 | 含义 | 常见用途 |
| --- | --- | --- |
| `buy_open` | 买入开多 | 建立或增加多头仓位。 |
| `sell_close` | 卖出平多 | 减少或平掉多头仓位。 |
| `sell_open` | 卖出开空 | 建立或增加空头仓位。 |
| `buy_close` | 买入平空 | 减少或平掉空头仓位。 |

## 6. 编写规则与示例

### 6.1 无信号必须返回空列表

```python
def on_bar(bar, state):
  return []
```

不要省略 `return`。Python 默认返回 `None`，而编辑器要求的是委托列表。

### 6.2 只在确认后的条件下下单

```python
def on_bar(bar, state):
  is_bullish = bar["close"] > bar["open"]
  if bar["position"] == 0 and is_bullish:
    return [{"action": "buy_open", "quantity": 100, "reason": "阳线确认开多"}]
  return []
```

变量 `is_bullish`（本根K线是否为阳线）只基于已完成 K 线的数据判断，因此不会使用未收盘价格。

### 6.3 多条委托前先确认系统语义

当前最小契约尚未定义以下语义：

- 同一根 K 线返回多条委托时的执行顺序；
- 多条委托之间的部分成交关系；
- 多条委托的资金占用顺序。

在这些规则确认前，每次回调推荐只返回一条委托，避免依赖未定义的撮合顺序。

## 7. 常见问题

### 为什么策略没有交易？

先检查：

1. 当前 K 线是否已经完成。
2. 条件是否真的满足，例如 `close > open`。
3. `position`（当前持仓数量）是否符合分支条件。
4. 返回值是否为列表，且 `action`（交易动作）拼写正确。
5. `quantity`（下单数量）是否为正数并符合系统最小数量要求。

### 为什么一段时间内连续开仓？

可能原因：

- 策略扩展后删除了 `position == 0` 的开仓限制；
- 持仓更新、部分成交或未完成委托与策略预期不一致；
- 同一触发条件连续成立，但策略没有防重入状态。

处理方法：先确认委托回报、部分成交和挂单占用的系统语义，再用 `state` 记录待处理订单或阶段，避免重复开仓。

### 可以在 `state`（策略状态）保存开仓价或止损价吗？

可以在当前一次回测会话内保存开仓价、止损价、阶段序号和待处理订单标识。`state` 会跨同一任务中的 Bar、Quote 与委托回报回调保留。

注意：任务结束、重跑或 worker 重启后不承诺恢复。因此，`state` 不能替代系统账户、持仓、现金或跨任务持久化存储。

### 回测结果能直接等同于实盘结果吗？

不能。

- 普通 Bar 回测以信号后的下一根可交易 K 线开盘价为基础，并按配置滑点虚拟成交。
- L2 回测使用可见十档盘口模拟成交，但仍只覆盖 3 秒采样点。
- 实盘还受行情跳动、撮合、资金、券源、涨跌停和交易时段影响。

回测用于验证规则，不保证实际成交价格。

### 能否同时做多和做空？

可以使用 `buy_open（买入开多）`、`sell_close（卖出平多）`、`sell_open（卖出开空）`、`buy_close（买入平空）` 四类动作；是否接受开空还受 `allowShort（允许做空）` 控制。

在底仓增强策略中，`longQty（策略开多仓位）`、`shortQty（策略开空仓位）` 与 `baseQuantity（底仓数量）` 分账记录，尾盘会将策略多仓和空仓分别清零。编写双向策略前，仍应明确每个方向的开仓、防重入和尾盘规则。
