# 研究信号与策略联动回测方案

## 1. 背景与问题

研究平台 `xlquant_pro` 已能够产出版本化的研究信号。每条信号只表达研究结论对应的标准动作：`long`、`short` 或 `flat`，并携带 `signal_time`、`available_at`、`effective_at`、周期和来源哈希。

当前回测端把研究信号实现为独立的 `research_signal` 策略适配器，与 `user_script` 策略适配器互斥。该实现存在以下问题：

- 用户不能在一次回测中同时选择已有策略和研究信号；
- 信号不包含下单数量，单独作为策略无法表达仓位、底仓、风控和交易规则；
- 前端策略列表只暴露自定义策略，研究信号没有可理解的配置入口；
- 信号周期与回测周期不一致时，缺少可复现的 Bar 对齐规则；
- 当前回测详情没有将信号快照、策略快照和对齐结果作为一个组合展示。

本方案将研究信号定位为“策略的可选外部输入”，而不是另一类独立策略。策略仍是唯一负责产生订单数量与交易动作的执行主体。

## 2. 目标与边界

### 2.1 目标

1. 复用现有回测页面、策略方案、运行历史和结果详情，不新增独立信号回测页面。
2. 允许用户在一次回测中选择策略，并可选地选择一个已发布研究信号集。
3. 回测提交时冻结原始信号、时间对齐计划、策略配置和执行参数；运行时不依赖研究服务在线。
4. 向策略提供当前已生效研究信号，使策略自行决定是否采纳信号及交易多少股。
5. 保持“只选策略、不选信号”的全部现有行为和历史任务兼容性。
6. 在前端清晰说明信号版本、覆盖范围、周期兼容性和冻结结果。

### 2.2 不在本期范围内

- 将 `long`、`short` 或 `flat` 自动换算成固定股数的独立“直接跟随信号”策略；
- 多个研究信号集的投票、加权或冲突合并；
- L2 级研究信号、Tick 信号或秒级执行对齐；
- 信号周期细于回测周期时的自动压缩或聚合；
- 真实融券券源、保证金、借券费率和强平规则。

## 3. 已确认设计决策

### 3.1 策略必选，研究信号可选

回测方案必须选择执行策略。研究信号集为可选输入：

| 配置 | 行为 |
| --- | --- |
| 仅选择策略 | 保持现有回测逻辑；不访问研究服务，不生成研究信号快照。 |
| 选择策略与研究信号 | 冻结研究信号，并在每个回测时点向策略提供当前已生效信号。 |
| 仅选择研究信号 | 前端和后端均拒绝提交。 |

策略可声明是否依赖研究信号。声明为“必须依赖”的策略在未选择信号时不可运行；普通策略在没有信号时照常运行，在有信号时可自行使用或忽略。

### 3.2 研究信号不是订单，也不是仓位

研究侧只输出标准方向事件：

```text
long / short / flat
```

实际下单方向、数量、底仓处理、风控和调仓频率均由回测策略决定。研究信号不得绕过策略直接生成订单。

### 3.3 不新建回测页面

在现有回测页面的策略配置区域增加“研究信号集”选择和信号摘要。研究中心信号台账中的“用于回测”入口跳转到既有回测页面，并携带 `signalDatasetId（研究信号数据集标识）` 预选值。

### 3.4 研究侧定义时间语义，回测侧完成 Bar 对齐

研究侧负责提供权威的 `signal_time（信号对应时点）`、`available_at（可用时间）` 和 `effective_at（最早可交易时间）`。回测侧在提交阶段按照本次回测的周期、交易日历和成交模型，把信号定位到具体可执行 Bar。

研究侧不为不同回测周期生成不同信号副本；回测侧不修改研究信号的时间语义。

## 4. 总体架构

```text
xlquant_pro
  发布标准研究信号
      ↓ 内部 API
backtest_system 提交回测
  冻结原始信号 + 生成对齐计划
      ↓
ResearchSignalProvider（研究信号输入提供器）
  每根 Bar 返回当前已生效信号
      ↓
UserScriptAdapter（用户策略执行适配器）
  根据行情、账户、底仓和信号输出订单
      ↓
现有撮合与结果持久化
```

`ResearchSignalAdapter（研究信号策略适配器）` 不再作为用户可选择的独立策略。其“拉取、校验、冻结信号”的职责迁移为 `ResearchSignalProvider（研究信号输入提供器）`；现有策略适配器仍是唯一订单执行主体。

## 5. 后端设计

### 5.1 回测请求与策略方案

在既有回测请求和策略方案快照中增加可选字段：

```text
signalDatasetId（研究信号数据集标识）
signalDatasetVersion（研究信号数据集版本）
```

用户仅选择数据集标识；版本、manifest、分区哈希和实际读取内容均由后端在提交阶段解析并写入快照。浏览器不得提交可伪造的信号正文、快照哈希或研究服务凭据。

### 5.2 信号冻结与时间对齐

提交回测时，后端按标的、回测区间和用户权限执行：

1. 从研究服务读取已发布信号数据集的 manifest；
2. 校验数据集状态、标的、信号时间精度、来源分区哈希和权限；
3. 流式读取实际需要的原始信号行，按稳定顺序计算 `snapshotHash（信号冻结快照哈希）`；
4. 将原始信号副本写入回测产物卷；
5. 按回测 Bar 构建只含“信号切换时点”的对齐执行计划；
6. 保存原始信号快照、对齐计划、策略快照和行情快照；
7. 全部校验成功后再创建回测任务。

运行时只读取冻结产物，不重新请求研究服务。

### 5.3 周期兼容规则

首期仅支持标准 Bar 回测。允许研究信号周期不细于回测周期：

| 研究信号周期 | 回测周期 | 处理方式 |
| --- | --- | --- |
| `1d` | `1d` | 按首个满足 `bar_time >= effective_at` 的日线可交易时点使用。 |
| `1d` | `1m`、`5m`、`15m`、`30m` | 日线信号在首个可交易分钟 Bar 生效，沿用至下一条已生效信号。 |
| `5m` | `1m` | 按相同规则向更细周期 Bar 前向持有。 |
| 细周期信号 | 更粗周期回测 | 首期拒绝，避免隐式压缩、丢失盘中信号或引入未来函数。 |

对齐使用 `effective_at`，而不是仅按日期或 `signal_time` 比较。若首根回测 Bar 前没有已生效信号，则向策略传入空信号；策略自行决定不交易、保持仓位或按自身规则处理。

### 5.4 策略上下文

为保持 `on_bar(bar, state)` 既有函数签名不变，在 `bar（当前 K 线及账户数据）` 中新增可选只读字段 `researchSignal（当前研究信号）`。未选择研究信号或尚无已生效信号时，该字段为 `null`。

字段结构如下：

```text
researchSignal
  ├─ action: long | short | flat
  ├─ signalTime
  ├─ availableAt
  ├─ effectiveAt
  ├─ signalId
  ├─ datasetId
  ├─ datasetVersion
  └─ sourceHash
```

策略读取该字段后，仍按既有订单返回契约输出 `action（交易动作）`、`quantity（下单数量）` 和 `reason（下单原因）`。信号未选择时，字段为 `null`，既有策略无需改动即可运行。

实现该字段时，必须同步更新 `docs/玄龄回测系统使用手册.md` 中 `on_bar` 与 `bar` 的字段说明。

### 5.5 快照和结果持久化

每个使用研究信号的回测任务至少保存：

- 数据集标识、版本、manifest 和来源分区哈希；
- 实际读取的原始信号文件及其 `snapshotHash`；
- 信号周期、回测周期、时区、对齐规则版本和对齐执行计划；
- 策略配置和脚本快照；
- 行情数据快照、成交模型、费用和其他执行参数。

历史详情新增“研究信号快照”区域，展示上述元数据和信号摘要。历史任务永远读取任务自身快照，不按当前研究版本重新计算。

## 6. 前端设计

### 6.1 现有回测页面

在现有策略配置区域增加“研究信号”分组：

```text
研究信号集：未使用研究信号 / 已发布信号集
```

选中信号集后显示：

- 数据集名称和版本；
- 模型、标签池和动作策略版本；
- 信号周期、覆盖标的和日期范围；
- 最近若干信号的时点、动作和生效时间；
- 与当前回测周期的兼容性及对齐说明。

不增加新的回测页面，不增加“信号直接换算目标股数”的冗余预览。策略、底仓和仓位逻辑继续在现有配置中管理。

当周期组合不兼容、信号未发布、覆盖范围不足或策略要求信号但未选择时，前端阻止提交并显示明确原因；后端执行同样校验。

### 6.2 研究中心入口

研究中心的已发布信号台账新增“用于回测”操作。该操作仅导航至当前回测页面并预填数据集，不调用回测内部服务、不向浏览器暴露服务令牌。

### 6.3 回测详情

在现有详情页增加“研究信号快照”区域，展示信号版本、冻结哈希、原始周期、回测周期、对齐规则、信号条数和来源分区。该区域与策略、行情和费用快照并列，不另建结果页面。

## 7. 兼容性与迁移

1. 未填写 `signalDatasetId` 的新旧策略方案和历史回测均按无研究信号处理。
2. 现有 `research_signal` 历史任务继续按既有冻结文件和适配器语义读取，不重算、不改写结果。
3. 新任务不再将研究信号作为 `strategy（策略标识）` 的替代值；策略和信号分别保存。
4. 删除或归档研究侧信号版本不得影响已冻结的历史任务。

## 8. 实施步骤

1. 先完成 `xlquant_pro` 研究信号相关迁移，并修复研究会话和内部接口注册问题。
2. 重构回测端适配器：将冻结读取职责从独立研究信号策略迁移至输入提供器。
3. 扩展回测请求、策略方案快照、预检和 Worker 负载，支持可选研究信号标识。
4. 实现信号冻结、周期校验、Bar 对齐计划和策略上下文注入。
5. 改造现有回测页、研究中心跳转和回测详情快照展示。
6. 更新策略代码编辑器使用手册。
7. 完成测试、历史兼容检查和本地联调后，再按同批发布要求部署相关服务。

## 9. 验收标准

1. 用户可在现有回测页同时选择策略和已发布研究信号集。
2. 用户仅选择策略时，结果与未改造前的同一策略回测保持一致。
3. 选中信号后，策略能读取当前已生效信号并自行决定订单数量。
4. `1d` 信号可在 `1d` 和更细标准 Bar 回测中无前视地生效；不兼容周期被明确阻止。
5. 修改研究侧信号、模型或动作策略版本后，历史回测仍使用自身冻结输入，结果可追溯。
6. 前端可查看信号版本、冻结哈希和对齐计划；不新增独立信号回测页面。
7. 覆盖无信号、信号切换、无已生效信号、周期不兼容、来源哈希不一致、历史回退和策略上下文注入的自动化测试。

## 10. 风险与发布要求

- 信号时间精度高于行情精度或 `effective_at` 不合法时必须拒绝任务，不能静默向下取整。
- 修改策略回调上下文、Worker 负载、结果结构和前端契约时，后端、strategy-worker、相关 runner 与前端必须同批发布。
- 发布前检查排队和运行中的 L2 任务；本方案首期不改变 L2 执行，但同批发布不得静默中断相关任务。
- 研究服务不可用时，新的带信号任务应在提交阶段失败；已冻结任务必须仍可运行。
