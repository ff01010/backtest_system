# 策略管理页面深化方案

## 1. 背景与目标

当前回测工作台已完成全局视觉令牌、概览页和结果分析区的第一轮改造。策略管理页仍以分散的表单和代码区域为主，用户难以在同一视野内确认“正在编辑哪份代码、该代码绑定哪套方案、当前配置是否已保存、是否具备运行条件”。

本次深化将策略管理页定位为“策略研究工作台”：从左到右分别处理策略资产、代码编辑和回测配置；底部持续展示保存状态与运行前检查结果。

## 2. 范围与边界

### 包含

- 重组策略、方案、版本、代码编辑器和参数区的信息层级。
- 提升已保存、未保存、数据未完整、方案未选择等状态的可见性。
- 复用现有深青、纸面、石墨和 A 股红涨绿跌视觉令牌。
- 为键盘编辑、窄屏阅读和空状态提供明确反馈。

### 不包含

- 不修改 `on_bar`（K线回调函数）契约、订单动作或策略执行逻辑。
- 不修改回测撮合、行情读取、数据库结构或接口。
- 不引入实盘、模拟盘或 `live`（运行）模式入口；系统保持纯回测定位。
- 不新增第三方组件库或前端依赖。

## 3. 信息架构

```text
策略管理
├─ 策略资产栏
│  ├─ 策略脚本列表
│  ├─ 已绑定方案
│  └─ 方案版本记录
├─ 代码工作区
│  ├─ 脚本名称与状态
│  ├─ 代码编辑器
│  └─ 契约提示与校验反馈
├─ 回测配置栏
│  ├─ 标的与基准
│  ├─ 回测周期与日期
│  ├─ 账户、成本与持仓规则
│  └─ 行情覆盖状态
└─ 操作状态条
   ├─ 保存状态
   ├─ 版本快照
   ├─ 运行前检查
   └─ 运行回测
```

## 4. 页面布局

### 4.1 三栏工作台

桌面端采用 `260px / 自适应主区 / 340px` 三栏布局。

- 左栏保持策略资产，不承载参数输入。每个策略项展示名称、版本、绑定方案和保存状态。
- 中栏作为唯一代码编辑区，编辑器占可用高度的大部分；顶部仅保留脚本名称、状态标记和必要操作。
- 右栏按“市场—账户—交易规则—数据状态”顺序分组，避免把策略管理与实验结果混排。

窄屏时采用优先级降级：代码编辑区保留，左右栏改为可切换抽屉，不让编辑器被压缩到不可读宽度。

### 4.2 底部状态条

代码编辑区底部固定一条状态条，按以下优先级展示单一主状态：

1. 校验或保存错误；
2. 未保存修改；
3. 回测前检查未通过；
4. 已保存且可运行。

状态条右侧保留“保存策略”和“运行回测”。运行按钮仅在策略、方案和行情检查通过时可用；禁用时必须说明阻塞原因。

## 5. 视觉与交互规则

- 代码编辑区使用低饱和纸面背景、细边框与等宽字体，避免大面积纯白造成视觉疲劳。
- 已保存使用深青标记；未保存使用琥珀色标记；错误使用低饱和红色标记。颜色之外必须有文字说明，不能只依赖颜色。
- 参数分组标题使用小型圆点和衬线标题，内容采用统一 8–12px 间距节奏。
- 策略列表和版本列表使用悬停、选中和键盘焦点状态；选中项以左侧深青标尺标识。
- 所有保存、删除、运行操作必须保留清晰的禁用、进行中和完成反馈。

## 6. 实施顺序

1. 提取策略管理页现有区域，明确“策略资产、代码、配置、状态条”的组件边界。
2. 调整三栏布局与窄屏降级规则，不改变现有保存和运行事件。
3. 改造代码编辑器顶部、状态条、参数分组和策略资产列表。
4. 将版本快照和运行前检查接入状态条，补齐空状态与错误状态。
5. 执行前端单测、构建、键盘焦点检查和桌面/窄屏视觉核验。

## 7. 验收标准

- 用户可在不滚动页面主体的情况下辨认当前脚本、绑定方案、标的、周期和保存状态。
- 用户可清楚知道运行按钮不可用的原因。
- 已保存与未保存状态在鼠标、键盘和窄屏场景下均可辨识。
- 编辑、保存、运行的既有请求参数和后端接口不变。
- `npm test`、`npm run build` 和差异检查通过；视觉核验记录真实执行结果。
