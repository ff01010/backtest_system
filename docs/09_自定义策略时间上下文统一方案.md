# 自定义策略时间上下文统一方案

## 1. 背景与结论

当前自定义策略通过 `on_bar(bar, state)` 接收 `bar['time']`。普通 Bar 回测与 L2 回测分别直接传入各自的原始时间字符串：已有普通回测策略实际依赖紧凑格式 `YYYYMMDDHHMM`，而 L2 临时聚合 Bar 传入 ISO 格式 `YYYY-MM-DD HH:MM:SS`。同一脚本因此会因数据源不同而在字符串切片、日期切换或交易时段判断处运行失败。

前端 `startDate（开始交易日）`、`endDate（结束交易日）` 仅用于筛选回测区间；它们不是每次 `on_bar（K线回调函数）` 传入的当前 Bar 时间。当前 Bar 的时间必须由平台在脚本执行边界统一，不能要求脚本作者识别数据源格式。

结论：新增策略时间上下文适配层，由 `ScriptedBarStrategy（自定义脚本策略适配器）` 在调用用户脚本前完成解析和标准化。首版以存量兼容为先：保留 `time（旧兼容时间）`，但固定为 14 位紧凑秒格式；新增不需要字符串切片的显式字段。普通回测、L2 回测和未来正式 L2 Bar 表都必须复用该层。

## 2. 目标与边界

### 2.1 目标

- 同一根已完成 Bar 在任何回测路径中传给用户脚本的时间字段完全一致。
- 新脚本可通过明确字段判断交易日和时分，不需要截取 `time（旧兼容时间）`。
- 已有依赖 `time[:8]`、`time[8:12]` 的分钟策略继续可用，不因 L2 接入而回归。
- 无效或无法识别的 Bar 时间在执行策略前失败，错误消息说明原始值、字段和支持格式。
- 策略编辑器模板、参数说明和使用手册只描述一套脚本时间契约。

### 2.2 非目标

- 不改变前端回测区间的日期选择、交易时段、Bar 聚合边界或撮合成交时间。
- 不修改 ClickHouse 原始表、Redis 临时 Bar 缓存键和 L2 领域模型中的原始时间字段。
- 不要求本次自动改写数据库中所有用户脚本的业务逻辑。
- 不更改交易结果、订单审计和图表中保存的原始 `Bar.time（Bar原始时间）`；本方案只规范脚本可见的上下文。

## 3. 统一脚本时间契约

### 3.1 `bar（当前Bar）` 的时间字段

| 字段 | 类型 | 固定格式/值 | 用途 |
| --- | --- | --- | --- |
| `time（旧兼容时间）` | `str（字符串）` | 分钟 Bar 为 `YYYYMMDDHHMMSS` | 表示本 Bar 的完成时刻；兼容已有脚本；新脚本不应再通过切片解析。 |
| `datetime（完整时间）` | `str（字符串）` | `YYYY-MM-DD HH:MM:SS` | 当前已完成 Bar 的结束时间，供日志、比较和展示使用。 |
| `tradeDate（交易日）` | `str（字符串）` | `YYYY-MM-DD` | 日切换、按交易日保存状态。 |
| `hhmm（时分）` | `int（整数）` | 例如 `931`、`1300`、`1457` | 交易时段、收盘与风控判断。 |

`datetime（完整时间）` 表示已完成 Bar 的完成时刻；`09:30` 即完成于 `09:30:00`。L2 继续使用 `NormalizedBar.end_time（标准化Bar结束时间）` 作为完成时刻，例如 `09:30–09:31` 的首根 L2 Bar 在 `09:31:00` 触发。适配层只统一字符串契约，不改变各引擎已定义的触发或撮合顺序。

日线或其他无时分语义的周期暂不向自定义策略提供 `hhmm（时分）`；其值为 `None`，`time（旧兼容时间）` 为 `YYYYMMDD`，`datetime（完整时间）` 为 `YYYY-MM-DD`。本计划的分钟回测验收不依赖日线交易时段判断。

### 3.2 输入解析规则

新增 `backend/strategies/script_time_context.py`，以完整类型注解提供 `normalize_script_bar_time（标准化脚本Bar时间）`：

1. 接受当前已知的紧凑分钟/秒级格式 `YYYYMMDDHHMM`、`YYYYMMDDHHMMSS`，以及 ISO `YYYY-MM-DD HH:MM`、`YYYY-MM-DD HH:MM:SS`；保留对仅日期 `YYYYMMDD`、`YYYY-MM-DD` 的日线支持。
2. 使用显式日期时间解析验证日期与时分，拒绝字符串切片后看似可用的非法值。
3. 解析成功后生成第 3.1 节的四个字段；`time（旧兼容时间）` 始终输出 14 位 `YYYYMMDDHHMMSS`，任何来源的微秒部分只在解析时接受，输出统一截断到秒。
4. 不接受带时区偏移的时间。当前 A 股行情时间均为中国交易所本地时间，时区转换不属于本方案。
5. 解析失败抛出包含 `raw_time（原始时间）`、支持格式及数据来源标识的领域异常，禁止将底层 `ValueError` 直接暴露给策略作者。

### 3.3 脚本使用准则

新建策略模板和手册示例统一使用：

```python
trade_date = bar['tradeDate']
hhmm = bar['hhmm']
if hhmm is not None and 930 <= hhmm < 1130:
  pass
```

`time（旧兼容时间）` 仅为存量兼容字段。新脚本禁止将 `time` 用作日期/时分解析来源；如需完整时间，使用 `datetime（完整时间）`。

## 4. 实施步骤

### 4.1 建立中心适配器与测试

1. 新增 `script_time_context.py`，定义不可变的 `ScriptBarTimeContext（脚本Bar时间上下文）` 和标准化函数。
2. 用表驱动单元测试覆盖所有支持格式、闰年、无效时间、秒级输入、日线输入和微秒截断。
3. 明确并测试输出字段：紧凑 `time（旧兼容时间）`、ISO `datetime（完整时间）`、ISO `tradeDate（交易日）`、整数或空 `hhmm（时分）`。

### 4.2 在唯一脚本边界注入统一上下文

1. 改造 `backend/strategies/scripted.py` 的 `ScriptedBarStrategy._context（脚本上下文构造函数）`：先标准化 `bar.time（Bar原始时间）`，再向 `on_bar` 传入统一字段。
2. 保留 `Bar.time（Bar原始时间）` 供回测引擎、订单、成交、图表和审计继续使用；不得为统一脚本上下文而改写领域 `Bar` 对象。
3. 策略执行异常中补充“统一脚本时间契约”提示，并在时间解析失败时直接返回可行动的错误，而非 `invalid literal`、`name ... is not defined` 等底层异常。
4. `strategy-worker` 和 L2 Runner 无需各自再做时间格式转换；它们只负责构造正确语义的原始 Bar，并通过同一个 `ScriptedBarStrategy` 入口执行。

### 4.3 存量策略与编辑器迁移

1. 保留 `time（旧兼容时间）` 的紧凑分钟格式，先验证现有内置策略和数据库用户策略中常见的 `time[:8]`、`time[8:12]` 写法在普通/L2 两条路径均保持原行为。
2. 将 `trend_follow_qmt_1m_close_fill.py` 恢复为使用 `tradeDate（交易日）`、`hhmm（时分）` 的示范策略；删除其中仅为兼容 L2 原始 ISO 时间增加的本地解析函数，避免将错误做法作为范例。
3. 更新策略编辑器默认脚本、字段帮助文案和 `docs/玄龄回测系统使用手册.md` 的 `on_bar` 字段表及示例。
4. 在策略编辑器保存前增加轻量静态提示：检测 `bar['time'][`、`bar[\"time\"][` 等常见切片写法，提示迁移到 `tradeDate（交易日）`、`hhmm（时分）`；只提示，不阻断存量策略保存。

### 4.4 发布与兼容控制

1. 先发布中心适配器与上下文单元测试，再发布编辑器文案与示范策略；在适配器未上线前不得仅更新模板。
2. 使用完整构建启动 `backend`、`strategy-worker`、`l2-runner`，确保三个服务不会混用新旧脚本上下文行为。
3. 不需要数据迁移：策略代码和历史回测记录保持原值。兼容字段至少保留一个发布周期，之后根据静态提示命中量和用户脚本迁移情况评估是否废弃。

## 5. 测试与验收

### 5.1 自动化测试

- 时间适配器：所有输入格式均生成一致的四个脚本字段；非法日期、非法时分、混合格式和时区偏移均得到明确错误。
- `ScriptedBarStrategy（自定义脚本策略适配器）`：分别输入紧凑普通 Bar 和 ISO L2 Bar，用户回调接收到的 `time`、`datetime`、`tradeDate`、`hhmm` 完全一致。
- 存量回归：使用 `time[:8]`、`time[8:12]` 的最小策略在普通回测和 L2 Worker 日会话中均能执行且得到相同订单。
- 新字段：示范策略只使用 `tradeDate（交易日）`、`hhmm（时分）`，验证上午、午间休市、下午和尾盘收盘规则。
- 错误可读性：传入无法解析的 Bar 时间时，断言错误包含原始值、字段名和支持格式，不泄露内部堆栈。
- 前端：编辑器模板和字段说明可见；常见 `time` 切片会出现非阻断迁移提示；TypeScript 类型检查通过。

### 5.2 人工验收

1. 用 `688126.SH`、2026-06-01 至 2026-06-03 运行普通 1m 回测和 L2 回测，各保存一份相同的最小策略，确认日志中的脚本上下文时间一致。
2. 使用当前 `trend_follow_qmt_1m_close_fill.py` 执行 L2 回测，不再出现 ISO 切片或沙箱内置函数错误。
3. 在编辑器中新建策略，只根据字段说明写 `tradeDate（交易日）` 与 `hhmm（时分）`，无需了解 QMT、ClickHouse 或 L2 的原始时间格式。
4. 打开历史回测的图表与成交明细，确认其原始时间展示和订单时间没有被上下文适配层改变。

## 6. 风险与回滚

- 风险：将 `time（旧兼容时间）` 改为紧凑格式可能与少数已有 ISO 专用脚本冲突。缓解：先检索数据库脚本与内置策略的时间用法；上线前用真实样本回放；必要时为受影响脚本手动迁移到新字段。
- 风险：普通 Bar 与 L2 Bar 的完成时刻标签可能不同，例如普通首根为 `09:30:00`，L2 首根为 `09:31:00`。缓解：统一定义两者均为各自引擎的实际完成时刻；适配层不得改变事件排序、订单信号时间或撮合可用时间。
- 风险：静态提示不能识别所有动态字符串访问。缓解：提示仅作教育，不承担运行时兼容职责；中心适配器始终输出稳定字段。
- 风险：把原始 Bar 时间改写会影响撮合和审计。缓解：只复制并标准化脚本 `context（上下文）`，订单和回测领域对象继续保存原始时间。
- 回滚：回退 `ScriptedBarStrategy` 的上下文注入与编辑器提示即可；不涉及数据库或缓存迁移。若发生问题，存量策略仍可通过旧 `time（旧兼容时间）` 运行。

## 7. 自审

- 方案把格式转换放在唯一的用户脚本边界，避免普通 Runner、L2 Runner、Worker 和每个策略作者重复适配。
- 同时提供可读 ISO 字段和兼容紧凑字段，兼顾新策略可维护性与已有策略不回归。
- 区分了前端回测区间、原始 Bar 时间和脚本可见时间，避免再次把日期筛选问题误当作 Bar 时间问题。
- 未把统一上下文扩大为行情表、缓存键、撮合引擎或历史审计格式迁移，范围可控。
- 已确认 `09:30` 表示完成于 `09:30:00`；L2 以 `end_time（结束时间）` 完成。方案保留两条引擎既有时序，只在脚本边界统一为 14 位时间格式与显式字段。
