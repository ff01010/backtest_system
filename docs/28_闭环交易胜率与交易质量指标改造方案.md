# 闭环交易胜率与交易质量指标改造方案

**日期：** 2026-08-24  
**状态：** 待确认  
**适用范围：** 标准 Bar 回测、L2 盘口回放、方向性持仓与底仓增强策略

## 1. 背景与问题

当前回测结果中的胜率按“产生非零 `realized_pnl` 的单次平仓成交”计算。这个口径在一开一平的简单策略中基本正确，但无法表达一笔完整交易：

- 同一方向的加仓、分批减仓会被拆成多次胜负；
- 一笔策略仓位从开仓到全部平仓的总手续费、滑点和损益没有统一汇总；
- 概览页的“成交 / 胜率”容易被理解为完整交易次数，实际却接近成交明细中的平仓 Fill 数。

因此需要将胜率统一为“闭环交易胜率”：同一标的、同一策略仓位、同一方向从零持仓建立至再次归零，记为一笔交易。

## 2. 目标与边界

### 2.1 目标

1. 以完整仓位闭环作为胜率、平均盈利、平均亏损和盈亏比的计算单位。
2. 对标准 Bar 与 L2 两条回测链路采用相同口径。
3. 保留原始成交笔数，避免破坏信号明细和执行质量分析。
4. 在概览页明确显示“闭环交易 / 胜率”，减少使用者误解。
5. 不改变既有撮合、手续费、滑点、T+1、底仓或强平规则。

### 2.2 不在本期范围

- 不重算或改写历史回测结果。
- 不修改策略脚本接口、策略信号含义或成交顺序。
- 不新增独立的“交易闭环详情”页面；信号明细继续按每次成交展示。
- 不把不同标的、不同方向或不同策略仓位合并为同一笔交易。

## 3. 统一计算口径

### 3.1 闭环交易定义

闭环键为：`symbol（标的） + positionKey（策略仓位键） + direction（方向）`。

| 事件 | 处理方式 |
| --- | --- |
| 持仓从 0 变为正数或负数 | 新建一笔未完成闭环 |
| 同方向加仓 | 归入当前闭环 |
| 同方向部分平仓 | 归入当前闭环，但不结束 |
| 当前策略仓位回到 0 | 结束闭环并结算胜负 |
| 任务结束仍未归零 | 视为未完成持仓，不计入胜率 |

方向由撮合后的仓位效果确定，例如开多/平多、开空/平空；不能仅依据 `buy` 或 `sell` 判断，以免将开空与平多混淆。

### 3.2 损益与胜负

每笔闭环的 `netPnl（闭环净损益）` 使用回测引擎已经计算完成的平仓已实现损益汇总。引擎中的持仓成本已包含开仓费用，平仓已实现损益已扣除平仓费用，因此不得再次叠加同一笔费用，避免重复扣费。

| 条件 | 分类 |
| --- | --- |
| `netPnl > 1e-8` | 胜 |
| `netPnl < -1e-8` | 负 |
| `abs(netPnl) <= 1e-8` | 平局 |

胜率定义为：

`winRate（胜率） = winningTrades（盈利闭环数） / (winningTrades（盈利闭环数） + losingTrades（亏损闭环数）)`

平局不进入胜率分母，但单独返回 `breakevenTrades（平局闭环数）`。

### 3.3 底仓与日内做 T

- 用户设置的底仓属于组合基准，不作为策略开平仓闭环；不能把底仓成本或其估值波动混入做 T 胜率。
- 底仓增强策略产生的策略叠加仓位，按独立 `positionKey（策略仓位键）` 统计闭环。
- 日内模式的尾盘恢复操作，如属于策略叠加仓位的最终平仓，应结束对应闭环；底仓本身的恢复不产生做 T 闭环。
- 跨日仍未平仓的方向性策略，直到实际归零前均保持同一未完成闭环，不按交易日强制截断。

## 4. 数据模型与后端改造

### 4.1 新增统一闭环统计器

新增内部 `closed_trade_metrics（闭环交易指标）` 组件，输入按时间排序的标准化成交记录，输出闭环统计结果。标准化记录至少包含：

- `eventTime（成交时间）`
- `symbol（标的）`
- `positionKey（策略仓位键）`
- `positionEffect（开平与方向效果）`
- `quantity（成交数量）`
- `realizedPnl（该次平仓已实现损益）`

组件只消费已经完成撮合的成交结果，不重新计算成交价格、手续费或仓位成本。

### 4.2 三条结果链路接入

| 链路 | 当前结果来源 | 改造方式 |
| --- | --- | --- |
| 标准 Bar（组合回测） | `Fill` 列表 | 在汇总前转换为标准化成交记录，调用统一统计器 |
| 标准 Bar（脚本 worker） | `trades` 字典列表 | 补齐内部仓位键/仓位效果字段后调用统一统计器 |
| L2 盘口回放 | L2 成交结果适配器 | 在适配为前端结果前调用统一统计器 |

所有链路必须按实际成交时间和稳定序号排序；若缺失 `positionKey（策略仓位键）`、仓位效果或可用的已实现损益，任务应记录可排查的系统错误，不能静默按零损益统计。

### 4.3 结果字段

保留既有原始执行字段，并新增或统一下列闭环字段：

| 字段 | 含义 | 兼容原则 |
| --- | --- | --- |
| `fillCount` | 原始成交 Fill 数 | 保持现有含义 |
| `closedTradeCount` | 已完成闭环交易数 | 新增 |
| `winningTrades` | 盈利闭环数 | 改为闭环口径 |
| `losingTrades` | 亏损闭环数 | 改为闭环口径 |
| `breakevenTrades` | 平局闭环数 | 新增 |
| `winRate` | 闭环胜率 | 改为闭环口径 |
| `avgWin` | 单笔盈利闭环平均净收益 | 改为闭环口径 |
| `avgLoss` | 单笔亏损闭环平均净收益 | 改为闭环口径 |
| `profitLossRatio` | 平均盈利与平均亏损绝对值之比 | 改为闭环口径 |
| `tradeMetricVersion` | 指标口径版本 | 新增，首版为 `2` |

`tradeCount` 不再被用作“胜率分母”的依据。为避免破坏已有接口使用方，本期保留其现有语义；页面改用 `closedTradeCount（闭环交易数）` 展示完整交易次数。

## 5. 前端展示与历史兼容

### 5.1 概览页

保持原有“成交 / 胜率”卡片布局，文案调整为“闭环交易 / 胜率”：

- 主值显示 `closedTradeCount（闭环交易数）` 与 `winRate（胜率）`；
- 展开说明或指标区显示“原始成交：`fillCount（成交 Fill 数）`”；
- 平局数、平均盈亏和盈亏比使用新闭环字段；
- 信号明细页面仍逐笔展示委托/成交，不改变其名称和排列。

### 5.2 历史结果

历史任务没有 `tradeMetricVersion = 2` 时，不在读取页面时尝试补算。页面需标识为“历史统计口径”，并按该任务已保存的旧字段展示，避免把旧的逐笔平仓胜率误标为闭环胜率。

新任务统一写入版本标识和新字段。历史任务仅在用户主动重新运行后获得新口径。

## 6. 实施步骤

1. 审计三条回测链路的成交记录，确认仓位键、仓位效果、数量、已实现损益和排序字段的来源。
2. 实现类型明确的闭环统计器及标准化成交记录适配层。
3. 将标准 Bar 两条结果路径与 L2 结果适配器接入同一统计器，补齐结果字段与版本标识。
4. 调整结果接口类型、历史结果兼容分支和概览页“成交 / 胜率”展示。
5. 增加后端单元测试、链路集成测试和前端展示测试。
6. 以同一策略、同一标的分别执行标准 Bar 与 L2 回测，核对字段口径、闭环数与信号明细的可追溯关系。

## 7. 验证用例

| 用例 | 预期 |
| --- | --- |
| 一次开多、一次平多 | 产生 1 个闭环，结果与当前简单策略一致 |
| 开多、加仓、部分平仓、全部平仓 | 只产生 1 个闭环，所有已实现损益汇总 |
| 开空、部分平空、全部平空 | 正确识别为空头闭环，不与平多混淆 |
| 仅开仓未平仓 | `closedTradeCount = 0`，不进入胜率 |
| 强制尾盘平仓 | 对策略仓位完成闭环；底仓不计入做 T 闭环 |
| 盈利、亏损、零损益 | 胜、负、平局分类及胜率分母正确 |
| 标准 Bar 与 L2 | 相同成交序列得到相同闭环统计 |
| 历史任务 | 不重算、不报错，并显示历史口径提示 |

## 8. 风险与控制

1. **仓位键丢失。** 若中间适配层遗漏策略仓位键，可能把底仓与策略仓位混合。实施前先补齐内部字段并增加断言，禁止静默降级。
2. **手续费重复计算。** 只汇总引擎输出的 `realizedPnl（已实现损益）`，不再额外累加费用字段。
3. **排序不稳定。** 统计器仅处理已按成交时间和稳定序号排序的记录，保证结果可复现。
4. **接口语义变化。** 保留 `fillCount（原始成交数）` 和既有 `tradeCount（历史语义）`，以新增 `closedTradeCount（闭环交易数）` 承担页面展示，降低兼容风险。
5. **跨日误切分。** 闭环状态跟随整个回测任务生命周期，不按自然日重置。

## 9. 自审结论

方案将“策略表现”与“执行明细”分离：闭环指标用于判断策略每次完整判断的成败，逐笔 Fill 用于分析撮合与信号。它不修改成交事实，也不依赖重新计算历史结果。

实施前的唯一前置检查是：三条链路必须都能提供稳定的策略仓位键、开平效果和已实现损益。若某条链路缺少其中任一字段，应先补齐该内部数据，再接入统计器；不能以买卖方向或零损益猜测替代。

## 10. 验收标准

1. 新回测结果的胜率、平均盈亏、盈亏比均按已完成闭环交易计算。
2. 加仓、减仓、分批平仓不增加闭环交易数，只有策略仓位归零才结算一次。
3. 开空/平空、开多/平多、底仓增强和尾盘强平都能正确归类。
4. 概览页明确显示闭环交易数与胜率；信号明细保持逐笔成交语义。
5. 历史回测可正常查看，不被隐式重算，且不会误标为新口径。
6. 后端测试覆盖本方案第 7 节全部情形，并通过标准 Bar 与 L2 的交叉验证。
