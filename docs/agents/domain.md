# Domain Docs

工程技能在分析或修改代码前，应按本文件读取仓库领域文档。

## 开始分析前

- 读取仓库根目录 `CONTEXT.md`（如果存在）。
- 如果存在根目录 `CONTEXT-MAP.md`，按其中映射读取与任务相关的上下文。
- 阅读 `docs/adr/` 中与当前改动相关的 ADR。

相关文件不存在时继续工作，不主动创建空文档。新的术语或架构决定在实际确认后，通过领域建模流程补充。

## 文档布局

本仓库采用 single-context：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-*.md
│   └── 0002-*.md
└── backend/
```

## 使用统一术语

工单标题、改造方案、代码命名和测试名称应优先使用 `CONTEXT.md` 中已经定义的术语，避免为同一概念创造不同名称。

需要使用但尚未定义的核心术语，应记录为领域文档待补充项。

## ADR 冲突

如果计划或代码修改与既有 ADR 冲突，必须明确指出冲突的 ADR 和原因，不得静默覆盖既有决定。
