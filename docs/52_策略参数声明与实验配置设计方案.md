# 策略参数声明与开放策略管理设计方案

## 1. 背景与结论

当前系统已经具备网页端完整策略保存、不可变脚本版本、方案发布版本、乐观锁和归档能力，但开放 API 只支持提交、查询和取消回测。外部调用方不能创建、读取、修改、发布或归档策略，也不能对自定义策略参数做单次覆盖。

本方案决定同时补齐两类能力：

1. 策略代码通过 `STRATEGY_PARAMETERS` 声明允许调整的自定义参数，网页和开放接口共用同一套解析、校验与合并规则。
2. 开放 API 提供当前用户完整策略的读取、创建、修改、发布、版本查询、归档和恢复能力，并继续支持单次回测参数覆盖。

开放 API 不直接暴露内部的“脚本表”和“配置表”写入接口，而是以 `config_id` 标识一份完整策略，通过同一完整策略生命周期模块维护脚本、配置、版本和所有权一致性。

调用方如何组织参数文件、选择调用工具或编排多次请求，不属于系统设计和验收范围。系统只保证每个接口请求能够独立、稳定、安全地完成其声明的操作。

## 2. 目标与非目标

### 2.1 目标

1. 用户能够在策略代码中声明扁平标量参数、默认值和类型。
2. 网页在现有“策略参数与信号”区域生成基础输入框，并允许运行参数单次覆盖。
3. 开放 API 能读取、创建和修改当前 API Key 所属用户的完整策略。
4. 开放 API 能发布版本、查询版本历史、启用或停用策略、归档和恢复策略。
5. 开放 API 能在不修改已保存策略的前提下临时覆盖自定义策略参数并提交回测。
6. 网页接口和开放 API 复用同一套完整策略保存、参数校验、版本生成和回测快照实现。
7. 所有外部写操作具备权限隔离、幂等控制、乐观锁和安全审计。
8. 旧 API Key、旧策略、旧回测请求和历史任务保持兼容。

### 2.2 非目标

本期不包含：

- 管理员接口、其他用户资源或跨用户策略访问；
- 实盘交易、账户下单、凭据写入或 `live` 策略运行授权；
- 不可恢复的策略物理删除；
- YAML、JSON 等参数文件上传、解析或持久化；
- 服务端批量展开、自动寻优、网格搜索或批量调度；
- 独立参数版本、参数模板或跨策略实时参数引用；
- 列表、对象或任意嵌套的自定义策略参数；
- 通过普通 Python 变量猜测哪些字段属于可调参数；
- 绕过现有策略运行时安全校验、版本冻结或回测资源限制。

## 3. 完整策略资源模型

### 3.1 对外身份

开放接口把完整策略视为一个资源：

```text
完整策略
├─ 策略代码与运行声明
├─ 回测结构配置
├─ 已保存默认参数
├─ 当前脚本版本
├─ 当前方案 revision
└─ 不可变发布版本历史
```

对外稳定身份为 `config_id`。`script_id`、`strategy_version_id` 和 `published_version_id` 只作为只读版本信息返回，调用方不能通过传入其他脚本 ID 改绑策略。

### 3.2 生命周期语义

- 创建：原子创建独立脚本、脚本版本、方案和发布版本。
- 修改：必须携带 `expected_revision`，原子更新完整策略；代码语义不变时复用脚本版本。
- 发布：冻结当前完整策略；内容未变时复用最后一个相同发布版本。
- 启用或停用：通过完整策略修改设置 `enabled`，不绕过 revision 校验。
- 归档：设置方案归档状态并停用发布，不删除历史版本和回测快照。
- 恢复：恢复原完整策略所有权；名称冲突时返回 `409`，不静默改名。
- 版本读取：版本内容只读，不允许原地修改或删除。

保存完整策略继续遵循当前系统语义：保存成功后存在可复现的不可变发布版本。单独的发布接口用于显式确认当前版本，并在内容未变化时返回 `created=false`。

## 4. 自定义策略参数声明

### 4.1 声明格式

自定义策略在模块顶层声明 `STRATEGY_PARAMETERS`：

```python
STRATEGY_PARAMETERS = {
  "window": 20,
  "quantity": 200,
  "stopLoss": 0.05,
  "enableVolumeFilter": True,
}


def on_bar(bar, state):
  params = bar["params"]
  window = int(params["window"])
  quantity = int(params["quantity"])
  stop_loss = float(params["stopLoss"])
  enable_volume_filter = bool(params["enableVolumeFilter"])

  # 策略逻辑
  return []
```

一期通过字面量推导参数类型：

| Python 初始值 | 参数类型 | 网页控件 |
| --- | --- | --- |
| `int` | 整数 | 数字输入框 |
| `float` | 小数 | 数字输入框 |
| `bool` | 布尔值 | 开关 |
| `str` | 字符串 | 文本输入框 |

普通变量不会被识别为可调参数。

### 4.2 安全解析与上限

后端沿用 `WARMUP_TRADING_DAYS` 的 AST 解析方式，不执行用户代码。规则如下：

- 只接受模块顶层唯一一次赋值；
- 只接受字符串键和 `int`、有限 `float`、`bool`、`str` 字面量；
- 拒绝函数调用、表达式、变量引用、`None`、列表和嵌套对象；
- 布尔值先于整数判断，避免 Python 将 `bool` 当作 `int`；
- 参数名匹配 `^[A-Za-z][A-Za-z0-9_]{0,63}$`；
- 最多声明 64 个参数；
- 单个字符串值最长 1024 个字符；
- 规范化后的声明 JSON 最大 64 KiB；
- 参数名不得与系统运行参数保留名冲突。

未声明 `STRATEGY_PARAMETERS` 的旧策略按空自定义参数运行。

### 4.3 默认值协调

保存完整策略时按以下顺序确定已保存默认值：

1. 请求明确提供且通过类型校验的值；
2. 修改已有策略时，保留名称和类型均未变化的已保存值；
3. 新增参数或参数类型变化时，使用代码声明值；
4. 代码删除的声明参数从当前默认值中移除。

代码声明值是初始化依据，方案中保存的值是当前默认值。单次回测覆盖不改变二者。

## 5. 统一完整策略生命周期模块

网页 Cookie 接口和开放 API Key 接口是两个适配器，共用同一个完整策略生命周期模块。该模块的接口负责：

1. 解析并校验代码及参数声明；
2. 规范化完整策略请求；
3. 校验标的、周期、回测模式和运行参数；
4. 协调参数默认值；
5. 执行所有权校验和 revision 乐观锁；
6. 原子写入脚本、配置和不可变版本；
7. 归档或恢复完整策略；
8. 返回稳定的完整策略资源。

路由层只处理鉴权、Scope、HTTP 字段转换和错误映射，不复制保存规则。数据库层继续使用当前用户上下文和 RLS 作为第二道所有权保护。

## 6. 开放接口

### 6.1 接口清单

| 方法与路径 | Scope | 作用 |
| --- | --- | --- |
| `GET /api/v1/strategies` | `strategy:read` | 分页查询当前用户策略，可筛选启用或归档状态 |
| `GET /api/v1/strategies/{config_id}` | `strategy:read` | 读取完整策略及当前 revision |
| `POST /api/v1/strategies` | `strategy:write` | 创建完整策略 |
| `PUT /api/v1/strategies/{config_id}` | `strategy:write` | 按 `expected_revision` 完整更新策略 |
| `POST /api/v1/strategies/{config_id}/publish` | `strategy:publish` | 发布或复用当前不可变版本 |
| `POST /api/v1/strategies/{config_id}/archive` | `strategy:delete` | 可恢复地归档策略 |
| `POST /api/v1/strategies/{config_id}/restore` | `strategy:write` | 恢复已归档策略 |
| `GET /api/v1/strategies/{config_id}/versions` | `strategy:read` | 分页读取版本历史 |
| `GET /api/v1/strategies/{config_id}/versions/{version_id}` | `strategy:read` | 读取一个不可变版本 |
| `POST /api/v1/backtests` | `backtest:submit` | 使用已保存策略和本次覆盖创建回测 |

查询接口不要求幂等键。所有 `POST`、`PUT` 写接口都要求 `Idempotency-Key`。

### 6.2 完整策略写入契约

公开请求使用稳定的 snake_case 契约，不暴露 `paramsJson` 等数据库结构：

```json
{
  "name": "均线策略",
  "description": "均线方向策略",
  "code": "STRATEGY_PARAMETERS = {\"window\": 20}\n\ndef on_bar(bar, state):\n  return []",
  "entry_type": "on_bar",
  "signal_required": false,
  "symbol": "600004.SH",
  "timeframe": "5m",
  "benchmark_symbol": "600004.SH",
  "enabled": true,
  "backtest_parameters": {
    "start_date": "2026-06-01",
    "end_date": "2026-06-30",
    "initial_capital": 1000000,
    "commission_rate": 0.0003,
    "slippage": 0,
    "allow_long": true,
    "allow_short": false,
    "strategy_category": "directional_holding",
    "holding_policy": "overnight",
    "fill_model": "bar_next_open",
    "execution_algorithm": "immediate"
  },
  "strategy_parameters": {
    "window": 10
  },
  "expected_revision": 3
}
```

创建时不传 `expected_revision`；修改时必须传，并与当前 revision 一致。公开接口只允许 `mode=backtest` 的策略管理，不接受实盘账户凭据或实盘执行配置。

读取结果返回 `config_id`、只读脚本与版本 ID、`revision`、代码、结构配置、回测参数、策略参数、启用状态、归档状态和更新时间。读取结果可以作为下一次完整更新的基础，但调用方必须使用最新 revision。

### 6.3 稳定错误

开放接口至少提供以下错误码：

| HTTP | 错误码 | 含义 |
| --- | --- | --- |
| `401` | `api_key_invalid` | API Key 无效、过期或撤销 |
| `403` | `api_scope_denied` | 缺少所需 Scope |
| `404` | `strategy.not_found` | 当前用户不可见该策略 |
| `409` | `strategy.revision_conflict` | revision 已变化 |
| `409` | `strategy.name_conflict` | 恢复时名称冲突 |
| `409` | `idempotency.conflict` | 同一幂等键用于不同请求 |
| `422` | `strategy.validation_failed` | 代码、参数或配置无效 |
| `422` | `strategy.parameter_invalid` | 参数未声明或类型不匹配 |

不存在和无权访问统一返回 `404`，不泄露其他用户资源是否存在。

## 7. API Key 权限与所有权

新增四个 Scope：

| Scope | 能力 |
| --- | --- |
| `strategy:read` | 查询当前用户完整策略及版本 |
| `strategy:write` | 创建、修改、启用、停用和恢复策略 |
| `strategy:publish` | 发布当前策略版本 |
| `strategy:delete` | 归档策略，不执行物理删除 |

现有 `backtest:submit`、`backtest:read` 和 `backtest:cancel` 保持不变。已有 API Key 不会自动获得新增 Scope；用户必须创建新 Key 才能使用策略管理能力。

API Key 页面展示所有 Scope，但新增写入、发布和归档权限默认不勾选，并明确提示其影响。API Key 即使属于管理员账号，也只以普通所属用户身份访问资源，不继承管理员权限。

## 8. 幂等、并发与审计

### 8.1 幂等

所有开放写接口统一使用：

```text
API Key ID + Idempotency-Key
```

请求摘要包含 HTTP 方法、规范化路径和规范化请求体。相同键与相同摘要返回首次成功结果并标记 `replayed=true`；相同键与不同摘要返回 `409`。

现有 `api_idempotency_record` 扩展为通用开放写入幂等记录，保存操作类型、资源类型、资源 ID、响应状态和最小响应正文。回测现有 `run_id` 继续兼容。幂等记录与资源写入必须在同一事务完成，不允许出现资源已写入但幂等结果丢失的窗口。

### 8.2 乐观锁

- 更新、发布、归档和恢复请求携带 `expected_revision`。
- 服务端锁定当前方案行后比较 revision。
- revision 不一致返回 `strategy.revision_conflict`，不产生任何新版本或局部写入。
- 幂等重放先识别首次成功结果，不因资源 revision 后续变化而把同一请求误判为冲突。

### 8.3 审计

开放写操作在 `api_access_audit` 记录事件类型、API Key、所属用户、资源 ID、请求 ID、结果和安全摘要。审计不得保存 API Key 明文、策略源码、完整参数或完整请求正文。

## 9. 单次回测参数覆盖

`POST /api/v1/backtests` 的 `overrides` 增加 `strategy_params`：

```json
{
  "config_id": "932a0ce2-9d8d-4060-8614-5df0adbbf8a9",
  "overrides": {
    "start_date": "2026-06-01",
    "end_date": "2026-06-30",
    "initial_capital": 1000000,
    "strategy_params": {
      "window": 10
    }
  }
}
```

服务端按以下顺序处理：

```text
已保存策略参数默认值
        +
本次合法覆盖值
        =
本次最终有效参数
```

规则：

1. 只能覆盖当前已发布代码声明的参数。
2. 类型必须与声明一致，整数不接受布尔值，浮点值必须有限。
3. 未知字段或系统保留字段不会创建任务。
4. 覆盖参与回测提交幂等摘要。
5. 覆盖只写入回测任务快照，不更新策略、revision 或版本。
6. Bar 和 L2 任务均使用提交时冻结的最终有效参数。

任务快照保存：

```json
{
  "savedStrategyParams": {"window": 20},
  "strategyParamOverrides": {"window": 10},
  "effectiveStrategyParams": {"window": 10}
}
```

旧任务缺少这些字段时继续按既有 `strategyParams` 或 `runParams` 读取，不反推或改写历史数据。

## 10. 网页行为

### 10.1 回测配置

现有“回测配置”栏仍是主要入口，不新增独立参数管理页面。页面根据已保存参数声明，在“策略参数与信号”区域显示数字、布尔和文本输入框。

页面区分：

- `versionDirty`：代码、标的、周期、持仓语义或其他策略结构字段有未保存修改，必须先保存；
- `experimentDirty`：日期、资金、成本、执行算法或已声明策略参数仅影响本次运行，可以直接回测。

运行回测不会隐式保存策略；保存策略才会更新方案默认值和 revision。

### 10.2 API Key 页面

API Key 页面增加策略 Scope 的说明和风险提示。新增高权限 Scope 不默认勾选；创建请求提交中禁止重复点击，错误在当前页面显示并保留用户选择。

## 11. 安全与兼容

1. 参数声明只通过 AST 解析，不执行用户代码。
2. 开放写入复用现有策略运行时校验，不能保存系统明确禁止的导入或代码能力。
3. 策略代码和参数设置大小上限，避免超大请求耗尽资源。
4. 所有资源查询都受当前用户上下文和数据库 RLS 双重约束。
5. 归档不删除历史版本、历史回测、共享快照或审计记录。
6. 公开接口不接受实盘账号、口令、令牌或任意文件路径。
7. 新增 Scope 不回填到旧 Key，旧 Key 行为不变。
8. 历史策略和旧回测请求不要求补充参数声明。
9. 网页和开放接口对同一完整策略请求生成相同的代码版本、方案版本和参数默认值。
10. 接口新增字段保持向后兼容，不改变现有回测结果语义。

## 12. 系统验收标准

1. 合法 `STRATEGY_PARAMETERS` 能被安全解析，非法声明不会执行代码且返回稳定错误。
2. 网页和开放接口保存相同完整策略时，得到一致的脚本版本、方案版本和参数默认值。
3. 具备 `strategy:read` 的 API Key 只能读取所属用户策略及版本。
4. 具备 `strategy:write` 的 API Key 可以创建和修改完整回测策略；缺少 Scope 时返回 `403`。
5. 修改请求缺少或使用过期 revision 时不产生任何写入，并返回 `strategy.revision_conflict`。
6. 发布相同内容不会生成重复版本；修改代码或运行语义后生成新的不可变版本。
7. 启用和停用通过完整策略更新完成，并参与 revision 校验。
8. 归档后策略不再出现在活动列表且不能提交新回测；历史版本和历史任务仍可读取。
9. 恢复归档策略后重新可用；名称冲突时明确失败且不静默改名。
10. 所有开放写接口对相同幂等请求重放首次结果，对不同请求复用同一键返回冲突。
11. 审计记录包含操作和资源身份，但不包含策略源码、完整参数或密钥明文。
12. 单次回测接口能够临时覆盖已声明参数，且不修改策略、默认值、revision 或版本。
13. 回测快照能够区分已保存默认值、本次覆盖值和最终有效值。
14. Bar 与 L2 链路均使用提交时冻结的最终有效参数。
15. 旧 API Key、旧策略、旧请求和旧历史任务保持原行为。
16. 《玄龄回测系统使用手册》和开放 API 对接文档与实际发布行为一致。

以上验收只验证系统接口、权限、持久化、运行快照和执行结果，不验证任何特定外部调用工具的行为。
